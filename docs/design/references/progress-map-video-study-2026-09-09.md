## 2. 逐段可见事实

| 视频区间 | 可见的组织方式 | 可以借鉴的含义 |
| --- | --- | --- |
| 00–10 秒 | 浅色三维街区/海岸构成环境，粉色主点及其后方路径对比最强；镜头随位置变化调整；顶部指标区基本留在固定屏幕位置 | 让“当前进展”有明确焦点；空间内容与信息控件承担不同职责 |
| 10–20 秒 | 随进展，沿岸街区与湾区上下文展开，主点仍处于画面中部附近；右侧辅助卡片内容发生变化 | 把环境变化组织在主要叙事对象周围，而不是让对象反复离开画面 |
| 20–34 秒 | 弯折路线与街区一起出现在倾斜视角中；线路保留“已从哪里来”的上下文；旁边可见辅助信息/互动项 | 当前位置与已走路径共同解释行进，不必让所有图层同时强调 |
| 34–47.96 秒 | 更长的沿海片段进入视野，路线继续连接，屏幕信息区保持独立布局；辅助卡片又换为其他内容 | 一个稳定的信息落点能在持续的空间变化中降低观看负担 |

这里的“随进展”指录像可见内容，不证明动态数据来自真实运动。采样画面只能支持构图/序列关系，不用于宣称全段没有掉帧或镜头抖动。

## 3. Startrips 值得吸收的四件事

### 3.1 有一个明确的主角

图中的重点是行进点，而不是整张地图。迁移到 Startrips，主角是“当前回看的地点/叙事段”，不是设备实时位置，也不一定是一个不断移动的圆点。

### 3.2 路线解释过去，内容解释抵达

已播放过的段落可以退为较轻的上下文；当前段落有更明确的引导。抵达一个有记录的地点后，照片、视频或文字接管主要信息位。仅靠沿线飞行没有兑现 Startrips 的内容价值。

### 3.3 屏幕焦点稳定，但地理与命中不伪造

镜头的目标可以保持在由地图可用空间、侧栏/底部 sheet、安全区域推导的观看区。普通控件保持稳定命中区域；地理 marker 的命中仍跟随当前投影。不能把“焦点稳定”错误实现为一个与地图脱节的 fixed 图钉。

### 3.4 环境辅助叙事，不争做主角

可以借鉴低噪声底图与选择性强调，不要求复制白模三维建筑/配色/字体。Startrips 仍保持已有 Particle Earth 的空间语言；局部真实地理提供方向、河流、街区等必要环境。合法地图署名不能因简化界面而消失。

## 4. 不照搬的内容

- 心率、配速、运动距离、直播人数、评论与音乐面板没有成为 Startrips 当前需求的依据。
- 不引入后台 GPS、直播或运动追踪，给地图“凑信息”。
- 不把视频中未知来源的路径抄成可用轨迹数据。
- 不为了行进感把每一张照片都触发新镜头飞行，不让同一地点的连续媒体重复“抵达”。
- 不默认让相机持续转向或锁住。用户输入可以即时接管；重新跟随需明确意图。
- 不把整段动作强行交给弹簧：媒体、叙事进度按真实时间，弹簧只让空间目标的接续与收敛更自然。

## 5. 最关键的事实门槛：连接线不等于轨迹

| 数据来源 | 可以呈现 | 不能暗示 |
| --- | --- | --- |
| 只有稀疏 Route Points | 点之间的地理关系、章节进度、接近下一个记录地点 | 沿某条街道确实走过、实时位置、精确运动距离/速度 |
| 媒体只归属于某站 | 该站的媒体与日期/文字；没有精确拍摄位置的提示 | 给照片补一个看似精确的门牌或街道坐标 |
| 有可靠、授权、带来源的真实轨迹 | 由真实采样/精度支持的轨迹回放 | 采样间隔内未被记录的停留、活动或精确运动事实 |

叙事路线可以有动画，但它的图形、文案和交互都必须让用户理解其为回看进度，不是未经证据支持的实时定位。

## 6. 建议验收片段

使用合成三站 Journey：照片站、照片/视频站、文字站，并包含城市级位置与无独立 GPS 的媒体。

1. 从已有地图选择一站，看到其内容，而非只有地图。
2. 播放时当前段落成为空间焦点；抵达后交给该站媒体。
3. 同站换照片不重飞；跨站按授权跟随规则推进。
4. 行进途中拖动地图，自动相机当下让位；晚到的读取/动画不能夺回。
5. 静态 reduced-motion 路径仍能理解当前章节和经过关系。
6. 访客 scope 过滤先于标记、路径、聚类、数量、封面和预取。

这份视频支持的是以上方向，**不是**这些行为已经得到验证。行为须在真正的 Startrips 实现或明确标注的独立 Demo 中测试。
