## 0. 结论与证据边界

**Startrips 的详细地图应当是个人经历的空间索引，而不是独立的地图浏览产品。靠近的收益应当是理解更具体，不只是底图更细。**

用户给出的六条动效原则是本轮明确要求：可打断、Hit Area 与视觉解耦、Layout-aware、最少 DOM 与逐帧批量、Reduced Motion、弹簧优先。原研究核对的 main 中，`docs/motion-language.md` 已包含这六条，`src/motion/tokens.ts` 已有共享弹簧参数，存在 `src/motion/springElement.ts` 及对应测试文件。[R1–R3]

因此，本方案不发明第二份动效总规范，不把旧的 cubic-bezier-only 解读继续当成产品要求，也不以“加了 spring 参数”证明全部模块已经完成迁移。

证据分级：
- **外部已核实**：官方产品说明、作者项目 README、官方技术文档。原研究没有完成这些产品的登录后交互横评；本次修订未重新访问或交互验证这些外部产品。
- **仓库已核实**：原研究通过已认证 GitHub API 按上述精确 SHA 读取文件及议题状态。本次修订不能据旧快照判定新 PR/新版本；未运行本地完整测试、构建或真机性能测试。
- **视频观察**：本轮对用户上传的 `行进.mp4` 跨全段取样 24 帧，并放大核对 0/20/36 秒关键画面；视频时长约 47.96 秒。画面可以支持视觉组织分析，不能证明其为真实直播、GPS 精度、实现框架、触控可打断性或性能。
- **Startrips 提案**：下面的层级、展示策略、演示范围和阶段验收，是根据外部概念与本项目要求形成的设计建议，不是宣称其他产品都采用它们，也不是全部已实现。

## 1. 外部研究：借鉴信息关系，不搬整套界面

| 来源 | 公开材料支持的机制 | 对 Startrips 的借鉴 | 不直接照搬 |
| --- | --- | --- | --- |
| Ente Trip layout | 旅行相册的分享页把照片按位置放到交互地图上，并配合时间线。[S1] | 同一份记录同时用“在哪儿”和“什么时候”解释；媒体不是地图的附件 | 不自动导入它的分享/加密架构，也不假设本项目所有媒体都有 GPS |
| Apple Photos Map | 地图用缩略图和数量组织带位置元数据的媒体，可以从单张照片查地点及附近照片。[S2] | 地点是内容入口；一簇记录逐步展开；地理精度由数据支持 | 只有城市/Route Point 归属时，不伪造照片拍摄坐标 |
| Polarsteps | 用旅程路线与每个 step 的照片、视频、故事构成回顾。[S3] | 顺序连接地点，地点连接内容 | 不把它的自动轨迹采集、社交发现、行程规划全部变成 Startrips 的前置要求 |
| ArcGIS StoryMaps | 官方设计文章区分自由选择地点的 Explorer 与有顺序的 Guided tour，同一内容可有不同呈现。[S4] | 自由浏览与按序 Playback 是访问同一内容的两种方式，不是两份数据 | 不把整个浏览体验变成强制逐站滚动的营销故事页。引用为设计先例，不依赖其旧版数量上限 |
| Day One Map View | 地图标记指向有地点的日记内容；也用于理解日常发生在哪里。[S5] | 日常片段的价值来自内容，Home 是阶段性上下文 | 不假设全部平台功能相同，不要求 GPS 持续采集或先填写完整居住史 |
| Historypin | 通过照片、声音、视频讲述有意义的地方。[S6] | 后期探索“同一个地方，不同时间的经历” | 不照搬公开社区与社交信息流；私人 Atlas 默认私有 |
| Cheng Lou gallery / react-motion | 作者明确列出可打断、解耦命中区、resize 观察锚点、弹簧、可见性裁剪和每帧批量渲染。[S7–S8] | 连续性来自对象身份、布局、输入与状态，而非单条动画曲线 | 不直接移植旧库或全套画廊布局，也不为减 DOM 牺牲可访问性 |

### 三个更基础的概念

**Progressive disclosure（按需显露）**：先显示当前任务最重要的信息，次要能力有明确但不抢眼的入口。[S9] 在 Startrips 中，它不意味着把播放、返回、错误恢复隐藏成只能猜的手势。

**Focus + context（焦点与上下文共存）**：当前对象清楚，仍看得懂它属于哪段旅程。信息可视化研究也指出，不是每次都从总览开始：已经知道目标时，可以直接显示目标，再按需展开上下文。[S10] 所以媒体深链接无需强迫用户先看一遍地球开场。

**Semantic zoom（语义缩放）**：这里不是单纯放大符号，而是从旅程关系、地点摘要走向具体记录。Startrips 的方案还要加上当前意图、数据精度与可读空间；不能把全部披露决策交给 zoom 一个数。

## 2. 一个总目标：靠近发生的地方，而不是打开另一张地图

建议采用以下体验句子作为所有近景功能的判断标准：

> 我想再看这段旅程 → 我知道当时经过哪里 → 我找到那里的照片和文字 → 我继续看下一站 → 我随时能回到刚才的位置。

“每一个点有意义”不等于每颗粒子都可点击、每个地名都能弹窗。界面上的对象应当明确属于三类：

1. **内容对象**：某段 Journey、某个 Route Point、某张媒体、一个已确认的历史阶段。
2. **任务控件**：返回、播放/暂停、选择、重试、提交或撤销；它说明可执行的动作。
3. **环境背景**：地理底图、非交互粒子和氛围。它们可以帮助空间感与注意力，但不能伪装成可点击个人记录。

没有个人记录的区域仍允许探索。不自动制造内容，不封死缩放，不强行把镜头吸回家。只有明确进入记录流程时，才提供选点与保存动作。

## 3. 用户体验的五级递进

这些是按意图呈现的层次，不是强制五步向导；也不等于五个新路由或五个模式按钮。

| 层次 | 用户正在问什么 | 主要内容 | 下一步 | 此时退后的信息 |
| --- | --- | --- | --- | --- |
| 1. Atlas 总览 | 我想重看哪段经历？ | Journey 的地理关系、必要标题/时间 | 选择一段 Journey | 密集道路、商家 POI、所有照片缩略图 |
| 2. Journey 聚焦 | 我当时如何经过这些地方？ | 有序 Route Points、代表封面、当前地点 | 选择一站或播放旅程 | 其他 Journey 的强光与无关标签 |
| 3. 地点上下文 | 这里留下了什么？ | 这站已有的照片数量、封面、日期/文字和位置精度 | 打开记录或继续下一站 | 全图照片墙、通用百科、全部管理按钮 |
| 4. 媒体观看 | 我想认真看这一张/这段视频 | 当前媒体；少量地点/时间上下文 | 跟手切换、暂停、返回 | 竞争性的地球动效、仪式性 Logo 动画 |
| 5. 跨时间回看 | 我以前还在这里记录过什么？ | 明确关联同一地点的不同日期/旅程；用户可选 | 查看某次记录，再返回当前旅程 | 未请求的其他人内容、自动猜测的关系 |

### 不是越近越堆信息，而是信息在接力

区域层的一个“这一站 12 项记录”到近景可变成若干有代表性的内容入口。打开媒体后，就不再同时维持展开的地图卡片与大片统计面板。返回时从用户最后有效观察位置恢复，而不是清空世界重新演示。

全景必须平静不代表故意把所有入口变淡：当前选中对象的文字、焦点、可读对比与交互区域需要明确。多个背景对象可以共存，但不能争当当前主对象。

### 空间细节的准入

道路、河流、山体、地标等是地理参照。只在它们能够帮助定位、解释旅程关系或完成选点时增加优先级。仍保留必要的制图上下文与署名信息，不把整张底图涂黑到无法理解。

不用“泛 POI、天气、AI 百科”给空地图凑内容。它们只能在明确任务、来源可靠且用户需要的情况下作为后期辅助；并非近期里程碑。

## 4. 焦点不是只存一个 focused=true

建议从既有状态派生一份可测试的视图决策，而不是另建一个保存重复状态的全局 manager。

视图决策至少回答：当前合法 scope；正在浏览/播放/管理/选点/恢复哪个任务；选中 Journey/Route Point/asset 的稳定 ID；谁拥有相机输入；这次意图的 revision；位置精度；数据加载/失败状态；真实 viewport/布局与 reduced-motion 偏好。

关键区分：
- **内容选择**不等于**相机跟随**：用户拖走地图是 free explore；在他恢复跟随或明确选择新地点之前，媒体加载完成不能把镜头拉回。
- **键盘焦点**不等于**视觉主角**：自动镜头变化不能偷走用户正在操作的键盘焦点。
- **请求目标**不等于**已显示媒体**：B 尚未可呈现时不能把 A 的像素伪装成 B；加载状态应当诚实。
- **范围筛选**不等于**当前位置**：拖动地图不能暗中退出当前 Journey 或暴露其他分享范围。

### 每个重要界面元素的六项说明

| 字段 | 必须回答 |
| --- | --- |
| 对象 | 指向哪个稳定 ID，还是明确的非交互环境？ |
| 意义 | 帮用户解决什么问题？ |
| 出现条件 | 何种意图、尺度、数据状态下才值得出现？ |
| 优先级 | 当前主对象、上下文对象，还是装饰？ |
| 动作 | 点击/拖动/键盘会产生什么可预期结果？ |
| 离开与失败 | 被中断、内容失效或返回时怎样收口？ |

不能回答这些问题的常驻按钮、动效、统计卡，优先删掉或降为按需入口。

## 5. 一段具体的近景流程

以一个合成的日本三站 Journey 为演示，不使用用户私有素材：京都两张照片、大阪一张照片与一个短视频、奈良只有文字。媒体顺序来自明确输入，地图坐标包含精确地点和只有城市归属的两种情况。

1. Atlas 中选中这段 Journey：只强调这段 Route，不同时弹所有媒体。
2. 点击京都：形成一个地点上下文区域，显示已有日期、封面和数量；地图保持这是本次 Journey 的第一站。
3. 连续浏览两张照片：地图不为每张同站照片重飞；图片构图不挤压成统一横幅。
4. 翻到大阪：内容位置进入下一站，地图在允许跟随的模式下接住这次地理变化。旧京都读取结果不能把内容切回去。
5. 用户手动拖动地图：立即暂停自动跟随，不清空选中内容；提供按需的“回到当前地点”，不增加永久地图模式按钮。
6. 视频慢载：保持当前已可呈现内容与显式等待状态；原生视频控件不被切图手势覆盖。失败可重试或跳过，但系统不能自己静默跳过该站。
7. 进入奈良：合法的文字记录不因为没有照片而被丢弃；不造占位照片，不把“没有媒体”说成“没有内容”。
8. 从媒体返回：保留最后有效站点/资产，而非机械回到最初京都。只有对象被移走或删除时才按现有规则降级。
9. 某张照片仅归属于京都这站：标明“归属本站，未记录精确拍摄位置”，不冒充拍摄 GPS。城市级定位不能变成任意街道的精确图钉。

这段流程本身应当在没有小羊、没有额外光效的版本中成立，然后才加视觉层。

## 6. 六条动效原则：统一解释与边界

作者 Cheng Lou 的原始 README 明确讨论了打断、命中区、布局锚定、弹簧与批量渲染；Apple 的 Fluid Interfaces 强调从当前状态和动量出发，而不是用户操作后把控制权暂时交给演出。[S7–S8,S11]

### 6.1 Non-disruptive & Interruptible

新输入立即更新意图/目标，当前画面连续接管。不能使用 `isAnimating => ignore input`、排队等待整段旧动画或回到初始状态重播。异步图片、地图 readiness、旧 onComplete 均受 scope/revision 约束。

“可打断”针对界面与运动，不意味着已提交到服务器的写操作已被撤回。提交中允许离开与查看真实状态；防重提交可以有业务依据，不能靠动画结束猜成功。结果不确定时要 reconcile，不能用一段反向动画当作服务器 undo。

### 6.2 Hit Area 与视觉解耦

普通按钮有稳定命中壳，内部图标可以动；画廊上/下一项热区不跟着离场图片跑。扩大热区时排除关闭、文本选择、原生视频控件和纵向滚动。

**不能把“稳定命中”扩大解释成所有 hit-test 永远不变。** 地图地理点随投影移动，命中必须跟随当前可见锚点；直接拖动的卡片必须由 pointer capture/当前几何正确接管；ghost 不得留下旧位置透明挡板。动画反馈不制造目标逃跑，实际内容变化也不能让命中与视觉脱节。

44px 是本项目已有控制契约，不在此宣称是 WCAG 所有控件的一律最低标准。[R4]

### 6.3 Layout-aware

基于真实布局与稳定 ID 测量。FLIP 是手段：First 记录当前可见几何；Last 使用新布局；Invert 补偿差异；Play 以可打断的运动收敛。布局更新不能伪造服务器结果；可以显示明确的待提交 ghost，再于确认后反映正式归属。

滚动、resize、横竖屏、字体换行或目的地不在当前视口时，重新测量或采用局部反馈，不能飞向旧坐标。Motion 的 `layout/layoutId` 是可选实现机制，不是本项目必须安装的新依赖。[S12]

地图不采用 DOM FLIP 替代地理投影；保持现有 canonical projection、screen anchor、相机 owner。

### 6.4 最少 DOM + 批量渲染

目标是有界节点与有界工作，不是全站改成 Canvas。保留语义 DOM、键盘可达与屏幕阅读器支持；大量非交互粒子使用现有批量渲染。

一次交互统一收集输入并批量读/写布局，避免逐节点读写交错和逐帧 React state 带动整树刷新。媒体展示节点按已选内容及有限相邻项复用，临时视觉副本在结束/取消时释放。滚出视图的集合按需裁剪，不为每张图建立 rAF。

“不新增另一套调度器”指不让同一属性拥有两个竞争更新者；不意味着重写 MapLibre、原生视频和 Three.js 的全部内部循环成一个万能引擎。等待未就绪资源、隐藏页面时不空转；真实动画与资源事件按需唤醒。[S7]

### 6.5 Reduced Motion

不仅首次读取偏好，运行中切换也必须撤销非必要运动，并落到最新有效状态。关闭飞行、弹跳、连续光流不等于关掉缩放、换图、排序、播放和返回。业务结果不能依赖 transitionend/onRest 才落地。

W3C 提供 CSS 和 JavaScript 读取该偏好的技术；其中 Animation from Interactions 对非必要运动提供可禁用路径。[S13–S14] 本方案同样要求粒子/Three 消费统一偏好，不能仅给 CSS 一个 media query。

### 6.6 弹簧优先于固定缓动，但时间事实不弹簧化

| 行为 | 首选驱动 |
| --- | --- |
| 手指拖照片、拖地图的接触阶段 | 直接输入跟随；不要用落后于手指的弹簧替代跟手 |
| 松手归位、翻页收敛、可反向的卡片展开 | 从当前 x/v 开始的真实弹簧或对应惯性系统 |
| 地理镜头自由导航 | 当前相机状态/输入与既有地理约束，避免另一个实例写同一 transform |
| 视频、音频、Journey 的语义进度 | 真实媒体时间或既有 narrative timeline |
| opacity、短暂状态反馈 | 可用固定时长/淡变；不强迫亮度有物理过冲 |
| 少数品牌章节/小羊动作 | 可跳过的独立演出，不锁功能，不占高频操作时钟 |

Motion 官方区分 physics-based spring 与 duration-based spring：前者继承现有运动速度，后者用 duration/bounce 描述且不继承速度。[S15] 因此仅写 `type: spring` 不是完整验收；重点是重定向时的状态/速度连续和最新目标。

弹簧也不等于所有对象不停弹跳。Apple 的设计建议从无过冲开始，需要表达输入动量时再少量添加。[S11] Startrips 的地图和阅读界面可克制，手势松手可有适当物理感；不把“克制”误读成禁止弹簧。

原研究快照的共享 `stiffness=300/damping=28` 是该提交的仓库事实，不是本次重新拍板的各场景最优参数。[R2] 先复用并验证，有证据才按语义扩展共享预设；禁止每个模块散落新数字。

## 7. 各模块的意义、焦点与失败态

| 情形 | 唯一主要任务/焦点 | 呈现与动作 | 不能出现 |
| --- | --- | --- | --- |
| 选 Journey | 这段路线和记录 | 必要地点摘要、播放/进入故事 | 其他路线全亮、默认全站只有同一个主 CTA |
| 地点展开 | 本站具体内容 | 一处信息面板；地图是上下文 | 同站每翻照片相机重飞 |
| 媒体切换 | 当前可见资产 | 跟手、可反向、ready 后接管 | 上下挤出、旧解码夺权、把低清到高清和 A 到 B 混成一套 |
| 批量移动/撤销 | 已选集合、目标与真实操作结果 | 有限叠片、数量、目标确认、失败保留选择 | 源列表先假成功、undo 失败却反向飞回表示成功 |
| 404 | 恢复到可用上下文 | 明确页面不可用；一个返回图谱主动作；只有可靠 app 历史才提供返回上一层 | 联系支持/营销 footer 抢任务、虚构新旅程推荐来填错误页 |
| 空 Atlas | 创建第一段 Journey | 简单记录入口；选点只在任务内出现 | 一屏空统计、强制配置 Home |
| 地图或媒体加载失败 | 已可用内容与恢复 | 保留可用底层；错误/重试可见 | 把失败当成“没有记录”，或空白全屏 |
| 分享失效/无权限 | 明确边界 | 中性说明与回到允许的产品入口 | 未授权的名称、封面、Home、其他日期计数或聚类痕迹 |
| 完成 Playback | 已完成的位置 | 回看/返回，明确终态 | 还在计时、自发从最后一帧再播、强制品牌仪式 |
| 小羊品牌节点 | 品牌识别而非操作导航 | 登录、首次成功等少数节点，一次性/可跳过 | 每次切图、失败重试时反复演出 |

在同一意图下，照片、原位补齐和目的地反馈可以协同动画。“一个主焦点”不等于把相关变化拆成三段串行动画让用户等待。

## 8. 实施递进：每一阶段都形成可独立验收的增量

以下阶段名为本报告的提案编号，不是新建任务注册表，不写回正在运行的 feature_list。

### 阶段 A：最小“有内容的近景”

目标：用户点一站，就能知道这里有什么、怎么打开、怎么回来。

用现有 Journey/Route Point/media 信息构建地点上下文，不增加 Home、AI 推荐或更多地理数据为前置。只新增缺失的选择与内容投影，不重做已存在的底图与焦点求解。

验收：一段合成 Journey 的有照片、只有文字、无精确拍摄坐标三类点均成立；每个可点元素有目的；静态模式也完全可用；一处主信息面板，无全图卡片墙。

### 阶段 B：一个对象贯穿地图、媒体和返回

目标：选择/地理尺度变化/媒体查看/跨站/返回连续；把六原则用到实际行为。

复用已完成的 #245 返回合同和 #252 地图交接基础，核对当前剩余缺口，不重做 closed issue。#65 媒体 compositor、#261 whole-Journey calibration 等问题只由原 owner 收口。手动地图探索中止自动跟随；快速 A→B→C 最终由 C 占有。

验收：同站不重飞；跨站不丢点；镜头、可见媒体和焦点树没有双 owner；反向输入、拖动接管、orientation 和 reduced-motion 在线切换都能完成。原生视频保持可用。

### 阶段 C：同一个地方，跨时间的私人回看

目标：用户主动询问“这里以前还有哪些记录”。

先展示明确相同地点/同一区域归属的不同 Journey 和日期，不通过接近就认定同一次访问或同一家店，不按照片数量推断访问次数。所有聚类、数量、代表封面先过滤当前授权 scope，再做计算。

验收：当前旅程与其他旅程边界清楚；查看其他年份可返回当前观察点；访客看不到未分享内容及其统计痕迹。时间不明确时明确缺省，不制造精确日历。

### 阶段 D：接入人生阶段，但不增加配置负担

目标：在 Home 与 Everyday Fragment 的真实领域模型完成后，让过去在哪里生活与附近日常自然出现。

常住地推断只可建议，确认后才是事实；历史 Home 不覆盖过去 Journey；未配置 Home 不阻塞前面三个阶段。沿用既有 #229 子工作，不另做“Home V2”。

验收：城市级 Home 不透露家庭地址；日常不淹没 Journey 列表；分享不默认泄露 Home；无需用户填一套半径/地理精度/动效参数。

### 阶段 E：复用现有品牌/动作 V1，验收与内容流程的整合

**既有事实：用户本轮确认品牌与动作已完成一版。本阶段不是再设计小羊、再出 Logo 或重新制作开场 Demo。** 只消费当前已采用的 V1 资产与接口，验证适合哪些表面、何时出现、何时退场；确有缺口才形成窄的适配修复。不等待品牌重做来完成 A/B，也不修改 V1 的字标、轮廓、配色与动作，除非另有明确设计要求。

目标：同一体验里，选择更清楚、抵达有回应、结束有淡痕；错误页可有空间氛围但恢复路径始终明确。

把已有小羊动作、环境光、arrival 和 imprint 当不同层。近景体验 Demo 可复用现有 V1，不另起品牌设计线。上线不能以特效掩盖前面阶段的错误；品牌演出不上每一次媒体切换。真实地图仍体现地方环境，不变成纯装饰舞台。

验收：普通使用无持续仪式噪声；暂停/退出不等待；渲染预算和 reduced motion 通过；关闭品牌效果不影响任务。

### 生命周期规则

先只定义阶段 A/B 中当前代码确实缺少的增量；后面的跨时间、Home 和视觉整合保持依赖图，不一次给所有模块开泛化“优化体验”单。**已有品牌/动作 V1 不新增实施单，也不重新挂为 pending。** 已完成合同关闭；新范围另建窄子单。#244 作为父级追踪，不能因父单新增研究评论就自动重新实现旧阶段。

文档合并不代表 A/B 行为交付；文档 PR 只用 `Refs/Addresses` 引用父 issue，不用 `Fixes #244/#246` 误关整条体验主线。实现 issue 需要写清基于哪个文档 commit/节和哪个代码 SHA 定义验收；评论发生变化时必须区分参考补充与明确产品决定。

## 9. 下一份动态 Demo 的最小规格

不是新的整页效果图。推荐一个可离线操作的合成数据 Demo，分四个互相共享同一数据身份的入口：

1. **旅程—地点—媒体—返回**：覆盖阶段 A/B 的三站旅程，含照片、视频与文字站。
2. **直接操作压力路径**：快点三次、反向、拖到一半接管、冷图、错误与重试、resize；显示 requested / visible / ready 的调试信息，但正式界面不暴露工程术语。
3. **移动与撤销**：有限叠片；模拟成功、失败、结果未知、undo 失败。模拟服务端需明确标记，不能当真实后端交付。
4. **空态/404/分享失效**：焦点都是恢复或下一步任务，而不是满屏的新导航。动态偏好一键切换，所有信息和动作仍可用。

独立 Demo 内可有技术控制面板用于验收，但不能把这些开关变成用户必须配置的正式功能。

## 10. 验收方法：从“看起来更好”转向可以观察的行为

| 检查 | 观察点 |
| --- | --- |
| 无鼠标辅助 | 键盘能够抵达当前内容、暂停、返回、重试；隐藏 renderer 不残留可操作控件 |
| 连续点三次 | 不锁输入、不误关 Viewer；最终目标符合明确的下一项语义和边界规则 |
| 中途反向 | 可见位置不重置，运动从当前状态接续；旧 callback 不回写 |
| 手指接管 | 指针从当前画面抓住内容，不跳到目标终点；释放速度与手势相关 |
| 同站/跨站 | 同站保持镜头；跨站按用户许可跟随；旅程点不被媒体筛选遗漏 |
| 布局变化 | 当前资产 ID 保留；基于新布局的几何与 hit-test 一致 |
| 冷加载/失败 | 不露底、不假成功；当前可用内容不因另一资源失败被清空 |
| 资源上界 | 连续切换/移动后媒体与视频节点不持续增长；取消释放临时 clone/监听/rAF |
| 地图校准 | 对点、整段 Route、无选择分别检验；度量屏幕锚点和局部尺度，不只查字段存在 |
| scope | 过滤先于聚类、计数、封面选择与预取；失效后无旧私有 UI 回流 |
| reduced motion | 初始和运行中切换均有确定终态，不依赖动画完成事件 |
| 真机与证据 | CI 行为测试和真实浏览器视频分开记录；桌面模拟、Canvas2D、SwiftShader 不等于手机 Opera GPU 验收 |

具体帧时长、锚点误差、曲线像素误差上限应在对应合同里按被测设备与准确场景声明。这里不凭外部产品截图发明一套全局硬数值。

## 14. 《行进》视频：让地图有明确主角，而不是单独展示地图

这段视频的参考价值主要是**行进中的焦点组织**。白色三维街区只是环境，粉色当前位置及其后方路线承担主要视觉叙事。画面中的时间/配速/距离/心率等卡片解释该行进任务；这些运动指标不是 Startrips 应复制的功能。

推荐迁移：

```text
视频中的当前位置          → 当前回看的 Journey 阶段 / 地点
后方留下的线路            → 本次回放已经经过的叙事段落
相对稳定的观察焦点        → 根据真实可用视口建立的跟随区
运动数据卡                → 当前地点的实际日期、文字、照片/视频
整段镜头围绕移动点组织    → 行进时地图解释空间，抵达后媒体成为主角
```

静态浏览不自动启动行进。只有用户选择 Playback/明确跟随时才启用该编排；用户拖动、缩放或选择新目标即撤销旧自动镜头控制。视口中心是动态计算的“可用观看区”，不是把地图 marker 的命中位置锁死。

### 路线真实性是首要边界

- 只有 Journey 起终点或稀疏 Route Points 时，连线是地点关系；即使做了叙事进度动画，也不能画成沿真实街道实时奔跑的定位点。
- 明确把叙事进度与测量位置分开。没有真实轨迹，不显示推断速度、运动距离、心率或虚构途经道路，不用自动吸附到路网营造精确感。
- 用户确有可靠、授权且有来源的轨迹时，才允许忠实轨迹回放；该能力不是当前 A/B 的前置任务，也不引入后台定位。
- 完整路线若未知，临近或抵达已记录地点时展示该地真实内容，比沿编造的路径演一遍更有意义。

### 焦点在时间上的交接

```text
准备：知道将回看哪站
行进：当前叙事段落 + 地理环境
抵达：当前地点 + 可用内容提示
浏览：照片 / 视频 / 文字
手动探索：用户相机输入优先，选择仍保留
返回：回到最后有效地点与内容位置
```

地图不应永远保持最高强度。原视频的持续跟随适合其行进表达，但 Startrips 到站后必须主动让媒体成为主要内容，避免成为“始终飞行的路线动画”。

完整时间段、观察证据、不可推断事项与迁移表见 [视频研究附录](references/progress-map-video-study-2026-09-09.md)。视频与关键帧只保留在私有审阅材料中，**不随公开文档 PR 上传**。
