# PR #222 - Render a shared link as a read-only Atlas capability set

- **Source head:** `5b9aba871a327311bde9a45bf13b272019ab56d8`
- **Scope:** #200 phase D. New `src/journey/atlasView.ts` holds the `AtlasViewCapabilities` contract, `AtlasViewProvider`, `useAtlasView`/`useAtlasCapabilities`, the owner default and `GUEST_ATLAS_VIEW_CAPABILITIES`; the value carries `listJourneys`, `readMedia` and a `mutations` object that is `null` for a guest, so a read-only mode is the absence of a client rather than a hidden button. New `src/journey/SharedAtlasView.tsx` mounts `LivingAtlasApp` under that guest value, owns the loading / ready / empty / unavailable / error states, sets the persistent-earth stage itself because `AuthGateway` does not mount on this route, and adds `noindex, nofollow` and `no-referrer` meta tags to the shared document only. New `src/journey/sharedAtlas.ts` is the guest client: it reads the token from `location.hash` once per document, sends it only as `Authorization: Bearer`, maps the guest payload into the `Journey` shape the globe, timeline, story and playback already consume, checks the scope-closure invariant on every read, and keeps `SHARE_UNAVAILABLE` apart from `MEDIA_UNAVAILABLE`. New `src/journey/mediaReadRefresh.ts` replaces four independent refresh margins with one rule. `JourneyStory.tsx`, `JourneyPlaybackOverlay.tsx`, `JourneyTimeline.tsx`, `LivingAtlasApp.tsx`, `AuthGateway.tsx` and `main.tsx` read the contract instead of constructing owner clients directly, and `isSharedAtlasPathname` routes `/share` and `/share/`. New `src/styles/shared-atlas.css`. New tests: `atlasView.test.ts`, `sharedAtlas.test.ts`, `guestReadOnlyMode.test.ts`, `mediaReadRefresh.test.ts`, additions to `soundtrackReadCache.test.ts`, `LivingAtlasApp.test.ts` and `server/authorization/share-access.test.ts`. New `scripts/qa-guest-share.mjs` and a `browser-qa / guest-share` lane. No schema change and no change to `server/auth.ts`, so no `db:generate` and no regenerated `server/db/auth-schema.ts`.
- **User-visible change:** Opening `https://<host>/share#<token>` renders the Atlas as a read-only product mode: the globe, the Journey rail, the story dialog and Journey Playback all work, and no composer, upload, reorder, cover, delete or account affordance exists anywhere in the document at desktop, portrait-phone or phone-landscape size. The token stays in the URL fragment and never reaches a request URL. A link that is invalid, expired or revoked - including one that dies while the page is open - shows a finished unavailable panel rather than a blank screen or an error code, and a single withdrawn photo no longer ends a live session. Owner mode is unchanged.
- **Review fixes:** Codex left three inline threads, all verified against the code and all valid, fixed in `1c7513d`. (1) P1, `SharedAtlasView.tsx`: when the browser clock ran ahead of the server the expiry timer fired, the read succeeded with the same `expiresAt` and the same status, every effect dependency was unchanged and React kept the stale timer, so an expired Atlas could stay rendered indefinitely. The state now carries a `reads` counter that advances on every successful grant read and is a dependency of that effect; the delay is `sharedAtlasRecheckDelayMs` - `max(15_000, expiresAt - now)` - so re-arming cannot turn into a tight poll. (2) P2, `JourneyStory.tsx`: the `manageMedia` gate had landed on the first of two identical `journey-story__mobile-media-menu-trigger` elements, so a shared journey containing a photo still rendered the mobile media menu and, behind it, set-cover, organize, move and delete. The `asset`-branch trigger and the desktop `journey-story__media-order` group are now gated too, while autoplay, previous/next media and fullscreen stay. (3) P2, `sharedAtlas.ts`: `response.json()` on a 200 with an empty or truncated body rejected with a plain `SyntaxError`, which `reportFailure` ignored, leaving the viewer on the loading screen with no retry; parse failures on the success path are now reported as the retryable `network` failure. Owner review 5117317936 then named two blockers on that head: the missing ledger, which this file closes, and a real executed `browser-qa / guest-share` failure. That lane failure was in the lane, not the product: it clicked the Journey rail's first entry and asserted the boundary pair of the *first* journey of the granted set, but `journeyRail` is `[...journeys].reverse()` over a chronologically sorted list, so the first rail entry is the *last* journey - where 上一段 is enabled and 下一段 is disabled, exactly what the run reported. `5b9aba8` corrects the expectation, adds a second block that opens the rail's last entry and asserts the inverted pair, so both ends of the granted set are now measured, and makes the trailing-slash case wait for the rail to populate instead of reading the document in the frame where `.living-atlas` mounts around an in-flight read.
- **Follow-up:** The owner-facing share UI is phase E and does not exist yet, so no link can be created from the product and the QA lane stubs the guest API at the network boundary. The lane therefore does not cover the real presign lifetime (the stub answers instantly) or Story fullscreen media playback, which needs a decodable video the stub does not serve; the server side of the same contract is covered by the phase A-C integration tests. `#194` compact-mobile: the guest gate panel is one clamp with no mode switch, so it publishes no `data-mobile-v2` marker of its own and is out of the shared layout contract's scope.
