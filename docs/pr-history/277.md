# PR #277 - Model Home Base as a timeline of dated life periods

- **Source head:** `75a47a92485e623e14858fa5e5bf02f4e19d0eef`
- **Scope:** Issue #231. New Atlas-scoped `home_base_periods` table in `server/db/app-schema.ts` (place label, latitude, longitude, a required `started_on`, a nullable `ended_on`, a `source`, cascade on `atlases.id`) with drizzle-kit migration `0015_melted_tomorrow_man.sql` and its `meta/` snapshot; new pure `src/journey/homeBase.ts` holding `resolveHomeBaseForDate` on `startedOn <= date < endedOn` plus `classifyHomeBasePeriodWrite`, the invariant table the repository imports; new `server/repositories/home-base-repository.ts` writing a move as one Atlas-locked transaction that closes the open period on the new start day, and refusing a reversed interval, an overlap and a second current Home through `HomeBasePeriodConflictError`; new `server/routes/home-bases.ts` serving `GET/POST/PATCH/DELETE /api/home-bases` with the Atlas taken only from `requireAtlasAccess`; `server/app.ts` mounts it and maps the new error class to a 409 `{ error, message }` envelope. `CONTEXT.md` gains **Home Base / 常住地** and **Home Base Period / 常住地阶段** in `## Language` and one implementation invariant. No column is added to `journey_route_points` and `buildSharedJourneyView` is unchanged.
- **User-visible change:** None yet in the browser. The API can record and correct a Home Base timeline, and a Journey can resolve the Home Base that applied to its own date; no client surface renders it in this PR.
- **Review fixes:** Codex raised a P2: `deleteHomeBasePeriodForAtlas` was the one write path that skipped the Atlas lock, so a removal could commit inside the window an amend had already opened between the history it loaded and its own `UPDATE ... RETURNING`, which then matched no row and made `asRecord(undefined)` throw a 500. Confirmed and fixed in `a13c501`: the removal now runs inside `db.transaction` behind `lockActiveAtlas`, so every write on one Atlas serializes on the same row and only two orders exist, and it picks up the deleting-Atlas refusal the other paths already had. The `asRecord(updated)` read is guarded as well. The owner’s reviewer then raised a second P2: `DELETE` asked for the owner-only `delete` action, which contradicts #231 making Home Base member-confirmed and its manual editing include removing a period, leaving a member able to record a mistaken period and correct every field of it while unable to withdraw it. Changed to `update`, the same level `shares.ts` revokes a link under, and pinned by a `hasAtlasPermission` assertion in `server/routes/home-bases.test.ts`. Rebased onto `main@a6ec02a` (#274 added no migration, so `0015` still sorts after `0014` with no journal conflict) and dropped `sortHomeBasePeriods`, which `listHomeBasePeriodsForAtlas` made redundant by ordering in SQL and which had no caller outside its own test.
- **Follow-up:** The client surface, quiet inference and confirmation (#232), Atlas visual presence (#233), everyday fragments around Home (#234) and the Playback prelude/epilogue (#235) stay open. Deriving a start date from the first Journey belongs to #232 and is deliberately absent here. `source` accepts `suggested-confirmed` so #232 needs no schema change, but nothing writes that value yet.
- **Validation:** Locally `pnpm typecheck`, `git diff --check` and `node scripts/pr-history.mjs validate-all` (`./init.sh smoke`, EXIT=0). Every test is delegated to CI. The `core` lane applies the migration to an isolated PostgreSQL 17 and runs the suite including `src/journey/homeBase.test.ts` (boundary case proving a move day resolves to exactly one period, and that adding a later period leaves an earlier date's resolution unchanged), `server/repositories/home-base-repository.test.ts` (the move transaction plus all three refusals), `server/routes/home-bases.test.ts` (a body-supplied atlas/organization id ignored, a POST without `startedOn` answering 400, another Atlas's period answering 404, and each conflict rendered as the 409 envelope) and `server/tests/home-base-periods.integration.test.ts` (deleting a period leaves `journeys`, `journey_route_points` and `media_assets` intact, an Atlas deletion removes its periods, a second Atlas can neither read nor mutate the first's, and create, amend and removal all refuse an Atlas marked for deletion). The unchanged guest payload is pinned by the existing `shared-journey-repository.test.ts` key-set assertion. The `ledger` lane and the twelve `browser-qa` lanes remain authoritative for the ledger and the client.
