# PR #221 - Resolve compact mobile mode once and hand it to the globe overlays

- **Source head:** `f52e2b77360e3a0c3e4bad4c815e61728bdcfc23`
- **Scope:** #194. `src/scene/ParticleEarthScene.tsx` no longer contains `window.innerWidth <= 760`: the route-label safe area, the `buildJourneyConnector` `compact` argument and the route-label budget all read one scene-local `currentCompactMobileLayout` seeded from a new `compactMobileLayout` prop, and the layout rules move into the exported pure helpers `resolveRouteLabelSafeArea` (host size, host-relative header bottom, host-relative card rect, the flag) and `resolveRouteLabelLimit`. A new controller method `setCompactMobileLayout` recomputes the safe area and bumps `routeProjectionRevision`, because an orientation flip can cross the shared query with no canvas resize and the projection cache would otherwise keep the previous mode's label layout. `PersistentEarthProvider` in `src/scene/LivingAtlasGlobe.tsx` calls `useCompactMobileLayout()` and supplies the prop, so the login earth and the atlas earth share the shell's answer. `src/styles/journey-playback.css`, `src/styles/globe-time-scrubber.css` and the `.particle-earth-route__label text` block in `src/app.css` state their compact block as `COMPACT_MOBILE_MEDIA_QUERY`. New `src/journey/compactMobileContract.test.ts` guards an explicit allowlist of the surfaces #194 names - the two globe scene sources, `src/styles/journey-playback.css` and `src/styles/auth-gate.css` - and asserts nothing about any other stylesheet, so the legacy `?qaState=` experience is untouched. Six cases added to `src/scene/ParticleEarthScene.test.tsx`. No schema change, no server file, so no `db:generate` and no regenerated `server/db/auth-schema.ts`.
- **User-visible change:** On a coarse-pointer landscape phone wider than 760px (844x390, 932x430), the globe route labels, the Journey connector and the Journey Playback controls and soundtrack now use the same compact layout the Atlas shell already used, instead of desktop geometry. Desktop and tablet, where the shared query resolves false, are unchanged.

- **Follow-up:** `src/styles/auth-gate.css:725` is deliberately left width-only and the reasoning is in the file next to the block, as #194's audit clause and the feature's acceptance both permit. The block never decides interaction mode - `AuthGateway.tsx` does that from `useCompactMobileLayout()`, and every surface that decision gates (`.account-dock`, `.account-sheet*`) is styled outside any media query at lines 908+. It chooses a layout shape for a narrow viewport, sized in `vh`/`svh` (`70vh` earth, `min(66svh, 560px)` card, `clamp(34px, 10.8vw, 44px)` heading), and the sizes the shared contract additionally admits are coarse-pointer landscape at 480px tall or less, where a 66svh sheet is about 284px; widening the query would degrade landscape rather than align it. The guard test requires that justification to stay next to the block. Also open: the QA matrix in #194 lists eight viewports, and nothing in this PR drives a real browser at any of them - the coverage here is a `core`-lane contract test, which is what #194's own Tests section asks for over screenshot-only coverage, but it is not the matrix.
