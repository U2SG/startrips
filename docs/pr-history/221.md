# PR #221 - Resolve compact mobile mode once and hand it to the globe overlays

- **Source head:** `4185d5600a6bccb972cdccd4f15e1762a609b8bf`
- **Scope:** #194. One product-level compact/mobile decision, and the query literal is stated once. `src/journey/mobileLayout.ts` keeps `COMPACT_MOBILE_MEDIA_QUERY` and gains `COMPACT_MOBILE_LAYOUT_ATTRIBUTE` (`data-mobile-v2`) plus `compactMobileLayoutMarker`. `src/scene/ParticleEarthScene.tsx` no longer contains `window.innerWidth <= 760`: the route-label safe area, the `buildJourneyConnector` `compact` argument and the route-label budget read one scene-local flag seeded from a new `compactMobileLayout` prop, the layout rules move into the exported pure helpers `resolveRouteLabelSafeArea` and `resolveRouteLabelLimit`, and the host element publishes the marker. `setCompactMobileLayout` recomputes the safe area and bumps `routeProjectionRevision`, because an orientation flip can cross the shared query with no canvas resize. `PersistentEarthProvider` in `src/scene/LivingAtlasGlobe.tsx` supplies the prop from `useCompactMobileLayout()`; `JourneyRoutesQaPreview` in `src/main.tsx` does the same so the QA lane measures something. `JourneyPlaybackOverlay.tsx` and `GlobeTimeScrubber.tsx` publish the marker from the hook, `LivingAtlasApp.tsx` uses the helper for the attribute it already set, and `src/styles/journey-playback.css`, `src/styles/globe-time-scrubber.css` and the route-label block in `src/app.css` key off the attribute - none of the three contains `760` any more. New `src/journey/compactMobileContract.test.ts` (7 cases) guards the allowlist; six cases added to `src/scene/ParticleEarthScene.test.tsx`. New `scripts/qa-mobile-contract.mjs` and a fifth `browser-qa / mobile-contract` lane. No schema change and no server file, so no `db:generate` and no regenerated `server/db/auth-schema.ts`.
- **User-visible change:** On a coarse-pointer landscape phone wider than 760px (844x390, 932x430), the globe route labels, the Journey connector, the globe time scrubber and the Journey Playback controls and soundtrack now use the same compact layout the Atlas shell already used, instead of desktop geometry. Desktop and tablet, where the shared query resolves false, are unchanged.
- **Review fixes:** Review 5115848475 from U2SG raised two P1 blockers, both verified against the code and both accepted. (1) The first head copied the full `COMPACT_MOBILE_MEDIA_QUERY` literal into three stylesheets and guarded only one, which #194 forbids outright ("Do not duplicate this literal independently across TS and CSS"). Fixed in `bf94976` by taking the issue's preferred option: the surfaces publish `data-mobile-v2` from product state and the stylesheets key off it, so no stylesheet states a breakpoint at all, and the guard test now checks whole-file text rather than only `@media` preludes. (2) The phone-landscape QA matrix was not exercised. Fixed in the same commit with the `browser-qa / mobile-contract` lane, which drives all eight matrix viewports with a coarse pointer and asserts the query and every mounted surface's marker agree, that Playback controls stay on screen at 44px at 844x390 and 932x430, and that an orientation flip leaves no stale marker; it fails loudly if the browser does not report `any-pointer: coarse`, since the landscape half of the matrix rests on that clause. (3) CI on that head then caught a self-inflicted regression: the attribute selectors matched `.mobile-v2__timeline .globe-time-scrubber` at the same 0,2,0 specificity and, being imported later, displaced the Atlas timeline placement, which `browser-qa / post-login` reported as a 220px overlap between the scrubber play button and the journey chip at every mobile viewport. Fixed in `4185d56` by moving each scope into `:where()`, which restores the exact weight the rules carried inside the media query; the same commit stubs the media read the Playback preview issues, the only assertion the new lane had failed on.
- **Follow-up:** Two parts of #194's QA matrix remain unmeasured, because neither QA preview mounts them: label/header-chrome collision and Journey connector geometry. The lane says so in its own comment rather than implying coverage. `src/styles/auth-gate.css:725` is deliberately left width-only with its reasoning in the file, as #194's audit clause and the feature's acceptance both permit: the block never decides interaction mode - `AuthGateway.tsx` does that from `useCompactMobileLayout()`, and every surface that decision gates (`.account-dock`, `.account-sheet*`) is styled outside any media query - it chooses a layout shape for a narrow viewport, sized in `vh`/`svh` (`70vh` earth, `min(66svh, 560px)` card), and the sizes the shared contract additionally admits are coarse-pointer landscape at 480px tall or less, where a 66svh sheet is about 284px on a 932x430 phone. The two remaining copies of the literal in `src/styles/living-atlas.css` are the pre-existing #58 shell implementation on `main` and are outside this feature's allowlist; folding them into the attribute contract is the natural next step. `src/App.tsx` and `src/styles/personal-gallery.css` keep their own breakpoints as the legacy `?qaState=` experience.
