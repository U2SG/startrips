# PR #305 - Add same-asset private media previews

- **Source head:** `9754b781919d439e57a6681db201a6526c2f896b`
- **Scope:** Issue #264 / ST-049 browser-client half of the same-asset private preview protocol. Adds bounded photo/video preview production after original multipart completion, same-asset preview-layer selection for Story/Playback/prefetch, and focused login-media QA. Playback/Home session topology, placement-analysis ownership, EXIF scoring/parsing, guest-share protocol and server preview storage/state machines remain unchanged.
- **User-visible change:** Owner media can present a bounded preview from the same durable asset first, then replace it in place with the original while preserving asset identity and frame dimensions. Preview derivation is best-effort: the completed original remains successful even when preview request, signed PUT, rasterisation or preview completion fails.
- **Review fixes:** Rebased onto current main after #304. Closed the current duplicate-completion P2 by preserving an already-ready preview returned with a deduplicated/idempotently completed asset: the client now skips preview regeneration when the completed asset reports `previewState: ready`, so a failed best-effort replacement cannot demote or destroy an existing valid derivative. The regression fixture proves preview preparation/begin is never invoked for that ready duplicate and the ready state remains intact. An initial test-only typing error on the first repair head was corrected without changing the product rule.
- **Follow-up:** Preview production remains deliberately best-effort beneath the durable original. Guest/shared reads do not receive private owner preview metadata, and future preview-generation lifecycle improvements should stay at the shared server generation boundary rather than adding Story/Playback-specific ownership. Playback session step topology remains owned by the existing director and is not part of this slice.
