# PR #223 - Pin globe annotations to the geographic surface

- **Source head:** `25f88ac202f4f77fdab44b92d75da370ecd2b696`
- **Scope:** ROUTE_ANCHOR_RADIUS becomes GEOGRAPHIC_SURFACE_RADIUS, so the one canonical anchor #224 had already unified place labels, Route Points, route endpoints, the focus signal and the journey connector behind is now the real map surface instead of an elevated 1.46 shell. The personal glow keeps a render-only 1e-4 lift on that anchor and loses its world-space radial pulse; the route arc finishes flattening to zero lift by max zoom. Horizon clipping in buildProjectedRoutePath now probes along the spherical path with twelve bisection steps rather than along the straight chord with eight, because a zero-lift Route Point on the occluding surface makes that chord a secant. Place labels publish data-anchor-x/y and data-city-lat/lon, the scene publishes the focused coordinates, and a new browser-qa lane measures anchoring against the projected silhouette of the geographic surface.
- **User-visible change:** At high zoom, dragging or zooming the particle globe no longer makes place names, selected Journey locations, route endpoints or the focus signal travel at a different apparent speed from the coastline underneath them, and clicking a place name focuses the place it named. Route lines that cross the horizon now stop at the limb instead of being drawn a few degrees into the globe's silhouette.
- **Review fixes:** Codex raised horizon clipping; the stated mechanism did not reproduce, since isSphericalPointVisible short-circuits to true for a submerged point in front of the perpendicular foot, but the opposite error was real - the chord probe reported the crossing up to 5.27 degrees past the limb - and the spherical probe it suggested fixes it. The owner's review blocked on that thread and on this ledger, which had a bare carriage return inside its Validation line: the parser splits on newlines only and JS dot excludes U+000D, so the field genuinely did not match. The branch was also rebased onto #224, which dropped every hunk of the original commit that re-did work #224 had already landed, including a CITY_LABEL_ANCHOR_RADIUS constant that would have re-fragmented the coupling #224 removed.
- **Follow-up:** The lane's silhouette-containment bound is exact for a sphere but assumes the anchor is a surface point of that sphere; a future annotation that is deliberately elevated would need its own bound. The no-visible-jump measurement clicks the place label nearest the view centre, which is whichever place #79 collision left there, rather than a named fixture. Coastline detail (#154) and the globe-wide visual system (#220 family) remain separate.
- **Validation:** ./init.sh smoke here - pnpm typecheck, git diff --check, node --check on the new lane, and node scripts/pr-history.mjs validate-all. Nothing was run against a local server, database or browser. GitHub Actions is the authority: core (PostgreSQL, migrations, typecheck, full suite, build), ledger, and eight browser-qa lanes including the new city-label-anchoring lane, which measures every rendered place label against the projected geographic silhouette across four fixtures at 1x, 2x and max zoom, through a continuous pointer drag out toward the limb.
