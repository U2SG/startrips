# PR #455 - Route explicitly owned CI families on first occurrence

- **Source head:** `93d36a09e7cbedbc60121b1c6e2d109c2ee10b39`
- **Scope:** Issue #399. A non-infrastructure CI failure whose exact fingerprint is already carried by an active ONE owner's mapped issue is now routed to that registered owner on its first observed occurrence, instead of waiting for the recurring-family threshold. The recurrence threshold still escalates otherwise-unowned repeated families unchanged, and infrastructure families remain excluded. Regressions in `tests/test_review_regressions.py` pin both first-occurrence ownership discovery and `REPAIR_CI_FAMILY` routing.
- **User-visible change:** None. Control plane only.
- **Review fixes:** `93d36a09` resolves the review finding that `failure_family_owner()` flattened every fingerprint in a run, so a run mixing an owned failure with an unowned one could hand the unowned failure to the wrong owner; mixed runs now route conservatively and stay with the current feature.
- **Follow-up:** None.
- **Validation:** Local static checks only - `git diff --check` and `node scripts/pr-history.mjs validate-all`. The control-plane regression suite is GitHub-CI-authoritative per repository policy.
