# PR #689 - Withdraw the compass under the account menu even while it rotates

- **Source head:** `95096289980d8dbb12f0e591829b0df53725ee4b`
- **Scope:** The account-menu rule in `src/styles/living-atlas.css` now matches every descendant of the detail map's bottom-right control container directly. Each one gets `visibility: hidden; pointer-events: none` instead of inheriting `visibility` from the container. MapLibre rewrites the compass icon's inline transform on every `rotate` event, and in Chrome that icon could keep an inherited `visibility: visible` under a hidden button. That left the 6px compass strip beside the panel hit-testable, which made `globe-focus-chrome` / `detail-zoom-group-under-account-menu` fail in 3 of about 107 globe-context jobs since #660 (jobs 113221216344, 113429054904, 113660214086). The scenario now rewrites the compass transform every frame across the open, so the race is exercised on every run, and its diagnostics record the icon's own visibility and pointer-events.
- **User-visible change:** While the desktop account menu is open, the strip of the compass button beside the panel can no longer be clicked or dragged.

- **Follow-up:** None.
