# PR #220 - Anchor route geometry to one Route Point anchor and attenuate arc lift with zoom

- **Source head:** `187ee096d66448f3ccac713394b221864944bbe8`
- **Scope:** #193, globe rendering only. `src/scene/geo.ts` gains the canonical Route Point anchor (`ROUTE_ANCHOR_RADIUS` 1.46 and `routePointAnchor`) and replaces `buildSphericalRouteSegments`/`buildSphericalRouteLegs` with `buildRouteArcSamples`/`buildRouteArcLegSamples`, which store unit directions plus a per-vertex lift fraction (`RouteArcSamples`) instead of baked world positions; `liftAt` forces the lift to exactly zero at both ends of a leg, so an endpoint resolves to the anchor itself at any lift strength. New `src/scene/routeArcLift.ts` resolves one frame's lift as the minimum of three continuous terms - a semantic-zoom attenuation curve from 1x to 2.55x with a 0.06 floor, a screen ceiling of 12% of the smaller viewport edge, and the near-plane radial budget the label shell already occupies - plus `routeArcPixelsPerWorldUnit`, which measures magnification at the nearest depth a route vertex can occupy. In `src/scene/ParticleEarthScene.tsx`, `buildProjectedRoutePath` now takes samples and a `{radius, liftScale}` world, returns `{d, start, end}`, and clips a segment straddling the horizon at the crossing by bisection instead of dropping it; the route marker reads `routePointAnchor`, the route group carries `data-journey-route`, each marker carries `data-anchor-x`/`data-anchor-y`/`data-route-point-index`, and the host carries `data-route-arc-profile`, `data-route-arc-lift`, `data-route-arc-lift-px`, `data-route-arc-lift-cap-px` and `data-route-endpoint-max-error-px`. New `scripts/qa-route-anchoring.mjs` and its own `browser-qa / route-anchoring` CI lane measure the rendered SVG; `src/main.tsx` adds the reported US Southwest QA fixture. `docs/cross-feature-assumption-audit.md` records the new coverage for invariant 2 and narrows its known gap to the place-label half. No schema change, no server file, no migration and no regenerated `server/db/auth-schema.ts`.
- **User-visible change:** A Journey route line stays attached to its Route Point markers while wheel-zooming to maximum zoom instead of peeling tens of pixels away, and the reported Los Angeles / Yosemite detachment no longer occurs. Decorative arc altitude now decreases as the view closes in - a cinematic elevated geodesic at global view, restrained at regional, effectively geographic at maximum zoom - so a long leg can no longer become an oversized airborne chord across the screen. Near the limb the line tapers into its Route Point and both disappear together rather than the marker floating with its route already clipped.
- **Review fixes:** One inline review thread, 3935523420 from the Codex connector, P2, on the screen-space ceiling. Verified against the code and valid: the ceiling divided the focal length by the globe centre's camera depth, but the anchor shell reaches 1.46 * 1.15 * zoom, so a camera-facing vertex sits about 0.36 world units from the camera at 3x rather than 5.4 and is magnified roughly fifteen times more than the ceiling assumed; a route could therefore exceed the ceiling it was measured against. Fixed in `187ee09`: `routeArcPixelsPerWorldUnit` divides by `cameraDistance - anchorRadius * globeScale`, the worst case for magnification, floored at 0.2 so a degenerate configuration cannot divide by zero. The ceiling now binds from 1x, which lowers the global-view lift to about 0.83 of the full hump while keeping it an elevated arc. Answered in reply 3935594342 naming the commit and the two new cases.
- **Follow-up:** The regression-family search confirmed one sibling of the same class and filed it as #219: the focus signal is built at radius 1.45 while `LivingAtlasApp` derives that focus point from the selected Route Point's own coordinates, so the same geographic object is drawn at two radii and the journey connector lands on the 1.45 projection. It is not fixed here because moving it changes focus arrival geometry that `qa:post-login-controls` asserts. The place-label half of the same family is #196 and stays queued. The new QA lane measures a desktop viewport only; a phone viewport gets a smaller ceiling by construction but is not measured. `data-route-endpoint-max-error-px` is a read-back guard computed by the scene, not an independent measurement - the QA lane is what measures the rendered SVG.
- **Validation:** `./init.sh smoke` on the final code head `187ee09` - `pnpm typecheck` for both projects, `git diff --check`, `node --check scripts/qa-route-anchoring.mjs` and `node scripts/pr-history.mjs validate-all` - plus `validate-pr --pr 220`. Behaviour is verified by GitHub Actions and nowhere else, by product-owner rule: the `core` lane runs the rewritten `src/scene/geo.test.ts` route cases, the new `src/scene/routeArcLift.test.ts` and the new projection cases in `src/scene/ParticleEarthScene.test.tsx`, and the new `browser-qa / route-anchoring` lane drives the real US Southwest fixture at 1x, 2x and 3x zoom. On this head that lane reported an endpoint-to-marker distance of 0.071, 0.045 and 0.058 CSS px across ten measured endpoints per zoom against a 1.5 px threshold, with the arc lift falling 0.8325 -> 0.2284 -> 0.0000 and projected altitude 96.00 -> 96.00 -> 0.00 px against a 96.00 px ceiling.
