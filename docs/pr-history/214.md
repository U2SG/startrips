# PR #214 - Document the cross-feature assumption audit as repository policy

- **Source head:** `d519c941efb3a4a0d24352b9b52f9586e981e5fa`
- **Scope:** Two new Markdown files, no product code. `docs/cross-feature-assumption-audit.md` is the durable form of the policy defined in issue #198: philosophy (what did this change make variable that older code assumed was fixed, and which previously-correct subsystem now receives inputs it was never designed for), a nine-row high-risk dimensions table with the subsystems to audit and the canonical question for each, an eleven-entry invariant library where every invariant is one sentence citing the issue that established it, a per-invariant map to the automated QA that encodes each one together with the parts it does not cover, the risk-driven matrix with its six bounded axes, the regression-family-search procedure, the weekly recent-change interaction audit with its four output buckets, and a recent-cases table. The ninth dimension, authorization identity and lifetime, is not in #198's original eight; it is added because #200 and #201 established invariants that none of the eight covers. `.github/pull_request_template.md` carries the audit block — the dimension checklist, `Old assumptions potentially invalidated`, `Dependent subsystems checked`, `Cross-feature fixtures exercised`, `New follow-up issues found`, the sentence permitting a small isolated pull request to state `No material cross-feature assumption changed` with a one-line reason, and an HTML comment reminding a P0/P1 fix, or a P2 defect that reveals a shared architectural assumption, that a `Regression-family search:` line is required — plus a ledger reminder pointing at `docs/pr-history/README.md`. #198 phases C (targeted invariant QA) and D (a recent-change audit helper script) are deliberately out of scope: both would add files outside `docs/` and `.github/`.
- **User-visible change:** None in the product. GitHub now prefills a body for every new pull request in this repository, which is #198 phase B.
