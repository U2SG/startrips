# PR #214 - Document the cross-feature assumption audit as repository policy

- **Source head:** `f5803b0ced5715edcb5ce360bafee2550d849b53`
- **Scope:** Two new Markdown files, no product code. `docs/cross-feature-assumption-audit.md` is the durable form of the policy defined in issue #198: philosophy (what did this change make variable that older code assumed was fixed, and which previously-correct subsystem now receives inputs it was never designed for), a nine-row high-risk dimensions table with the subsystems to audit and the canonical question for each, an eleven-entry invariant library where every invariant is one sentence citing the issue that established it, a per-invariant map to the automated QA that already encodes it, the risk-driven matrix with its six bounded axes, the regression-family-search procedure, the weekly recent-change interaction audit with its four output buckets, and a recent-cases table.
