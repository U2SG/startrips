# PR #719 - Reorder Route Points from one sentence in the Composer

- **Source head:** `7cb896a05760b3e68ba6a9c00e07518a1b447e58`
- **Scope:** `POST /api/intents/route-order` (update permission) sends the sentence and ordered Route Point labels as positional ids to the intent model and returns an order that must be an exact permutation, else no proposal; capabilities gain `routeOrder.configured`. The share reader's provider call moves into a shared `intent-model-request` helper with unchanged behaviour. The Composer adds 「用一句话调整顺序」 with a preview of moved points and the consequences of the proposed order (times going backwards, Stay anchors to correct), applied only by 「应用新顺序」 and superseded by manual reorders or a newer sentence.
- **User-visible change:** With an intent provider configured, members can reorder a draft route by describing it; nothing changes until they apply and save.
- **Review fixes:** Owner review: editing the sentence voids a preview (the proposal is bound to its sentence), with a browser repro. Codex: the proposal is bound to the exact points sent (ids and labels), so a renamed point voids it; consequence warnings are no longer squeezed into the route-row grid. CI: `final-acceptance` runs without an API and fails on any unstubbed `/api` request; it now stubs `/api/intents/capabilities` as off, matching the real disabled-driver answer.
- **Follow-up:** No per-Atlas in-flight guard for reorder requests.
- **Validation:** Local `pnpm typecheck`, `git diff --check`, `node --check`. CI run 39799692283 on the Source head (rebased on main bf72906e): `core`, `keepsake-render` and all eight browser-qa shards passed.
