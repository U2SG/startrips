# PR #687 - Harden and trim the authenticated API after #683

- **Source head:** `32638367ff85a85ab197b762379869b90d1e1f85`
- **Scope:** The four owner-approved #683 follow-ups, one commit each. Account-identity, password change/enrollment and email-change routes read the session through `getAuthoritativeSession` (`disableCookieCache`) instead of the 60 s cookie cache. A new integration test revokes a session that holds a real cache cookie and asserts 401 on all six routes, with a control showing the cache is still accepted by `get-session`. `perf-api` runs only when server code, the `src/journey` modules the server imports, dependencies or the workflow change. Owner Journey responses and upload completion no longer carry `storageDriver`, `storageKey`, `previewStorageKey` or `uploadedByUserId`; `contentHash`/`contentHashVerified` stay because cover reveal and duplicate clustering read them. The workspace gate starts `atlases/current` alongside `organization/list` when an active Organization is known, keeps the list-first decision order, and no longer hangs on a failed Atlas read.
- **User-visible change:** The signed-in workspace opens one round trip sooner. A network failure while reading the Atlas now shows the error state instead of a stuck loader. A session revoked elsewhere can no longer change sign-in methods, password or email during the cache window.
- **Review fixes:** None; Codex found no issues on `72954c2b` (comment 6073849268). This Source is that tree rebased without conflicts onto `dca58f11` (#686); #686 only adds `markAutoRoutePriority` calls in the shared files and no media projection, so no new review was requested.
- **Follow-up:** The browser QA mocks in `scripts/*.mjs` still include the withheld media fields; they are inert extras and can be pruned when those scripts are next touched.
