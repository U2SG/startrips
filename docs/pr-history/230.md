# PR #230 - Execute the video trim transport in QA and bound it to its beat

- **Source head:** `955c7ddd7a32eda6b1b0eab58035d8b483e8a629`
- **Scope:** #195 Phase 2 follow-up to #228. `src/journey/videoTrimPlayback.ts` gains `videoTrimSeekApplies()`, and `JourneyPlaybackOverlay.tsx` keys its `videoTrimSeek` state by `assetId` plus `director.stepIndex` instead of `assetId` alone, routing every settle, guard, watchdog and the hold effect through that key; `settleVideoTrimSeek()` now only updates the beat it was computed for and never creates a state, and it no longer clears the watchdog inside the state updater. `onSeeked` gains the holding-state guard `onLoadedMetadata` already had. The overlay publishes the transport's status as `data-video-trim` on the playback root, beside the existing `data-playback-*` attributes. `src/main.tsx` gives the `journey-playback` QA preview an opt-in trim mode (`qaMode=trim`, `qaTrimIn`, `qaTrimOut`) that declares a window through `mediaTrimResolver` with the matching booked length and a second media asset after the video. `scripts/qa-media-controls.mjs` gains a `videoTimeline` page option and two checks. New cases in `videoTrimPlayback.test.ts`. No schema change, no server file touched, no CI matrix entry changed.
- **User-visible change:** None intended. Two transport defects are closed: a native scrub after the trim watchdog had settled `unavailable` re-entered the seek path and handed the beat a second completion owner, and a trim state keyed by asset alone would have let a late `seeked`, `waiting` or watchdog settle from one beat release the budget of the next beat trimming the same source. Only the second is not yet reachable in production, because no planner emits two windows over one video today.
- **Review fixes:** None yet on this PR. It exists because the fresh-context evaluator returned NEEDS_WORK on #228 after that PR had already merged, and both findings are addressed here rather than left as prose: P1, that no assertion executed the transport - all sixteen new checks in #228 were pure-function assertions while the seek, the hold, the out-point completion and the pause path lived in the overlay's event handlers, in a repository with no jsdom and no browser lane that declared a trim; and P2, that the PR body and ledger of #228 stated `seeked` was "bounded to the holding states so it cannot loop" when the handler carried no such guard. The record and the code now agree.
- **Follow-up:** The QA timeline is synthesized, not decoded: the shim gives the element a deterministic `duration`, `currentTime`, `seeked` and `timeupdate` and never dispatches `ended`, because the data URI the other media checks use decodes to nothing and would make `duration` `NaN` and degrade the trim before it started. The element, the React handlers, the `element.currentTime` write and the director are real; frame-accurate seek behaviour on a decoded source is not covered and would need a real media fixture. #228's own follow-up is unchanged and still open: no real video duration is persisted, so a trim is still booked against `QUICK_RECAP_PENDING_VIDEO_DURATION_MS`, and a trimmed beat still prefetches the whole source.
- **Validation:** Locally only `./init.sh smoke` - `pnpm typecheck` (client and server projects), `git diff --check`, `node --check scripts/qa-media-controls.mjs`, and `pr-history validate-all`. No local test run, dev server, browser, database or Docker; CI is authoritative. The two new checks run inside the existing `login-media` browser lane against the submitted head: `playback-video-trim-segment` records that the only seek was to 1.2 s and was issued while the status was `positioning`, that the first sample under `playing` was at 1.3 s, that the beat's last media time was 4.6 s against an out-point of 4.7 s and a 12 s source, and that `ended` never fired; `playback-video-trim-pause` records that media time froze at 2.4 s across a pause, that the trim kept ownership of the beat rather than degrading, that no sample left the segment, and that the resumed beat still ended at 9.1 s against an out-point of 9.2 s.
