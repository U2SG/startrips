# PR #289 - Keep superseded merge-readiness runs green

- **Source head:** `08dd0681d82aaaa293e91ee62b749c9e3c74f9ca`
- **Scope:** Change only the merge-readiness controller scheduling/authority model and its contributor documentation. Replace `cancel-in-progress` serialization with live head + newer-run freshness checks so superseded controller executions finish successfully as no-ops instead of leaving cancelled check-runs attached to PR heads. Because the freshness read and GitHub status write are not atomic, every status write also hands the shared context to a newer controller that appeared in that gap: an in-flight newer run forces fail-closed pending, while a completed newer run has its exact status restored from commit-status history.
- **User-visible change:** GitHub should no longer show a red aggregate check on an otherwise-green merged PR solely because an older `merge-readiness-controller` execution was superseded. Required `verify`, `merge-readiness`, explicit `merge-ready`, resolved-review and squash-only gates are unchanged.
- **Review fixes:** Self-review first guarded stale rejection and label mutations. Automated P1 review then identified the remaining check/write race where an older invalidation could publish `pending` after a newer sign-off had already completed. Source `08dd0681` closes the regression family in both directions: invalidation, rejection and success all run a post-write handoff; a stale writer restores the newest completed controller status or leaves the gate pending while that newer run is still in flight. A completed newer success also restores `merge-ready` if an older controller removed it after sign-off.
- **Follow-up:** Historical cancelled check-runs on already-merged PR heads cannot be rewritten; the fix applies to controller runs created after this workflow lands.
- **Validation:** Earlier Source `e00c581e` was exercised with two rapid review submissions: run `34310423470` detected newer run `34310430163` and finished success/no-op, while the newer run completed success, and no controller check was cancelled. Source `08dd0681` adds the post-write handoff required by the P1 race review; exact-head GitHub CI and a final sign-off/invalidation race probe are authoritative before merge. This final ledger commit changes no workflow or product code.
