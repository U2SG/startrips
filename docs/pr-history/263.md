# PR #263 - Give private media a same-asset preview and display size

- **Source head:** `114d24dd806933ca19da90d9d92e4fdb3e8fe997`
- **Scope:** Source issue #260. Adds orientation-corrected display dimensions and derived-preview columns (storage key, MIME, byte size, state) to `media_assets` with drizzle migration `0012_wet_quasimodo.sql`; a pure server-side derivation plan in `server/media/preview-derivation.ts` bounded by the new `MEDIA_PREVIEW_MAX_EDGE_PIXELS` and `MEDIA_PREVIEW_MAX_BYTES` ceilings in `server/config.ts`; the two-step producer protocol `POST /api/uploads/assets/:id/preview` and `.../preview/complete` behind `server/services/media-preview.ts`; an optional `preview` block on both `GET /api/uploads/assets/:id/read-url` and `GET /api/shared/:token/assets/:assetId/read-url`, the guest one signed from the same resolved row with the same grant-capped lifetime; a `signObjectUpload` presigned single-object write on `MultipartStorage`; derived-object cleanup in the media, journey and atlas deletion paths; the no-foreign-key `media_preview_writes` ledger with its `reconcilePreviewWrites()` sweep (migration `0013_whole_sir_ram.sql`), which gives an issued preview write an owner that survives the cascade; `listObjects` prefix listing and `readObject` whole-object read on `MultipartStorage`, with a global `previews/` key layout and the `reconcilePreviewNamespace()` sweep that retires every preview object no `media_assets` row references; and JPEG frame-size reading in `server/media/preview-image.ts` so completion verifies the produced object against both ceilings.
- **User-visible change:** None yet. The backend contract and model only; #260 states the frontend line does not wait on this ticket, and no `src/` code produces or consumes a preview yet (#264).
- **Review fixes:** Atlas deletion now deletes the derived object alongside the original, which the cascade would otherwise orphan permanently. `previewStorageKey` became the generation marker for the whole protocol: begin, the ready promotion and both failure clears compare-and-swap on it, so of two concurrent derivations exactly one owns the row and a superseded one is refused instead of stranding the winner's object. The single-object preview write is presigned to its own `MEDIA_PREVIEW_UPLOAD_EXPIRES_IN_SECONDS` (120 s) rather than the 15-minute multipart part window, since it has no session to abort. The PR closes nothing: it says `Addresses #260`, because #260's acceptance also needs the client wiring in #264. Issued preview writes became deletion-safe rather than clock-bound: every presigned preview PUT is recorded in `media_preview_writes`, which carries no foreign key because a reference to `media_assets`, `journeys` or `atlases` would cascade away with the very row whose disappearance the record exists to survive, so a PUT landing after the media, Journey or Atlas was deleted no longer leaves an object nothing can name. `reconcilePreviewWrites()` then treats an expired signature as a starting point rather than a terminal state, since expiry stops a new request from starting but not one already streaming: it inspects the key and retires whatever is under it once nothing references it. A surviving `media_preview_writes` row is a retirement obligation, not a reference: nothing reads it to serve, restore or locate media, and no read path can reach the key through it. The settle interval that decided when such a row could be forgotten was then removed entirely, with `PREVIEW_WRITE_SETTLE_MS` and the `retire_attempted_at` column: a presigned `PutObject` is authorised when the request starts and carries no provider-enforced request lifetime, so no elapsed interval proves an in-flight write has finished, and keeping every unlanded record instead buys an unbounded row per abandoned derivation. On the owner's decision in #260, `MultipartStorage` gained prefix listing and a whole-object read instead. `reconcilePreviewNamespace()` enumerates the preview namespace and deletes every key no `media_assets` row references, so forgetting a record is free and a late object is discovered from storage however long it took to arrive; the record pass now retires an unreferenced key and drops its record in one go. Preview keys moved from `atlasId/journeyId/previews/uuid` to one global `previews/` prefix, because an atlas-scoped path cannot be enumerated without knowing every Atlas id that ever existed - nothing shipped on the old layout, the key was never an authorization input, and it now carries even less about the original. Migration `0013` was regenerated rather than amended, since it has never been applied anywhere. The same read capability made acceptance item 6 satisfiable as written, so the earlier wording that softened `MEDIA_PREVIEW_MAX_EDGE_PIXELS` to a requested bound is reverted in both `server/config.ts` and `server/media/preview-derivation.ts`: completion measures the produced object's byte size and reads it back for its encoded frame size, and an oversized file, an oversized frame and bytes that are not a readable still are all decided failures that never reach `ready`.
- **Follow-up:** #264 wires the producer and the consumers into the client and is a remaining acceptance dependency of #260, which stays open. #265 was split out to verify a produced preview's encoded pixel size; that verification is in this PR on the owner's decision, so what remains there is the owner's to re-scope or close - stated in a comment on the issue, with no edit to it or its queue entry. Assets uploaded before this lands stay preview-less by design; no backfill pass is in scope.
- **Validation:** Locally `./init.sh smoke` only - `pnpm typecheck` on both projects, `git diff --check`, and `node scripts/pr-history.mjs validate-all` / `validate-pr`. Everything behavioural is CI: the `core` lane runs the migration and the full suite including `server/media/preview-derivation.test.ts`, `server/tests/media-preview.integration.test.ts` the new guest-preview cases in `server/tests/share-grants.integration.test.ts`, the new `server/media/preview-image.test.ts`, the prefix-and-read cases in `server/storage/s3-compatible-storage.test.ts` against a non-empty `keyPrefix`, the two-ceiling verification against a pinned 600x467 JPEG read back out of storage and the 2048x1024 pixel-ceiling rejection, and the four lifecycle cases (a PUT landing after its media was deleted, an abandoned write forgotten with no clock, an object landing after its record was forgotten and retired by the namespace sweep, and a referenced object surviving that sweep); `ledger` validates this file; twelve `browser-qa` lanes cover the unchanged product surfaces. No test, browser, database or object store was run locally.
