# PR #263 - Give private media a same-asset preview and display size

- **Source head:** `3c64314ddccacbda9b999e5fc0c36c693fd89959`
- **Scope:** Source issue #260. Adds orientation-corrected display dimensions and derived-preview columns (storage key, MIME, byte size, state) to `media_assets` with drizzle migration `0012_wet_quasimodo.sql`; a pure server-side derivation plan in `server/media/preview-derivation.ts` bounded by the new `MEDIA_PREVIEW_MAX_EDGE_PIXELS` and `MEDIA_PREVIEW_MAX_BYTES` ceilings in `server/config.ts`; the two-step producer protocol `POST /api/uploads/assets/:id/preview` and `.../preview/complete` behind `server/services/media-preview.ts`; an optional `preview` block on both `GET /api/uploads/assets/:id/read-url` and `GET /api/shared/:token/assets/:assetId/read-url`, the guest one signed from the same resolved row with the same grant-capped lifetime; a `signObjectUpload` presigned single-object write on `MultipartStorage`; derived-object cleanup in the media, journey and atlas deletion paths; and the no-foreign-key `media_preview_writes` ledger with its `reconcilePreviewWrites()` sweep (migration `0013_cute_jackal.sql`), which gives an issued preview write an owner that survives the cascade.
- **User-visible change:** None yet. The backend contract and model only; #260 states the frontend line does not wait on this ticket, and no `src/` code produces or consumes a preview yet (#264).
- **Review fixes:** Atlas deletion now deletes the derived object alongside the original, which the cascade would otherwise orphan permanently. `previewStorageKey` became the generation marker for the whole protocol: begin, the ready promotion and both failure clears compare-and-swap on it, so of two concurrent derivations exactly one owns the row and a superseded one is refused instead of stranding the winner's object. The single-object preview write is presigned to its own `MEDIA_PREVIEW_UPLOAD_EXPIRES_IN_SECONDS` (120 s) rather than the 15-minute multipart part window, since it has no session to abort. The PR closes nothing: it says `Addresses #260`, because #260's acceptance also needs the client wiring in #264. Issued preview writes became deletion-safe rather than clock-bound: every presigned preview PUT is recorded in `media_preview_writes`, which carries no foreign key because a reference to `media_assets`, `journeys` or `atlases` would cascade away with the very row whose disappearance the record exists to survive, and `reconcilePreviewWrites()` retires any recorded key no asset references once the signature has expired - so a PUT landing after the media, Journey or Atlas was deleted no longer leaves an object nothing can name. Finally, the two ceilings are now described at their true strengths: `MEDIA_PREVIEW_MAX_BYTES` is checked against the object that landed, while `MEDIA_PREVIEW_MAX_EDGE_PIXELS` is the pixel size the plan asks for, not a verified property of the stored still.
- **Follow-up:** #264 wires the producer and the consumers into the client and is a remaining acceptance dependency of #260, which stays open. #265 verifies a produced preview's encoded pixel size, which needs an object-read capability `MultipartStorage` does not have today; until it lands, no consumer may treat the pixel ceiling as a decode-cost guarantee, and both `server/config.ts` and `server/media/preview-derivation.ts` say so. Assets uploaded before this lands stay preview-less by design; no backfill pass is in scope.
- **Validation:** Locally `./init.sh smoke` only - `pnpm typecheck` on both projects, `git diff --check`, and `node scripts/pr-history.mjs validate-all` / `validate-pr`. Everything behavioural is CI: the `core` lane runs the migration and the full suite including `server/media/preview-derivation.test.ts`, `server/tests/media-preview.integration.test.ts` the new guest-preview cases in `server/tests/share-grants.integration.test.ts`, and the delete-between-sign-and-PUT sweep cases; `ledger` validates this file; twelve `browser-qa` lanes cover the unchanged product surfaces. No test, browser, database or object store was run locally.
