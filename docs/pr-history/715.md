# PR #715 - Propose a share selection from one sentence

- **Source head:** `d89d5c9d3e8efda27adfc3e01bf21e2122dc68c2`
- **Scope:** New `INTENT_*` config (default `disabled`, fail-closed for incomplete `http-model`), an OpenAI-compatible share-intent reader with a strict JSON-schema answer, and `/api/intents` (`GET /capabilities`, `POST /share`). Candidates are the session Atlas's live Journeys (id, title, dates; 200 most recent via a lightweight query); the answer is narrowed to candidate ids and the `1d`/`7d`/`30d` presets. Writes nothing. The multi-journey share dialog gains a sentence entry that pre-ticks the proposal. Deploy compose/env pass the new variables through.
- **User-visible change:** When enabled, the share dialog offers 「用一句话说想分享什么」; the proposed Journeys and expiry are pre-selected and the link is still created only by Create. Hidden when the deployment has no intent provider.
- **Review fixes:** Dropped the nullable enum from the strict schema (server validation still refuses unknown expiries). Codex: `enable_thinking` is sent only to DashScope hosts; any manual edit (Journey checkbox, expiry preset, custom expiry) supersedes a pending proposal.
- **Follow-up:** The strict schema has not yet been exercised against the production provider. "Share only landscape photos" is planned as a separate PR (on-demand vision classification, server-side grant media scope).
- **Validation:** Local `pnpm typecheck`, `git diff --check`, `node --check scripts/qa-owner-share.mjs`. Unit/route/config tests and `qa-owner-share` (`reveal-share` shard) are authoritative in GitHub Actions.
