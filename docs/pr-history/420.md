# PR #420 - Gate the Earth Dive hard-policy stage fixture on an observable detail construction instead of the stage attribute

- **Source head:** `46dd468374fb968348bf278dc348243913b1bd5c`
- **Scope:** Issue #411 reported the `browser-qa / earth-dive` lane intermittently failing the `prewarm: detail lifetime survived hard policy` assertion. The reported root cause is ALREADY FIXED ON MAIN: PR #409 merged as 88ecbec1fe685927b3f8da09f63b454ac90bb390 and `scripts/qa-earth-dive.mjs:741` now reads `after.mapRemovalCount !== after.mapConstructionCount`, both counters from the same post-switch snapshot, so a construction that raced the `before` read no longer reds the lane. The issue's newest comment claiming main still carries the old form predates that merge. The real remaining gap, which the owner explicitly kept the issue open for, is the sibling assumption in the same loop: both intermediate-stage iterations (`prewarm` and `blending`) wait on the `data-earth-dive` stage attribute via `wheelUntil`, and that attribute flips before a detail map is observable (`mapConstructionCount: 0`, `mapDomCount: 0` in the captured green run on 05f8c75). On those timings the iteration asserts teardown of a resource that was never constructed, so it passes vacuously and the particle-only teardown contract from ST-084 goes untested. The fixture must wait on an observable construction/readiness signal and must fail rather than pass when the pre-switch snapshot proves nothing was constructed. Checked sibling, deliberately out of scope: the comparison at `scripts/qa-earth-dive.mjs:900` uses `policyBeforeDisable`, which is read after the dive has committed to detail and the detail map has been dragged, so construction is already observable there and it is not an instance of this class.
- **User-visible change:** Gate the Earth Dive hard-policy stage fixture on an observable detail construction instead of the stage attribute
