# PR #815 - Draft Route Points from picked photos natively on iPhone

- **Source head:** `194533da1d834def8a8194440054d1089bc56ef2`
- **Scope:** Native version of the web photo Route Point flow (#337) in the StartripsMedia package (`mobile/ios/NativeMedia/Sources/RouteBatch/`). `PlacementPlanner` is a Swift port of `planMediaPlacementProposals` (`route-point-proposal-v1`, same limits), keyed by stable file ids. The shared fixture `Tests/Fixtures/route-point-proposals.json` runs in vitest (`src/journey/mediaPlacementParity.test.ts`) and in XCTest. `PlacementSignalReader` reads GPS, accuracy, capture time and offset from HEIC and JPEG through ImageIO. It fills a missing coordinate from the PHAsset location only when library access is already granted. `RouteBatchDraft` ports the review edits and the apply body. `RoutePointBatchModel` keeps a per-Journey journal. The operation id is written before the first upload and before the apply POST. A lost response reads `GET …/:operationId` instead of resending. Undo reads the receipt first. Uploads now send `recordedEvidence` on start. Picking two or more photos in the Story tools opens the SwiftUI review; a single photo keeps the plain import. Server and web flow unchanged.
- **User-visible change:** On iPhone, an owner who picks several photos for a Journey sees numbered groups. Groups either match existing Route Points, are new drafts, or are a visible unplaced group. The owner can rename, reassign, split, merge and reorder them, then apply them as one batch and undo it. Auto-organize is a per-batch opt-in.
- **Review fixes:** Codex P2: dismissing an unknown apply result now only closes the sheet. The journal stays, so the next open reconciles by reading the batch status. Codex P2: `partially-undone` is no longer reported as undone. The sheet shows the server's conflicts by kind and keeps the journal until the owner closes it. Unit tests cover both fixes.
- **Follow-up:** No XCUITest was added because the system photo picker cannot be driven from XCUITest. A new Route Point draft defaults to the name 新途径点, and there is no reverse-geocoded name yet. Times on new drafts cannot be edited natively. On the first Source CI run, ios-native hit the 45-minute limit after the existing `testLandscapeAtlasIsFullBleed` failed with "Failed to terminate app" and the UI suite was retried. The rerun of the failed jobs passed.
- **Validation:** Local: `pnpm typecheck`, `pnpm vitest run` on the parity and mediaPlacement tests, `git diff --check`, and `swiftc -typecheck` of the package sources and tests for the iOS Simulator SDK. GitHub CI run 44656001613 on the Source head passed ios-native on rerun, including all `RouteBatchTests`. Core and browser-qa also passed. No browser QA locally.
