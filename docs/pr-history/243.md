# PR #243 - Preserve particle optical size across renderer DPR

- **Source head:** `8a9ce4541f214b7d2f02d31051e6e998e243a2d0`
- **Scope:** Updates the shared particle-earth ShaderMaterial so each draw reads the effective Three.js renderer pixel ratio and converts the existing CSS-space point-size expression into drawing-buffer pixels at the final `gl_PointSize` assignment. The same contract applies to base and spatial-LOD particle materials, survives `ShaderMaterial.clone()`, and does not add React state, per-frame allocation, or changes to particle density/quality policy.
- **User-visible change:** Particle core/halo size is no longer implicitly tied to a 1× drawing buffer. High-DPR displays and quality-tier DPR caps keep the authored optical particle size consistent instead of making the particle globe appear finer/smaller solely because renderer resolution changed.
- **Review fixes:** None before the initial review; this ledger records the final reviewed code Source head for the first PR submission.
- **Follow-up:** Real-GPU/browser comparison should still grade optical core/halo size, additive brightness, point-size hardware limits, and render cost across effective DPR 1/1.25/1.5/2/3. This PR does not claim a measured performance improvement. #241 already owns single-projection-space geography and is intentionally not duplicated here.
