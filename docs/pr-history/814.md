# PR #814 - Create, share and revoke Journey share links natively on iPhone

- **Source head:** `4a4212accd10e1b3aeac79c144bb4d8abe532a22`
- **Scope:** Adds an owner-only native share sheet on the iPhone Journey card (beside 打开故事 and the edit pencil). It creates a link via `POST /api/shares` with the web expiry choices (1, 7 or 30 days, or a custom time within a year) and optional media selection, then hands `<origin>/share#<token>` to the system share sheet. It lists this Journey's active links from `GET /api/shares` and revokes them via `POST /api/shares/:id/revoke` after confirmation. All calls go through `AtlasSession.api`; the token lives only in view state and is never logged or persisted. Guests never see the entry. No server change.
- **User-visible change:** The owner can create, send and revoke share links for a Journey on iPhone.
- **Review fixes:** Codex P2: a just-created link stayed sendable after its grant was revoked. The created link and any open system share sheet are now cleared on revoke, even if the list reload fails (`4a4212ac`, unit test added).
- **Follow-up:** Part of #775 (iOS recording loop R3). The create path is covered by unit tests only, because the system share sheet cannot be driven reliably from XCUITest.
- **Validation:** Local `git diff --check` and compile-only `xcodebuild build-for-testing`. GitHub CI on the Source head (rebased onto `ad1b5d24`) ran the new unit tests and the revoke XCUITest in ios-native, which is authoritative.
