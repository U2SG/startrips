# PR #321 - Deterministic private Keepsake render prototype

- **Source head:** `d5b55d98193b50332c068f1e647666db6b2569a1`
- **Scope:** Implements ST-019 / issue #87 as a deterministic private-render mechanism proof behind the existing Keepsake manifest authority. It adds a narrow render plan containing semantic scenes, exact manifest timing, Journey revision/narrative pin and authorized media IDs only; separate trusted resolvers provide revision-pinned Journey presentation context and private media bytes. A CI-only FFmpeg prototype encodes the same three-stop portrait fixture twice, records codec/resource evidence, compares decoded-frame signatures, and validates actual decoded scene boundaries. It does not add a production render queue, client export UI, public sharing path, soundtrack, or a second narrative state machine.
- **User-visible change:** No production export surface is exposed yet. The prototype proves that a future private Keepsake export can preserve the existing narrative order/timing while resolving private media through an owner-authorized boundary and producing deterministic decoded video evidence without exposing storage coordinates or share URLs to the serializable plan.
