# PR #467 - Bound Windows process provider queries

- **Source head:** `0bd6e49743cb02e566bebef5a83e881d90914f60`
- **Scope:** Issue #399. `execution.py`'s `snapshot()` enumerated the full `Win32_Process` schema, so the Windows CIM provider could stall on unrelated expensive fields while the identity/argv fields it actually reads were healthy; Experience occupancy and canonical launch then timed out. The query now requests only `ProcessId`, `ParentProcessId`, `Name`, `CommandLine` and `CreationDate` via `-Property`, keeping the existing `CreationDate` identity contract and the fail-closed carrier semantics unchanged. A regression in `tests/test_recovery.py` asserts the bounded projection and rejects the former unbounded query shape.
