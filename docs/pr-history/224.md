# PR #224 - Place the focus signal on the canonical Route Point anchor

- **Source head:** `259a384ccc8e81df4b2dec7a7ca4afe02f9ecab3`
- **Scope:** Source issue #219, a P2 in the #193 family. `src/scene/ParticleEarthScene.tsx` built the focus signal at a world radius of its own, 1.45, at four sites: the initial `personalGeometry` position, `applyFocusPoint`, and the `pointRadius` defaults of `projectFocusPointForRotation` and `solveFocusRotationForViewport`. A new exported `focusSignalAnchor(point, fallback)` resolves the signal through `routePointAnchor` from `src/scene/geo.ts` and absorbs the fallback logic the two vector sites had copied verbatim; the two parameter defaults now name `ROUTE_ANCHOR_RADIUS`. No `1.45` literal remains in the module. `src/scene/ParticleEarthScene.test.tsx` gains a `#219` block: the focused Route Point and the fallback both land exactly on `routePointAnchor` at length `ROUTE_ANCHOR_RADIUS`, and a source guard asserts the superseded literal is gone and that both `pointRadius` defaults name the constant, because a helper cannot cover a parameter default. `scripts/qa-route-anchoring.mjs` gains a second framing on a real Route Point of the same fixture and a `measureFocusSignal` read-back. The cross-feature audit then found the same coupling one layer over: place labels agreed with the route layer only because they repeated the literal `1.46` at five sites - the city particle direction scaling and both label projections - so `ROUTE_ANCHOR_RADIUS` could move and detach them silently. Those five now name the constant or call `routePointAnchor`; the value is identical, so nothing renders differently, and the source guard covers both literals. No schema change and no change to `server/auth.ts`, so no `db:generate` and no regenerated `server/db/auth-schema.ts`.
- **User-visible change:** Selecting a Route Point now draws one object instead of two. The focus signal sits exactly on the Route Point marker it represents at every zoom, and the connector from the active Journey card terminates on that same anchor instead of landing short of the marker - the separation grew with magnification and was worst near the limb, where perspective parallax is strongest.

- **Follow-up:** `src/scene/` keeps three deliberately different shells that are not Route Point renderings and were left alone: `GLOBE_SURFACE_RADIUS` 1.39 for surface picking, 1.405 for the coastline LOD rings, and 1.43 / the 1.44-based spread for the legacy archive-burst and ambient cluster particles. The new measurement covers the focus signal against the Route Point marker. It does not measure `data-journey-connector-end-x/y` directly, because the `qaState=journey-routes` preview mounts no active Journey card for the connector to leave from; the connector is covered transitively, since `updateJourneyConnector` projects `personalGeometry` index 0, the same buffer the measurement reads. The focus signal is projected without the `isSphericalPointVisible` cull that `projectRoutePoint` applies, so a focus point behind the limb still publishes `data-personal-point-*`; that predates this change and the connector itself is culled correctly.
