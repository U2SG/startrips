# PR #466 - Derive a before-SHA so main ledger immutability runs on a recovery dispatch

- **Source head:** `6567ced64c0f72d280bf629d5e9e9f6cf253d428`
- **Scope:** Issue #452. The ledger job's 'Validate main ledger immutability' step was gated on `if: github.event_name == 'push'` and read `github.event.before`/`.after`, so a workflow_dispatch recovery run for a missed exact-main push skipped it silently. This closes the sibling gap PR #451 identified in its own Regression-family search and explicitly left outside its acceptance scope: scripts/verify-main-sha.mjs gains a `derive-before-sha` command that resolves the previously validated main commit from the newest successful push run of ci.yml on main through the Actions API, the immutability step now also runs on workflow_dispatch with that derived SHA and `github.sha`, the derivation exits non-zero when no previous validated main commit can be determined instead of leaving the check skipped, and the ledger job declares `actions: read` alongside `contents: read` for the run lookup.
- **User-visible change:** None. Repository CI only.
- **Review fixes:** None yet; this ledger accompanies the first submitted Source.
- **Follow-up:** A dispatch-run log showing the immutability step executing can only be captured after this lands, because the exact-main guard rejects a dispatch on any non-main ref; the derivation writes the derived SHA and the resolved before..after range to the job summary so that artifact materializes on the first real recovery dispatch.
- **Validation:** Local static checks only - `git diff --check`, `node --check` on both changed scripts and `node scripts/pr-history.mjs validate-all`. `pnpm typecheck` covers only src, server and templates, which this PR does not touch. Every test, including `node --test scripts/verify-main-sha.node-test.mjs` in the ledger job, is delegated to GitHub Actions, which remains authoritative.
