# PR #811 - Add an owner-scoped upload status endpoint for native resume

- **Source head:** `b4cd4655b724441aa84391e4e0b0989b1aed0fa4`
- **Scope:** Adds `GET /api/uploads/:id/status` behind the multipart family's `requireAtlasAccess(..., "create")` gate, backed by a new `readUploadStatusForAtlas` that reuses the Atlas-scoped `findUpload`. Returns `uploadId`, `status`, `partSize`, `partCount` and the persisted `assetId`, matching the iOS `UploadStatus` decoder and its `upload-status.json` fixture. Foreign, unknown and malformed ids all answer `404 UPLOAD_NOT_FOUND`; storage keys and provider upload ids are never returned. No schema change.
- **User-visible change:** The iPhone app can resume, complete or cancel an interrupted media import instead of failing on a missing route.
- **Review fixes:** None.
- **Follow-up:** The remaining #769 items (session/guest contract samples, batch move/undo verification) stay open. Part ETags are client-journaled and not stored server-side, so the route does not return them.
- **Validation:** Local `pnpm typecheck`, uploads route unit tests and `git diff --check`. New API integration tests in `server/tests/upload-evidence.integration.test.ts` (fixture shape parity, completed/deleted asset id, reconciliation states, cross-Atlas 404, guest Bearer and anonymous 401) run in GitHub CI, which is authoritative.
