# PR #320 - Use SSH agent for deploy authentication

- **Source head:** `c126e839c471c1b5bdf305ef3f90a76c4cf68213`
- **Scope:** Makes `--key` optional in `scripts/deploy-main.py`. When omitted, Paramiko uses ssh-agent/default SSH key discovery; when supplied, the existing explicit key-file path remains supported. `deploy/README.md` documents the no-argument deploy command and one-time Windows OpenSSH agent setup.
- **User-visible change:** Routine deployments no longer need to put a private-key path on the command line, reducing repeated execution-layer false positives while preserving the exact-main CI gate, immutable archive deployment, rollback, migration, and health verification behavior.
- **Review fixes:** None yet.
- **Follow-up:** Windows hosts must enable the built-in `ssh-agent` service and add the server key once before the no-argument deploy path can authenticate. Explicit `--key` remains the fallback for workstations that intentionally do not use an agent.
- **Validation:** `python -m py_compile scripts/deploy-main.py`; `python scripts/deploy-main.py --help`; `git diff --check`. Current workstation inspection confirmed `ssh-agent` is installed but stopped/disabled, which is why the documented one-time setup is required.
