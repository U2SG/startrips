# PR #298 - Resolve Chinese place-name exonyms from shared place data

- **Source head:** `7243d26193c8e8a82e442036070d03206540174e`
- **Scope:** Issue #296 / ST-054 only, forward location search behind the `LocationSearch` adapter boundary. `ENGLISH_QUERY_ALIASES`, the 22-entry hand-maintained exonym table in `server/location/photon-location-search.ts`, is deleted; `git grep -n 檀香山 -- server/location/photon-location-search.ts` is empty and the only occurrences under `server/` are test queries. The English query now comes from `server/location/place-name-aliases.ts`, which derives it from `public/earth/cities.json` — the bounded place-name payload already checked in for globe labels (34,104 entries, 12,354 carrying a Chinese display name, built offline by `scripts/build-city-data.mjs` from GeoNames plus the Wikidata CC0 crosswalk), read lazily on first need and indexed once per process into 12,840 keys. This generalizes beyond the finite alias table because recall is now a property of the data rather than of which names were typed into a source file: every localized name the payload carries is answerable, including `檀香山`, and two rules written without naming a city widen each display name into the forms people type — administrative suffixes are dropped (`纽约市` also answers `纽约`, `首尔特别市` also answers `首尔`), and a leading country qualifier of any length is dropped when the remainder is a known place name and no prefix of the qualifier is one. A shared name resolves to its most populous claimant, since the payload is population-ordered. Only an all-Han query reads the payload. Two Chinese-to-Chinese transliteration variants are folded so the payload stays the sole authority on English names. `server/location/location-search.ts` and `nominatim-location-search.ts` are untouched, no vendor identifier is added under `src/`, and no globe-label, reverse-geocode or EXIF behaviour changes.
- **User-visible change:** A Chinese exonym for a foreign place now finds it. `檀香山`, `美国檀香山` and `Honolulu` all resolve to Honolulu, Hawaii, US, as do thousands of localized names that were never hard-coded (`里约热内卢`, `慕尼黑`, `佛罗伦萨`, `印度尼西亚雅加达`). Every mapping the removed table answered still answers identically, with the same `label` / `labelEnglish` / `labelLocal` fields. A local query is not rewritten: `深圳南山区`, `上海外滩` and `西安大雁塔` stay searches for those places. `深圳` still costs a single provider request. An unknown query returns nothing, and unreadable place-name data reports `LocationSearchUnavailableError` rather than a fabricated place.
- **Review fixes:** (1) Codex P2: gating the English request only on result metadata let a fuzzy but bilingual primary hit swallow an exonym query. The gate now asks whether any primary result actually names the query, so an answer full of unrelated bilingual places still earns its English round trip while a query the provider answered by name still costs one request and never reads the payload. (2) Codex P2: with the gate reworked, `preferEnglish` had been tied to an empty primary answer, so `limit` unrelated local hits would push the resolved place past the slice. The pre-existing expression is restored, leaving `mergeBilingualResults` byte-identical to `main`. (3) Codex P2, half accepted: the four-character qualifier cap dropped valid full country names and is gone, bounded only by the query, so `印度尼西亚雅加达` and `阿根廷布宜诺斯艾利斯` resolve. `阿拉伯联合酋长国阿布扎比` still does not, and the leading-place-name guard rather than the cap is why — `阿拉` is itself a payload entry (Arrah, India). Removing that guard was measured against the payload: it resolves that query but turns `西安大雁塔` into a search for `雁塔`, making every city-plus-landmark query eligible for the same misrouting, so the guard stays and both behaviours are pinned by tests.
- **Follow-up:** None for #296. The payload carries one Chinese display name per place, so a place whose common exonym differs from the recorded spelling still needs its variant; the two known cases are folded Chinese-to-Chinese here, and widening that coverage belongs to `scripts/build-city-data.mjs` and its alternate-name source, not to the search layer.
