# PR #298 - Resolve Chinese place-name exonyms from shared place data

- **Source head:** `19f45619655341b6ad5928d175475f04de38c265`
- **Scope:** Issue #296 / ST-054 only, forward location search behind the `LocationSearch` adapter boundary. `ENGLISH_QUERY_ALIASES`, the 22-entry hand-maintained exonym table in `server/location/photon-location-search.ts`, is deleted; `git grep -n 檀香山 -- server/location/photon-location-search.ts` is empty and the only occurrences under `server/` are test queries. The English query now comes from `server/location/place-name-aliases.ts`, which derives it from `public/earth/cities.json` — the bounded place-name payload already checked in for globe labels (34,104 entries, 12,354 carrying a Chinese display name, built offline by `scripts/build-city-data.mjs` from GeoNames plus the Wikidata CC0 crosswalk), read lazily and indexed once per process into 12,840 keys. This generalizes beyond the finite alias table because recall becomes a property of the data rather than of which names were typed into a source file: every localized name the payload carries is answerable, including `檀香山`, and two rules that name no city widen each display name into the forms people type. Administrative suffixes are dropped, so `纽约市` also answers `纽约` and `首尔特别市` also answers `首尔`. A leading qualifier of any length is dropped only when that qualifier is itself the Chinese name of a country or region, taken from the platform's CLDR region display names in `server/location/chinese-region-names.ts` rather than from a table here; requiring that positive evidence is deliberate, because treating "this prefix is not a known city" as proof of a qualifier would let an arbitrary prefix change which place a query means. A shared name resolves to its most populous claimant, since the payload is population-ordered. Suffix morphology is deliberately split by job: the index is widened with the broad set (`市`, `市区`, `区`, `县` and the municipality tokens), which is safe because every stripped form is another key for the same payload entry, while proving that a provider label already names the query accepts only the municipality suffixes of the settlement itself (`特别行政区`, `自治市`, `特别市`, `市`). That distinction is what keeps the generalization honest: a rule broad enough to widen recall across 12,354 names would otherwise equate different geographic levels, and `纽约州` is New York State rather than `纽约`. `州` is excluded from both lists, because in this payload it marks a first-level division rather than a city name variant. Only an all-Han query the provider did not answer by name reads the payload, and two Chinese-to-Chinese transliteration variants are folded so the payload stays the sole authority on English names. `server/location/location-search.ts` and the Nominatim adapter are untouched, no vendor identifier is added under `src/`, and no globe-label, reverse-geocode or EXIF behaviour changes.
- **User-visible change:** A Chinese exonym for a foreign place now finds it. `檀香山`, `美国檀香山` and `Honolulu` all resolve to Honolulu, Hawaii, US, as do thousands of localized names that were never hard-coded (`里约热内卢`, `慕尼黑`, `佛罗伦萨`, `印度尼西亚雅加达`, `阿拉伯联合酋长国阿布扎比`). Every mapping the removed table answered still answers identically, with the same `label` / `labelEnglish` / `labelLocal` fields. Local queries are not rewritten: `深圳南山区`, `上海外滩` and `西安大雁塔` stay searches for those places, and so does an unrecognised qualifier such as `不存在巴黎`. `深圳` still costs a single provider request. An unknown query returns nothing, and unreadable place-name data reports `LocationSearchUnavailableError` rather than a fabricated place. A search for `纽约` returns New York City even when the provider offers New York State first, and `马里兰` is no longer answered with Randallstown.
- **Review fixes:** (1) Codex P2: gating the English request only on result metadata let a fuzzy but bilingual primary hit swallow an exonym query. The gate now asks whether any primary result actually names the query, so an answer full of unrelated bilingual places still earns its English round trip while a query the provider answered by name still costs one request and never reads the payload. (2) Codex P2: with the gate reworked, `preferEnglish` had been tied to an empty primary answer, so `limit` unrelated local hits would push the resolved place past the slice. The pre-existing expression is restored, leaving `mergeBilingualResults` byte-identical to `main`. (3) Codex P2: the four-character qualifier cap dropped valid full country names. The cap is gone and qualifier stripping now requires the head to be a CLDR region name, which resolves the reported `阿拉伯联合酋长国阿布扎比` and is stricter than the first attempt's "head is not a known city" heuristic, under which `阿拉` (Arrah, India) blocked that query and an unverified prefix could have redirected one. (4) Self-review: the first form of that gate accepted any provider label containing the query, so a same-named street could stand in for the exonym; a label now names the query only when it equals it or differs by an administrative suffix. (5) Owner P2: that administrative suffix set was too broad to prove identity — `namesSamePlace("纽约州", "纽约")` was true, so a primary New York State hit could suppress the `New York City` lookup and return the wrong geographic entity. Identity now accepts only municipality suffixes; the index keeps the broad set. The regression-family sibling of the same assumption is fixed in the same commit: `州` also left the index list, where it had mapped `马里兰州` to Randallstown and `麻萨诸塞州` to Grafton. `server/location/photon-location-search.test.ts` asserts that `纽约` answered with a bilingual `纽约州` hit still issues `q=New York City` on a second request, and `place-name-aliases.test.ts` asserts the identity pairs directly.
- **Follow-up:** None for #296. The payload records one Chinese display name per place, so a place whose common exonym differs from the recorded spelling still needs a variant; the two known cases are folded Chinese-to-Chinese here, and widening that coverage belongs to `scripts/build-city-data.mjs` and its alternate-name source rather than to the search layer. Qualifier stripping is also limited to what the runtime's CLDR data carries: a runtime without Chinese region names strips nothing, which narrows recall but never resolves a different place.
