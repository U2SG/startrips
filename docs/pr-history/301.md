# PR #301 - Add historical Home context to Journey Playback

- **Source head:** `7c3ec1b65b226046ef30eb7f45c05de9ef355ce1`
- **Scope:** Issue #235 / ST-030 only. Add optional owner-only historical Home Prelude and Home Epilogue narrative context to Journey Playback using the existing Home Base period resolver, canonical geographic anchoring and the existing playback plan/step/camera authorities. Home remains camera-only context: it never becomes a persisted Journey Route Point, route arc, measured travel leg, shared DTO field or guest-visible Home datum.
- **User-visible change:** When a confirmed historical Home period is eligible and the Journey is farther than the inclusive 25 km skip radius, Full Playback may begin with a Home prelude and return to Home after the final Journey beat. An eligible Home epilogue remains the final camera/life context through the outro/completion fade; without eligible Home, the existing route-framed intro/outro behavior is unchanged. Atlas Journeys become usable as soon as Journey data loads, while optional private Home history may hydrate later. A Home period that resolves after Playback has already started is intentionally deferred to the next playback session rather than changing the current beat under the viewer.
- **Review fixes:** Earlier owner CFAA blockers kept Home camera ownership through outro/completion and removed optional private Home hydration from the Atlas readiness critical path. The final P1 found that detached Home hydration could still rebuild the active playback topology by raw `stepIndex`. Final Source snapshots the resolved Home narrative context for the mounted playback session, so late hydration cannot replace the current `playbackStepIdentity`, visible media owner, camera target or timer; a later newly mounted playback may snapshot and use the newly available Home context. The regression covers the active media beat, camera owner and preserved timer budget across a late Home resolution.

Unknown Journey end dates remain ineligible for Home epilogue rather than borrowing `startedOn`.
