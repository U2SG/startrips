# PR #820 - Create the first Atlas natively on iPhone

- **Source head:** `5ce1750c92d65d6221653dbfd3a94f4bc836556f`
- **Scope:** Replaces the native sign-in dead end (这个账户还没有图谱) with a native Atlas-name step in `NativeSignInView`, driven by a new `AtlasSetup` that mirrors the web gate (`gateFromOrganizationList` / `gateFromCurrentAtlas` / `AuthGateway.createOrganization`): no Organization → `POST /api/auth/organization/create {name, slug: <ascii-slug-or-atlas>-<8 hex>}` → `organization/set-active` → `POST /api/atlases/bootstrap {title, dedication: ""}`; an active Organization whose `/api/atlases/current` answers 404 ATLAS_NOT_FOUND → the same step prefilled with the Organization name, bootstrap only. A retried create re-lists Organizations first, so a lost response never creates a second one. A later launch whose owner `refresh()` gets 404 from `/api/journeys` sets `atlasSetupRequired` and reopens the sheet on the step instead of showing 当前图谱或分享不可用. Calls go through `AtlasSession.ownerResponse` (the former `ownerAuthCall` body, now also allowing `/api/atlases/`), which keeps cookies and the first-party Origin on writes. 取消 on the step returns to the welcome screen with the session kept; swipe-dismiss is disabled there. Server and web unchanged.
- **User-visible change:** A verified account without an Atlas can name and create it on iPhone and lands in the empty Atlas with 创建第一段旅程; an unfinished Atlas is completed on the next sign-in or launch.
- **Review fixes:** Codex P2: Atlas names are validated, clamped and prefilled by the server's UTF-16 limit of 80 code units, never splitting a character (`5ce1750c`). CI fix: the `AtlasSetupTests` helper no longer publishes a WebKit cookie; the default off-main cookie writer started WebKit's network process and trapped in `WebKit::allDataStores()` when the suite ran first (`5ce1750c`).
- **Follow-up:** `AtlasSession.publishOwnerSession`'s default `write` closure runs `WKHTTPCookieStore.setCookie` off the main actor; it only trapped in tests, but the default could be made main-actor isolated. No XCUITest: the synthetic fixture has no auth backend.
- **Validation:** Local `xcodebuild build-for-testing` (no simulator booted) and `git diff --check`. GitHub CI ios-native on the Source head ran `AtlasSetupTests` (web slug/UTF-16 title rules, the three-call order with bodies and Origin, a lost create resumed without a second Organization, a failed bootstrap resumed after a relaunch refresh, error mapping, the sign-in model's retry) and passed; CI is authoritative. The main session simulator-tested the flow.
