# PR #791 - Undo a saved journal import in one step

- **Source head:** `0fd11601a4f6d0b7940ab23ed4ed0fe997630688`
- **Scope:** Saving an AI import preview sends `importedChapterIds`; the server stamps the chapters this save adds with a server-owned `importBatch` record (`id`, `at`, key-order-independent `digest`, `pointIds`) inside the existing chapter JSONB (no migration), and every write strips client copies and restores the stored record. The hotel step appends the points it creates for batch events and refreshes the digest of still-untouched batch chapters. New `POST /api/journeys/:id/journal/imports/:batchId/undo` (origin, update permission, Atlas/Journey lock, journal revision) removes the batch's chapters and deletes only created points no remaining event, media asset, media upload or stay anchor uses (points locked `FOR UPDATE` first), pruning stale route segments and bumping the Journey revision when points go. Edited batch chapters return 409 `JOURNAL_IMPORT_EDITED` with a count unless `confirmEdited: true`; a batch with no chapters left is a 200 no-op.
- **User-visible change:** After saving an AI import, 每日手记 offers 「撤销这次导入」 for the latest import with a confirmation (and a second one naming how many chapters were edited), then 「已撤销这次导入。」. The helper paragraph above the hotel tool is gone.
- **Review fixes:** None.
- **Follow-up:** Only the latest batch is offered in the UI; older batches remain undoable through the API.
- **Validation:** Local `pnpm typecheck`, `git diff --check` and `node --check` on the QA scripts. GitHub CI is authoritative for the unit tests, the PostgreSQL integration tests (created vs reused vs shared points, edited confirmation, replay, stale 409, foreign 404, forged import records) and browser QA (`qa:journal-hotels` including `qa:daily-journal` undo flow).
