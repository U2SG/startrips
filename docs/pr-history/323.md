# PR #323 - Quiet Home Base suggestion on the Atlas

- **Source head:** `649df1dacf994a48121c89f3f782d6b9dd6ea0e0`
- **Scope:** Implements ST-060 / issue #232 by wiring the frozen ST-027 inference core into the Atlas. Adds an atlas-scoped `home_base_dismissals` table with a drizzle-kit generated migration, a dismissal read and write on `server/routes/home-bases.ts` whose Atlas comes only from `server/authorization/atlas-access.ts`, a pure `src/journey/homeBaseSuggestion.ts` mapping inference state and reason codes to the issue's evidence-phrased copy, a non-modal card rendered beside the Atlas timeline on desktop and in the planet state on compact mobile, a confirm action that creates a new period through the #231 write path, and a `browser-qa / home-base-suggestion` lane with `scripts/qa-home-base-suggestion.mjs`. `src/journey/homeBaseInference.ts` does not appear in the diff: its thresholds, state union and digest function are imported exactly as merged.
- **User-visible change:** A member whose Journeys repeatedly start and end near one region is now offered a quiet, non-modal card naming that region from their own Place Labels, explaining the evidence rather than announcing a conclusion, with confirm, 「暂时不用」 and 「不是<place>」 answers. The card never appears while Journey Story or Journey Playback is open, the Atlas stays interactive behind it, an answer survives a reload, and confirming a move closes the previous period instead of overwriting it. Guests and shared Atlases see none of it.
- **Review fixes:** Round one closed two Codex findings: inference no longer runs against an unread Home history, so an owner with a confirmed Home cannot briefly receive a first-time card; and the period returned by the confirmation, not the best-effort refresh, is what takes the card down, so a failed refresh cannot leave an enabled card that only conflicts. Round two repaired the QA and contract surfaces the feature had invalidated: the stale `AtlasMutations` key list, the guest negative-contract vocabulary scan, a substring 地球 locator that matched two buttons, missing dismissal mocks in the login and final-acceptance fixtures, and a Playback-to-Story return that blocked the next header interaction. Round three closed the owner's 2026-09-12T21:54:08Z audit: `homeBaseSuggestionCanBeConfirmed` now classifies the very draft the confirm button would POST against the whole recorded history, so an Atlas holding only bounded periods is never offered a confirmation `classifyHomeBasePeriodWrite` would reject as an overlap (thread 3997731556); and the card renders in compact mobile Atlas mode, which the previous `!isMobileV2 && view === "timeline"` condition had excluded entirely even though mobile has no timeline view and no other route to the feature (thread 3997754982). Round four bound the card's name to its own evidence: `resolveHomeBasePlaceLabel` had been voting over every Journey endpoint while the core excludes future-dated Journeys and drops the final Route Point of a Journey with no `endedOn`, so a future plan near the anchor could name a card it never supported; the evidence digest is now the authority for which Journey starts and ends may vote, and unparseable evidence fails closed to no label and therefore no card (thread 3997795359). Every top-level review thread is answered.
- **Follow-up:** The third item of the owner's audit is filed as #324: `home_base_dismissals` is unique on `atlas_id` alone while the inference core scopes a `rejected` answer to a <= 25 km region, so answering about region B erases an explicit rejection of region A. Fixing it needs more than one row per Atlas, a list-shaped read and a selection step before the core is called, which changes the single-row table and the singular dismissal round trip this feature's acceptance pins, so it is an owner decision rather than a widening of this PR.
