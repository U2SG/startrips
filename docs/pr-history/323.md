# PR #323 - Quiet Home Base suggestion on the Atlas

- **Source head:** `81f7802e75d5fec37825fd62b05ad8a87842b0cc`
- **Scope:** Implements ST-060 / issue #232 by wiring the ST-027 inference core into the Atlas. Adds an atlas-scoped `home_base_dismissals` table with drizzle-kit generated migrations, a dismissal read and write on `server/routes/home-bases.ts` whose Atlas comes only from `server/authorization/atlas-access.ts`, a pure `src/journey/homeBaseSuggestion.ts` mapping inference state and reason codes to the issue's evidence-phrased copy, a non-modal card rendered beside the Atlas timeline on desktop and in the planet state on compact mobile, a confirm action that creates a new period through the #231 write path, and a `browser-qa / home-base-suggestion` lane with `scripts/qa-home-base-suggestion.mjs`. `src/journey/homeBaseInference.ts` carries a bounded diff required by the owner's 2026-09-12T22:55:56Z comment: an optional `evidenceNotBefore` input and the extraction of dismissal matching into the exported `applyHomeBaseDismissalToInferenceResult`. Its thresholds, its state union, the `HomeBaseEvidenceReasonCode` union, `homeBaseEvidenceDigest` and the dismissal policy itself are unchanged.
- **User-visible change:** A member whose Journeys repeatedly start and end near one region is now offered a quiet, non-modal card naming that region from their own Place Labels, explaining the evidence rather than announcing a conclusion, with confirm, 「暂时不用」 and 「不是<place>」 answers. The card never appears while Journey Story or Journey Playback is open, the Atlas stays interactive behind it, an answer survives a reload, an explicit rejection of one region survives answering about another, and confirming a move closes the previous period instead of overwriting it. Guests and shared Atlases see none of it.
- **Review fixes:** Round one closed two Codex findings: inference no longer runs against an unread Home history, so an owner with a confirmed Home cannot briefly receive a first-time card; and the period returned by the confirmation, not the best-effort refresh, is what takes the card down. Round two repaired the QA and contract surfaces the feature had invalidated: the stale `AtlasMutations` key list, the guest negative-contract vocabulary scan, a substring locator that matched two buttons, missing dismissal mocks in the login and final-acceptance fixtures, and a Playback-to-Story return that blocked the next header interaction. Round three closed the owner's 2026-09-12T21:54:08Z audit: `homeBaseSuggestionCanBeConfirmed` classifies the very draft the confirm button would POST against the whole recorded history (thread 3997731556), and the card renders in compact mobile Atlas mode, which the previous `!isMobileV2 && view === "timeline"` condition had excluded entirely (thread 3997754982). Round four bound the card's name to its own evidence: the digest is now the authority for which Journey starts and ends may vote on the Place Label, and unparseable evidence fails closed to no label and therefore no card (thread 3997795359). Round five implemented the region-scoped dismissal contract that had been filed as #324, after the owner's 2026-09-12T22:55:56Z comment folded it into this PR — the table is unique on `(atlas_id, evidence_digest_hash)` rather than on `atlas_id` alone, the read is list-shaped, and `rejected` outranks `soft` when several answers match (thread 3997815052) — and closed the three findings that repair drew: the unbounded digest is no longer the index key (3997945995), the backfill uses the built-in `md5` instead of an extension-dependent `sha256` (3997968549), and `inferHomeBaseCandidate` runs once per render with each persisted answer folded over that single result instead of rerunning the clique search per row (3997989676). Round five also closed the owner's remaining temporal-history blocker: bounded Home history is authoritative temporal context, so evidence and onset for a new current period derive from the current side of the latest recorded boundary and a boundary-spanning Journey contributes only its post-boundary endpoint (thread 3997891449). Round six closed the two findings the dismissal write drew: the endpoint accepted any nonempty `evidenceDigest`, so it now requires `isPersistableHomeBaseEvidenceDigest` — a bounded, canonical, checksum-verified digest over persisted Journey UUIDs — and the repository caps both the stored digest size and the number of answers per Atlas (thread 3998025173); and the persisted `dismissedOn` is now derived from server time rather than the request body, so a wrong browser clock cannot move the 90-day re-prompt interval in either direction (thread 3998025177). Every top-level review thread is answered.
