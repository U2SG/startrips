# PR #211 - Make Journey Playback media prefetch tempo-aware

- **Source head:** `305c67de9a92707e8a29ce5a0f1a07a83d018a71`
- **Scope:** New pure module `src/journey/playbackPrefetchPlan.ts`: `readyMsAheadForTempo(tempo)` derives the lookahead budget from `PLAYBACK_TEMPO_PROFILES` as `2 * immersive.imageMs - profile.imageMs` (7300 / 6200 / 4500 ms), and `planPrefetchWindow()` walks the expanded steps forward from the current index, spending each step's caller-supplied duration until the budget is exhausted, capped by `MAX_PREFETCH_ASSETS = 8`. `JourneyPlaybackOverlay.tsx` replaces the fixed `current + next` decode lookahead and the stop-loads-the-whole-chapter read effect with that window, keyed on `stepIndex` and `tempo`; `playbackHoldTargetMedia()` pins the asset the director may hold on (a stop chapter's first image, past any leading video) into the window. `useJourneyPlaybackDirector` gains `durationForStep(step)`, the single place a step becomes milliseconds, and the step timer is refactored onto it so the window and the timer cannot diverge. PR 5 of the shared narrative timing plan (#126, #166, #197, #87).
- **User-visible change:** At `fast` tempo an image-heavy Journey prepares 5 assets ahead instead of 2, so the decode hold that made Fast stutter more than Standard should fire less often; `immersive` keeps roughly the previous current + next window. Arriving at a route point no longer fires a signed-read request for every asset in the chapter at once.
- **Review fixes:** None yet.
- **Follow-up:** #197's browser-QA acceptance item (bounded decode holds under throttled network/decode on cold-media fixtures) is not met — it needs a `scripts/qa-*.mjs` capture, not a node test. The budget constants land inside #197's suggested ranges but the issue states exact values require QA. `planPrefetchWindow` deliberately overspends the budget in one case: reaching the next step that displays an asset at all, because the director holds on that asset. The overlay consumes durations through the director accessor, so #210's widening of `PlaybackStepDurationResolver` to `(journey, step, tempo)` needs to change only the one call site inside the director.
