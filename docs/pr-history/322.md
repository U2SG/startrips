# PR #322 - Add Living Atlas attention hierarchy measurement lane

Addresses #246.

- **Source head:** `4aa4579ea6cc316aeb5521d3652a71421d965e04`
- **Scope:** ST-037 adds a per-state attention contract and a reversible DPR optical-measurement lane for the existing Living Atlas visual system. `docs/attention-hierarchy.md` maps Atlas overview, selection/focus flight, arrival/dwell, Story viewing, fullscreen/Playback media beat, return to Atlas, and loading/failure onto named current components plus existing motion/glow tokens. In dev/QA only, `ParticleEarthScene` publishes `data-attention-layers` for every current `createParticleEarthMaterial` consumer after `renderer.render()` has run; the dataset includes authored `uPointSize`, the actual shader `uPixelRatio` uniform written by `ParticleEarthMaterial.onBeforeRender`, DPR-normalized resolved CSS optical size, opacity and strong-glow state. `scripts/qa-attention-hierarchy.mjs` uses fixed browser contexts at requested DPR 1/2/3, asserts the browser actually exposes those DPRs, asserts the documented high-quality renderer-DPR sequence 1/2/2 for the fixed 1200×800 fixture, then requires every material shader DPR to match the renderer and the resolved CSS size/opacity to remain invariant. The lane is registered in `package.json` and the GitHub browser-QA matrix. No authored particle, route, label, shader, motion-token or style-token value is changed.
- **User-visible change:** None by design. This PR freezes the current attention hierarchy as a measurable contract without retuning it. The measured focus fixture shows the personal focus signal as the sole strong-glow particle owner; background/archive/shell/halo layers remain below that threshold, while Route SVG and City/Place labels remain unaffected comparison references. Future browser-DPR, renderer-budget or shader-DPR regressions will fail QA instead of silently changing optical priority.
- **Review fixes:** P2 `3996937290` found that the first Source only echoed authored `uPointSize` and independently multiplied by `renderer.getPixelRatio()`, so it could pass if `onBeforeRender` stopped populating shader `uPixelRatio`. Source lineage was corrected to publish only after `renderer.render()`, read each material's actual `uniforms.uPixelRatio.value`, and resolve CSS optical size as `uPointSize × shaderPixelRatio ÷ rendererDpr`; the lane now requires shader DPR to match renderer DPR, and focused tests prove a stale DPR-1 shader uniform under a DPR-2 renderer resolves authored 58px to 29px. P2 `3998402580` then found that shader==renderer alone could still pass if all browser captures or renderer budgets regressed to DPR 1. Final Source `4aa4579ea6cc316aeb5521d3652a71421d965e04` hard-locks the fixed fixture's requested/actual device DPRs to `1/2/3` and expected/actual renderer DPRs to `1/2/2`, while still requiring each material shader ratio to match that renderer. The latest browser run recorded exactly requested/browser/scene DPR `1/2/3`, expected/actual renderer DPR `1/2/2`, shader DPR `1/2/2`, and zero resolved-size/opacity drift. Existing `particleEarthMaterial.test.ts` continues to lock the complementary shader expression and `onBeforeRender` update.

## Cross-feature assumption audit

- **Changed dimension:** rendering layers and occlusion under a variable DPR.
- **Browser/runtime budget checked:** the fixed QA requires the requested browser DPRs `1/2/3` to be real, then separately requires the existing high-quality render-budget sequence `1/2/2`; a constant-DPR fallback cannot masquerade as coverage.
- **Particle material family checked:** base particle surface, spatial-LOD refinement, archive signal, purple archive cluster, cyan archive cluster, shell, halo, and personal focus signal. All are measured through existing `uPointSize`/`uOpacity` plus actual post-render shader `uPixelRatio`; `src/scene/particleEarthMaterial.ts` remains untouched.
- **Shader/runtime boundary checked:** the browser lane reads `uPixelRatio` only after draw, while existing core tests assert both `ParticleEarthMaterial.onBeforeRender(renderer)` and the `gl_PointSize … * uPixelRatio` shader expression. This prevents the lane from passing by merely echoing renderer DPR independently of the shader.
- **Route/label sibling checked:** Route SVG core/glow and City/Place labels do not use `createParticleEarthMaterial`; they are recorded only as comparison references and are not folded into the particle DPR contract.
- **Semantic zoom / spatial LOD checked:** QA drives one fixed focus/camera to zoom 2.7 and waits for the real refinement build to report ready/present before measuring, so refinement absence cannot pass the lane.
- **Visited imprint / DPR contract checked:** measurement reads current material values after existing semantic/visited-imprint composition but changes neither visited-imprint behavior nor the renderer-DPR conversion introduced by #243.
- **Earth Dive checked:** #317 remains the camera/input handoff authority; ST-037 adds no camera state, zoom boundary, renderer or transition clock.
- **Story/Playback checked:** their attention ownership is documented as consumers of the existing motion/focus contracts only; this PR changes no Story, media, Playback or shared-element runtime code.
- **Design-system boundary checked:** `src/motion/tokens.ts`, `src/styles/tokens.css`, `docs/motion-language.md`, and `docs/design/meaningful-atlas-motion-plan.md` are unchanged. The new document cross-references them rather than creating a second source of motion/visual values.
