# PR #451 - Add a validated workflow_dispatch recovery entrypoint for missing exact-main push CI

- **Source head:** `4f6f9444a1798b4f66efde4d5334fe569e225948`
- **Scope:** startrips/.github/workflows/ci.yml today only triggers on push (branches: [main]) and pull_request; there is no workflow_dispatch trigger at all, and lib/github_evidence.py's exact_main_run() correctly fails closed with UNKNOWN when no push-event run exists for the exact main SHA (issue #450's live PR #431 case) rather than fabricating a pass. The real gap is the missing canonical recovery entrypoint: nothing in startrips lets a maintainer re-run the exact CI workflow against the current main SHA when GitHub never materializes the automatic push run, and nothing on-repo proves a manually dispatched run actually validated that exact SHA rather than an older or arbitrary one. This feature adds the workflow_dispatch trigger plus an in-workflow guard that only accepts a dispatch run whose checked-out SHA equals the live main HEAD, and records why the fallback was used. It intentionally excludes updating the loop-workspace's own github_evidence.py (outside startrips/) to consume that new run type, which remains follow-up work for the harness owner.
