# PR #558 - Apple explicit binding: a form_post-capable callback, SameSite=None bind cookie and per-provider PKCE opt-out

- **Source head:** `2fb8a637571eaaf6f4d410179567ee56aecc6241`
- **Scope:** On main (0a399cf, #349/ST-132) the shared bind round trip in server/routes/account-identities.ts is GET-only (`routes.get('/providers/:providerId/callback')` reading `context.req.query`), IDENTITY_BIND_COOKIE is `sameSite: 'Lax'`, and `/providers/:providerId/authorize` always sends `codeVerifier` for PKCE -- correct for Google's same-site GET return. ST-133/#350 (PR #485, not yet merged) adds Apple to `configuredSocialProviderIds`/`usableProviderIds` but the owner deliberately excluded `apple` from `bindableSocialProviderIds`/`linkableProviderIds` (Decision A on #350) because Apple's `response_mode=form_post` returns a cross-site POST that the GET route can't match, the Lax cookie isn't sent cross-site, and Apple's adapter never forwards `codeVerifier` while the shared exchange sends `code_verifier` whenever one is present. The real gap: add a form_post-capable callback path, relax IDENTITY_BIND_COOKIE to `SameSite=None; Secure` (owner-confirmed on #504, shared with the live Google flow so needs its own review), add a per-provider PKCE opt-out, then let `apple` into `bindableSocialProviderIds`/`linkableProviderIds`.
- **User-visible change:** Apple explicit binding: a form_post-capable callback, SameSite=None bind cookie and per-provider PKCE opt-out
