# PR #518 - Import a Ctrip trip plan into a reviewable Route draft

- **Source head:** `f65a44410c1f05d2773a5cb4778700515a42d610`
- **Scope:** Adds itinerary ingestion for #512. Two deployment adapters, both `disabled` by default and both truthful when unconfigured: `ITINERARY_SOURCE_FETCH_DRIVER` (`http` pins requests to checked addresses, `render` calls a real-browser renderer for pages a static client cannot read) and `ITINERARY_RECOGNITION_DRIVER` (`http-model`, server-side only, accepting versioned structured candidates and refusing anything else). `server/itinerary/*` holds the source fetch, recognition adapter and recognition-document contract; `server/routes/itinerary-import.ts` exposes the guarded import; `src/journey/itineraryImport.ts`, `itineraryText.ts` and `itineraryImageSegments.ts` read a day-structured itinerary, in Chinese or English, into a reviewable Route draft that preserves each entry's city/region context and role; `ItineraryImportPanel.tsx` is the Composer surface, behind its own disclosure and off the composer mount path. Pasted-text import works with neither adapter configured. Rebased past #350's Apple sign-in block in `server/config.ts`, keeping both field sets.
- **User-visible change:** A member can import a Ctrip trip plan from a share link, a screenshot or pasted text and review the resulting Route draft before it is applied, into a new Journey or an existing one. Day structure, per-entry city/region context and repeated places are preserved rather than normalised away; nothing is saved until the draft is confirmed.
