# PR #812 - Create and edit Journeys natively on iPhone

- **Source head:** `6b82720cce5ad3b1f37dff1155e016d7603c20c8`
- **Scope:** Native SwiftUI Journey composer for the Atlas owner (`mobile/ios/Sources/App/JourneyComposer.swift`, `JourneyComposerView.swift`). It covers title, dates, colour, story and Route Points, with `/api/locations` search and a MapKit centre picker. Requests go through `POST /api/journeys` and `PATCH /api/journeys/:id`, validated like the web composer. Edits echo `revision`, point ids, `occurredAt` and the light effect, and omit per-point extras so the server keeps them. On a 409 `JOURNEY_ROUTE_CHANGED` the owner reloads or merges and saves again, with no silent overwrite. Delete offers an undo via `/restore`. `AppRouter.apply(saved:)` and `remove(journeyId:)` bump the scene revision so the globe updates before the refresh. Entries are the empty Atlas, a top-bar plus and the card pencil. Backend unchanged.
- **User-visible change:** On iPhone, the Atlas owner can create a first Journey from an empty Atlas, add Journeys from the top bar, and edit or delete (with undo) a Journey from its card. Shares see no write entries.
- **Review fixes:** The first CI run hit the ios-native lane's 45-minute limit. A stale-edit XCUITest failed because the delete row was below the fold, and the failure made xcodebuild rerun the UI suite. That test and its fixture conflict hook were removed. The 409 path stays covered by unit tests against a synthetic server. Codex review: a merge where both sides changed the route no longer truncates to 64 points, which had silently dropped the owner's new points. The full list is kept, the existing route-limit validation blocks Save until the owner removes points, and the error row now sits at the top of the form and scrolls into view on every refused Save. A unit test covers 63 + 1 + 1 = 65 points.
- **Follow-up:** Photo-to-Route-Point drafts, share and journal import are later slices of #775. Reordering or demoting a Stop that other points belong to is refused by the server as a 409 at the same revision, and the app then asks the owner to recheck. Editing stay ownership natively is not covered. The ios-native lane ran in 18 to 40 minutes on this PR, against a 45-minute limit.
- **Validation:** Local: `git diff --check` and a compile-only `xcodebuild build-for-testing`. GitHub CI run 44555831040 on the Source head passed ios-native. That covers XCTest for request bodies, validation, merge, 409/create/delete/restore, guest refusal and scene revision, plus the create-flow XCUITest with screenshots in that run's `ios-native-1` artifact. No browser QA, as this PR changes iOS only.
