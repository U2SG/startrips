# PR #818 - Present the photo route review from the Story, not inside the tools sheet

- **Source head:** `0a894b1e084b7f9890907b9136121adf08da7413`
- **Scope:** `RoutePointBatchModel.pick` no longer sets `presented` while the photo picker is dismissing. It calls `requestReview()`, which bumps `reviewRequests` and marks a pending review. A new Story-level `RouteBatchPresenter` (mounted in the background of `NativeStoryDestination` for owners) hosts the review sheet. On a request it closes the tools sheet, and the tools sheet's `onDismiss` calls `presentRequestedReview()`; with no tools sheet up it presents directly. The sheet reports its own appear/disappear through `sheetVisibilityChanged`, and `RouteBatchEntry` shows 继续整理照片 from `showsReopen` (`stage != .idle && !visible`) instead of `presented`, so a dropped presentation can no longer hide it. Journal, operation-id, apply and undo logic unchanged; tools layout unchanged.
- **User-visible change:** On iPhone, picking two or more photos in 整理与导出 now closes the tools sheet and opens the 照片途径点 review. An open batch whose review is not on screen always shows 继续整理照片 in the tools sheet.
- **Review fixes:** None.
- **Follow-up:** No XCUITest, because the system photo picker cannot be driven from XCUITest; the picker-to-review hand-off still needs a manual simulator check. The tools sheet layout is being redesigned in a separate PR.
- **Validation:** Local: `git diff --check` and `xcodebuild build-for-testing` of the StartripsMedia scheme for the generic iOS Simulator (compile only); no XCTest or simulator run locally. GitHub CI run 44857798929 on the Source head passed ios-native (17m), including the new `RouteBatchTests` cases for the review hand-off and dropped-presentation recovery; core, browser-qa and keepsake-render were skipped by scope.
