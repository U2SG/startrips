# PR #434 - [Backend] Carry an optional recorded media-evidence document through upload finalization

- **Source head:** `670b444885824f761f64fbd4a606c6bb61a7f30d`
- **Scope:** `POST /api/uploads/start` accepts an optional recorded-evidence document validated by the existing `parseRecordedEvidenceWrite` normalizer before any storage call; one nullable `media_uploads.recorded_evidence` jsonb column (migration `0030_calm_medusa.sql` with its `meta/` snapshot) holds the normalized document until the media asset exists; `finalizeUpload` attaches it to a newly created asset inside the same transaction through `attachRecordedEvidenceToNewAsset`, writing nothing on a deduplicated completion and nothing new on a replay. Issue #428.
- **User-visible change:** None. The upload API gains an optional field no client sends yet; an upload without it behaves exactly as before.
- **Review fixes:** Pre-review hardening of the test set: the move case now also reclassifies the asset to an Everyday Fragment, the rollback case asserts the surviving database state rather than an asset nothing ever wrote to, and a console spy holds the refused start, the accepted start and finalization to writing no coordinate into any log channel.
- **Follow-up:** The EXIF/HEIC/video parser that would produce these documents remains #333. Supplying or correcting evidence for an already-existing asset stays with the owner-only `/api/media-evidence` route.
- **Validation:** The evidence insert is the second-to-last statement of the finalization transaction and no statement after it can fail, so the rollback case asserts the only observable outcome there is: nothing the aborted transaction wrote survives it. `tsc -p tsconfig.server.json --noEmit`, `git diff --check` and `node scripts/pr-history.mjs validate-all` locally; the full `pnpm typecheck` cannot run on a case-insensitive filesystem because `src/brand/StartripsRecoverySurface.tsx` and `src/brand/startripsRecoverySurface.ts` differ only in case, which is pre-existing on `main` and green in CI. Behaviour is delegated to the CI `core` lane, which runs the new `server/tests/upload-evidence.integration.test.ts` and the extended `server/routes/uploads-validation.test.ts` against PostgreSQL 17.
