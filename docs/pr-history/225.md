# PR #225 - Add the owner share surface for single and multiple Journeys

- **Source head:** `a1dd368221b1a0ee3e8b6a8f1d7f87d5c271f766`
- **Scope:** Phase E of #200, client-side only over the phase A share routes already on `main`; no server route, schema or DTO changed. New pure module `src/journey/shareLinks.ts` holds the share rules (preset resolution, the `/share#<token>` fragment link form, the exact-expiry formatting, the tokenless list row model, active-row derivation and the next-expiry refresh delay). New `src/journey/JourneyShareDialog.tsx` renders one dialog for both entry paths, locked to one Journey or picking a set. `createShare` / `listShares` / `revokeShare` were added to `journeyApi` and reach the UI only through `AtlasMutations`. Entry points: the desktop header, the compact mobile header, the mobile journey sheet, and the story manage row via a new `onShare` prop gated on `canShareAtlas`. New `browser-qa / owner-share` lane and CI matrix entry.
- **User-visible change:** An owner can share one Journey or a chosen set of Journeys as an expiring read-only link, pick a 1/7/30-day or custom expiry, see the exact expiration the server assigned, copy the link or hand it to the native share sheet, and see and revoke the links that are still live. The owner is told that anyone holding the link can view until expiry but cannot edit, and that the link is shown only once.
- **Review fixes:** Codex raised two P2 findings, both valid and both fixed. (1) The active-link list never re-derived, so a panel left open past a grant's expiry kept listing a link that had stopped working; `nextShareExpiryDelay` now schedules the re-derivation for the nearest expiry, capped below the 32-bit `setTimeout` ceiling, with the clock read through a ref so an inline `now` arrow cannot re-arm a state-setting timer every render. (2) The QA lane's stubbed expiry was a fixed 2027 date that would have made the lane fail after it passed; it is now derived from the lane's own clock. Two further fixes came from CI rather than review: `atlasView.test.ts` enumerates the mutation client's keys and needed the three new names, and the lane's click helpers had to match the accessible name, because the share entries are labelled buttons on desktop and icon-only buttons in the compact mobile header.
- **Follow-up:** The expiry-refresh timer is covered as a pure rule (`nextShareExpiryDelay`) but the effect that consumes it is not exercised by any lane; a browser check that holds a share past its expiry would close that gap. `shareStatusLabel` carries copy for `expired` and `atlas-unavailable` that the active-only list never renders today, kept so a future all-states view has one vocabulary.
- **Validation:** Locally only `./init.sh smoke` — `pnpm typecheck`, `git diff --check`, `node --check` on both QA scripts, and `pr-history validate-all`. No local test run, dev server, browser, database or Docker. CI is authoritative: `core` (PostgreSQL 17, migrations, typecheck, full suite, build), `ledger`, and all seven `browser-qa` lanes including the new `owner-share` lane, which drives the real dialog at desktop, portrait-phone and phone-landscape and asserts both entry paths, the server-assigned expiry, the fragment link form, the tokenless list, revoke removing a row, the no-gradient/shadow/rounding/blur/emoji audit and the 44px hit targets. One `mobile-contract` failure was diagnosed as a lane flake and re-run: the compact-mobile marker disagreed at 1024x768 after a resize, in a lane whose script and `mobileLayout.ts` both diff zero lines against `origin/main`, and the identical product code passed that lane on the preceding run.
