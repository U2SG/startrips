# PR #592 - Reject undefined token references and name every z-index step

- **Source head:** `6b0f9f6e7cf8c144dee5b4f230a092979c5e8b3c`
- **Scope:** The CI-decidable slice of audit batch 3 in #586. `scripts/css-token-guard.mjs` collects every custom-property definition and reference across the CSS the build actually includes, plus the properties modules supply at runtime, and fails on a reference that resolves to nothing; it ships with a 15-case `node --test` self-test and runs in the `core` job ahead of the existing checks. Alongside it, `tokens.css` gains a z-index scale and every literal `z-index` in the client is replaced by a named step that keeps its original number.
- **User-visible change:** None. No declaration resolves to a different value than before, so no rendered output changes. The difference is that the next `var(--typo)` fails the build instead of silently falling back at computed-value time, and that stacking order is readable as names.
- **Review fixes:** The work was produced by a subagent that failed after pushing but before reporting, so it was reviewed rather than trusted. `origin/main` had meanwhile merged #587, whose baseline predated that merge; the branch was rebased onto the merged main and its `--atlas-accent` commit dropped, because #587 had already fixed that exact defect. The z-index migration was re-verified independently rather than by its own claim: 127 `z-index` declarations were compared per file and in order against the pre-migration baseline after resolving each `var(--z-*)` back to its number, with zero drift, zero duplicate token values and a strictly ascending scale; the two comparisons the checker could not resolve, `calc(3 - var(--stack-depth, 0))` and `var(--story-live-z, 6)`, were confirmed equivalent by hand. The guard was negative-tested by injecting an undefined `var()` and confirming it exits non-zero and names the file, line, property and selector. The way it treats runtime-supplied properties was checked specifically, because a hand-maintained allowlist would have quietly swallowed real bugs; it derives them from actual `setProperty` and inline-style source patterns instead.
- **Follow-up:** The rest of batch 3 is deliberately not here. Migrating 948 bare colour literals and normalising the 11 breakpoints both change rendered output and need a screenshot baseline against `design-qa.md` before anyone touches them. A second observation worth acting on separately: the autoplay harness treats any console error as an invalid run, so #584 and this branch each discovered the missing recorded-track fixture stub independently, which suggests that fixture list needs a cheaper way to stay honest.
- **Validation:** Acceptance is GitHub Actions only. Source CI run 36759185382 is green on `core` (which now includes both new guard steps, the generated auth schema check, migrations, typecheck, the full `pnpm test` and the build) and on all ten browser-qa lanes; run 36759185385 is green on both `production autoplay` jobs after one re-run. This final commit changes only this ledger, and the ledger fast path proves the Source CI it reuses.
