# PR #592 - Reject undefined token references and name every z-index step

- **Source head:** `90041564a89347399dae7e96cc791d5b21ade6e9`
- **Scope:** The CI-decidable slice of audit batch 3 in #586. `scripts/css-token-guard.mjs` collects every custom-property definition and reference across the CSS the build actually includes, plus the properties modules supply at runtime, and fails on a reference that resolves to nothing; it ships with a `node --test` self-test and runs in the `core` job ahead of the existing checks. Alongside it, `tokens.css` gains a z-index scale and every literal `z-index` in the client is replaced by a named step that keeps its original number. A first pass was produced by a subagent that failed after pushing; the branch was rebased onto the merged #587 baseline and its `--atlas-accent` commit dropped, because #587 had already fixed that exact defect.
- **User-visible change:** None. No declaration resolves to a different value than before, so no rendered output changes. The difference is that a `var(--typo)` fails the build instead of silently falling back at computed-value time, and that stacking order is readable as names.
- **Review fixes:** Review found two ways the guard called a reference resolved when the browser would still discard it. Both are false negatives, the dangerous direction for a guard: they manufacture the confidence this rule exists to remove. A selector was recorded as a definition, because any `--name:` at brace depth 1 was accepted and `.auth-card--login-v3::after` inside a media block matches that shape; definitions now have to sit in a real declaration position. A test module was recorded as supplying a runtime definition, because `LivingAtlasApp.test.ts` asserts that nothing calls `style.setProperty("--journey-route-scale")` and the runtime patterns read that quoted name as a definition, so the guard inherited the very token whose absence the test proves. Fixing the first exposed a latent sanitiser bug: it blanked a comment's body but left the `/*` opener, so a property written directly after a comment stopped being recognised. The z-index migration was re-verified independently rather than by its own claim: 127 declarations compared per file and in order against the pre-migration baseline after resolving each token back to its number, with zero drift, zero duplicate token values and a strictly ascending scale. The guard was negative-tested by injecting an undefined `var()` and confirming it exits non-zero and names the file, line, property and selector.
- **Follow-up:** The rest of batch 3 is deliberately not here. Migrating 948 bare colour literals and normalising the 11 breakpoints both change rendered output and need a screenshot baseline against `design-qa.md` before anyone touches them. A second observation worth acting on separately: the autoplay harness treats any console error as an invalid run, so #584 and this branch each discovered the missing recorded-track fixture stub independently, which suggests that fixture list needs a cheaper way to stay honest.
- **Validation:** Acceptance is GitHub Actions only. Source CI run 36816691703 is green on `core` — which now includes both guard steps, the generated auth schema check, migrations, typecheck, the full `pnpm test` and the build — and on all ten browser-qa lanes; run 36816691424 is green on both `production autoplay` jobs. Re-injecting `var(--login-v3)`, `var(--journey-route-scale)` and one plainly absent name now fails with all three reported, where the first two would previously have passed. This final commit changes only this ledger, and the ledger fast path proves the Source CI it reuses.
