# PR #817 - Import journals with AI natively on iPhone

- **Source head:** `1587a1546d1f2b1d78fd6e9fb2fe7993f6ceb510`
- **Scope:** Adds a fully native, owner-only journal AI import (自动导入) to the iPhone Story tools: paste or pick a .txt/.md log, start `POST /api/intents/journal-import/jobs` with a request id persisted per Journey before the POST, follow n/m segment progress by polling `GET /jobs/:jobId` (not SSE, because `AtlasSession.api` buffers whole responses) with stop, review proposed chapters one by one (keep/skip, edit lines, settle 待确认 lines and questions), save with `PUT /api/journeys/:id/journal` on the plan's base revision, and undo the latest import via `/journal/imports/:batchId/undo`. A 409 on save reloads and never retries; undo's 409 asks for `confirmEdited` when imported chapters were edited. The model's status, degraded 待确认 lines (#786) and returned prose (#807) are kept as delivered. Guests never see the entry. Server and web unchanged.
- **User-visible change:** The owner can import a written travel log into a Journey's daily journal on iPhone, review it and undo it.
- **Review fixes:** Codex P2: restoring an unanswered submission could leave compose mode active and let a second start replace the persisted request id; `restore()` now leaves compose before re-posting (`1587a154`, unit test). CI fix: hyphens are no longer percent-escaped in request paths (`07362fac`).
- **Follow-up:** Last slice (R4) of the iOS recording loop for #775. No XCUITest: the synthetic Story fixture has no journal backend; logic is covered by `JournalImportTests`.
- **Validation:** Local `swiftc -typecheck` against the iOS Simulator SDK and `git diff --check`. GitHub CI ios-native on the Source head ran the new `JournalImportTests` (snapshot parsing, error codes, job lifecycle, relaunch, lost submission, stop, 409 on save, undo) and passed; CI is authoritative.
