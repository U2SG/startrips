# PR #192 - Shard pull request ledger files

- **Source head:** `f86c25f3df23786ec44280cd4fbe1f5f1201bbb2`
- **Scope:** Replaces the single shared PR ledger write target with one independent `docs/pr-history/<PR_NUMBER>.md` file per PR, adds parser/validator/index tooling, and makes a lightweight ledger CI lane part of the final `verify` gate.
- **User-visible change:** None directly. Parallel development no longer forces unrelated PRs to rebase just because another PR appended to the same ledger file.
- **Review fixes:** The design deliberately leaves `docs/pr-history.md` untouched as a legacy archive and does not commit a generated aggregate index, avoiding both another shared write lock and post-merge bot-commit/CI churn. PR validation now enforces three ownership boundaries: Source head must be an ancestor of final head; only this PR's own numeric ledger may change after Source head; and across the whole PR diff the frozen legacy archive and other PRs' numeric ledger files are forbidden. The whole-PR ownership check uses the PR merge-base so later main advancement does not create false positives. The aggregate-index contract was also corrected to match the implementation: CI publishes it to the GitHub Actions Job Summary rather than promising a downloadable artifact. Numeric ledger paths are now required to be regular non-symlink files, closing the remaining indirection path around immutable-history ownership checks.
- **Follow-up:** No legacy open PR remains to migrate. Future PRs must write only `docs/pr-history/<PR_NUMBER>.md`; the legacy archive remains frozen.
- **Validation:** Rebased onto `main@42ce719`. `node --test scripts/pr-history.node-test.mjs` is green locally with 7 passing Git/format tests plus the symlink-specific test skipped on Windows; GitHub Linux CI executes the symlink case. Coverage includes own-ledger success, frozen legacy rejection, foreign-ledger rejection, and non-symlink enforcement; `validate-all`, script syntax, and `git diff --check` green on the code head. This final ledger commit is additionally validated with `validate-pr`; GitHub CI is authoritative for workflow integration.
