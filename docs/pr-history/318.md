# PR #318 - Reject year-zero persisted calendar dates

- **Source head:** `73a8fff8045f50720c4253344ddf1586e219dcd4`
- **Scope:** Close ST-052 / issue #231's validation-only residual by introducing `src/journey/calendarDate.ts` as the single persisted `YYYY-MM-DD` contract shared by `server/routes/home-bases.ts`, `server/routes/journeys.ts`, `src/journey/journeyModel.ts`, and `src/journey/everydayFragment.ts`. The validator rejects `0000-*`, which JavaScript can round-trip but PostgreSQL `date` cannot persist, while deliberately retaining `0001-01-01` and `9999-12-31`. No schema/migration, Home Base interval rule, authorization, inference, sharing, Playback, or unrelated UI behavior changes.
- **User-visible change:** A year-zero date is refused at the normal validation boundary instead of surviving JavaScript validation and failing generically at the database boundary. `POST /api/home-bases` returns `400 INVALID_HOME_BASE` for a year-zero start; `PATCH /api/home-bases/:periodId` does the same for year-zero `startedOn` and `endedOn`; `POST /api/journeys` returns `400 INVALID_JOURNEY` for a year-zero `startedOn`.
