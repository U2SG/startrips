# PR #672 - Classify the playback return Next by its own intent commit

- **Source head:** `67ebb39b439da18477af976d73feb6593cde96e8`
- **Scope:** Issue #433, the outro gap only. In `scripts/qa-post-login-controls.mjs` the final-acceptance playback-return step used to click Next from the final Route Point stop and then wait 2 s for `media` + `fa-image-2`. Now, in the same task as the click, it installs a MutationObserver commit log on `.journey-playback`. It then waits for Next's own `data-playback-intent` revision (`advance` never bumps it) and classifies the landing: it continues on `media` + `fa-image-2` and otherwise fails with an explicit "skipped fa-image-2" or "advanced past fa-image-2 after Next landed on it" diagnosis plus the commit log. The witness stays playing. The script adds no timeout or retry and does not weaken any assertion. Product code is unchanged.
- **User-visible change:** None.
- **Review fixes:** None.
- **Follow-up:** The failure mode is an autoplay `advance` that was queued before the click but not yet rendered. React rebases Next on top of it (stop -> media -> outro), and no DOM read can see that pending update. If it recurs, the step now fails with a named cause instead of an ambiguous timeout. Making it fully deterministic would mean pausing the witness before Next, which reverses the playing-witness design from #285/#479 and is an owner decision. The rest of #433's acceptance stays open.
