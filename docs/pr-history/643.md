# PR #643 - Slide the mobile Story sheet on translate instead of animating its height

- **Source head:** `febd2a0c5b6c5f6d63665c9a21bd351d006b8863`
- **Scope:** The mobile Story sheet no longer transitions `height`/`max-height` (a per-frame relayout of a scrolling, media-heavy container). It is a CSS FLIP on the individual `translate` property: the real height commits once and the sheet slides from `calc(100% - extent - 1px)` of its own box. That offset is 0 at rest and the inverse offset while the box is taller. Collapse holds the tall box through a delayed zero-duration height transition. The collapsed extent is one custom property shared with the landscape 92svh block. `onTransitionEnd` also accepts `translate`, so the globe cover hold (#247) still clears after expanding. Reduced motion now snaps the portaled sheet (0.01ms, no delay). A CSS/source contract test in `JourneyStory.test.ts` locks this in.
- **User-visible change:** The Story sheet's expand/collapse looks the same and keeps its resting layouts, but runs on the compositor and is smoother on low-end phones. With reduced motion it snaps instead of animating.
- **Review fixes:** None.
- **Follow-up:** A real-device visual review of the slide is still pending. Known transition-only differences: on expand, a collapsed sheet scrolled near its end can have `scrollTop` clamped at frame 0. The collapsed rest carries a translate of about 0 (at most 1/64 px of layout rounding), which makes the sheet a stacking context.
