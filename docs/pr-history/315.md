# PR #315 - Hand Route Points into Story media

- **Source head:** `068896e988e247834a56bb6ae2940bbe2609e03d`
- **Scope:** Add one presentation-only observation aperture beside the currently rendered Route Point marker and hand that exact same media asset into the existing Journey Story media shell. Route Point DOM markers publish only Journey/Route Point identity; the handoff re-measures their live viewport geometry on each intent instead of storing x/y in React state. Image entry uses the same representative asset; video entry may use the same asset preview when available and never creates a second live video transport. Returning from Story uses the latest same-Journey `StoryLogicalObservation.routePointId`, verifies that Route Point still exists in the current Journey model, then re-measures the live marker. The shared-element primitive owns temporary-geometry cleanup and observes `data-media-page-ready` so same-asset persistent-page readiness can complete the handoff.
- **User-visible change:** Opening a Route Point's Story reads as that place's memory expanding out of the geographic context rather than an unrelated panel appearing. If the projected point moves while Story is open, exit returns to the new live position. If the user browses from Place A to media owned by Place B, B owns the return; rapid A -> B -> C leaves C as the only return owner. Fullscreen entry/exit preserves the same observation. Compact mobile uses a short bounded aperture; Reduced Motion keeps the exact same Story/media/Route Point identity without spatial travel. Text-only Route Points keep their truthful non-media context behavior.
- **Review fixes:** Dynamic QA first exposed an existing ownership conflict: Story scope initialization called `exitFullscreen()` even when fullscreen was already false, starting a second shared-element morph and cancelling the external Atlas -> Story handoff. Initialization now resets fullscreen state/timers directly and reserves fullscreen morphs for real user transitions. QA also showed Context can have a valid same-asset URL before image decode, so the observation aperture requires only that same-asset URL while the Story destination continues to obey ready/decode. A PR P2 then found cross-point return was incorrectly gated by the stale opening Route Point context selection; return authority now comes from the latest Story logical observation plus active-Journey/current-model/live-marker guards, and successful return refreshes Route Point context to that observed place. Focused browser QA covers A -> B + fullscreen/back and rapid A -> B -> C supersession.
- **Follow-up:** This does not change carousel mechanics, Story <-> fullscreen shared media behavior, Playback selection, Earth Dive, camera ownership, renderer architecture, coastline fidelity, or brand/error-state motion. Earth Dive seam refinement remains the next spatial-continuity slice.
