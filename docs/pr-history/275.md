# PR #275 - Make deploy-main independent of worktree state

- **Source head:** `fbb0937db0055533506abe7b9f389c3fb73d4ce5`
- **Scope:** Updates `scripts/deploy-main.py` so deployment no longer switches to the local `main` branch or pulls into the current worktree. The script fetches remote `main` through an explicit refspec into `refs/startrips/deploy-main`, resolves that exact commit, gates on CI for that SHA, and archives/deploys the immutable commit directly.
- **User-visible change:** Operators can run the existing deploy command from a dirty feature worktree, including one with an in-progress cherry-pick or rebase, without the deployment script modifying, stashing, resetting, or switching that worktree.
- **Review fixes:** Addressed the P2 review that `git fetch origin main` may update only `FETCH_HEAD` under restricted/custom fetch mappings. The fetch now uses `+refs/heads/main:refs/startrips/deploy-main`, and the deployment SHA is resolved from that explicit destination ref rather than assuming `refs/remotes/origin/main` was updated.
- **Follow-up:** `refs/startrips/deploy-main` is intentionally a deployment-owned local ref and may be overwritten on every deploy fetch. It is not a user branch or worktree and must not be used as a development base.
- **Validation:** `python -m py_compile scripts/deploy-main.py`; `git diff --check`; direct `git fetch origin +refs/heads/main:refs/startrips/deploy-main` from the existing dirty/cherry-pick repository followed by SHA equality between `refs/startrips/deploy-main` and fetched `origin/main`; GitHub CI/review to validate the final rebased head and ledger.
