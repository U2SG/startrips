# PR #202 - Preserve video-only route points in Quick Recap

- **Source head:** `000c25e86badd1ad38b277f766eb0e8e713d34c7`
- **Scope:** Replaces Quick Recap's image-only runtime candidate projection with a visual-media projection: `runtimeVisualCandidates()` keeps every non-soundtrack asset (reusing `journeyModel`'s `isVisualMediaAsset`/`isSoundtrackAsset` classification), video digests are emitted with `mediaType: "video"` plus an explicit analysis-pending `intrinsic.durationMs` (`QUICK_RECAP_PENDING_VIDEO_DURATION_MS`, reusing Full Playback's `PLAYBACK_PACING.videoMs`), and the fallback reason `no-photos` becomes `no-visual-media`. `autoEditPlan.ts` is untouched.
- **User-visible change:** A route point whose only media is a video keeps its Quick Recap chapter instead of vanishing from the recap route, and a video-only Journey now plays a Quick Recap instead of silently falling back to Full Playback. The fallback notice now reads 照片或视频 and only appears when a Journey really has no visual media.
- **Review fixes:** The duration fallback is load-bearing, not cosmetic: `autoEditPlan`'s video eligibility rule rejects an absent, non-finite, or non-positive duration, so an empty `intrinsic` would have deleted the route point's only chapter — the very regression this fixes. No `mediaType` term enters selection scoring, so photo-first quality is unchanged; photo roles remain image-only and a chapter's hero is still a photograph whenever the route point owns one.
- **Follow-up:** Phase 2 of #195 remains: measured video duration, bounded highlight segments, and a trim-aware playback contract. Phase 1 deliberately keeps clips whole — the planner's `trim.inMs` is always 0 and the director holds a video step until the media element's real `ended` event, so `trim.outMs` is a planning budget only and no trim is wired into `<video>`. Family search (#198) found no other image-only candidate projection: `journeyPlaybackPlan.ts` and `journeyKeepsake.ts` already classify video, and `JourneyPlaybackOverlay.tsx`'s `image/` checks are decode gating (a video-only chapter correctly releases the hold), not topology.
