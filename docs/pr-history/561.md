# PR #561 - Treat uncomputed PR mergeability as missing evidence in the control plane

- **Source head:** `d244a339498ea34812c24103ddcb23217df038d7`
- **Scope:** `feature_state.reconcile` re-reads a handed-off PR (`ready_for_eval` / `ready_to_merge`) whose GitHub `mergeable` is still null with a 2/4/8 s backoff; a settled `dirty` answer takes the existing conflict demotion to `needs_work`, and a still-null answer prints `WAIT_MERGEABILITY` and leaves the handoff state unchanged. `action_plan.derive` returns `WAIT_EVIDENCE` for null mergeability. The #527 reviewed hot-predecessor test now pins its historical `action_plan.py` pair instead of current planner Source.
- **User-visible change:** None in the product. In the loop, a handed-off PR made dirty by a sibling merge is no longer reported review-clear and left waiting for sign-off while GitHub is still computing mergeability (observed on #557 after #556 merged). A `ready_for_eval` row with null mergeability also skips that round's review-blocker demotion and is re-read next reconcile.
- **Review fixes:** The first Source failed only `test_deployed_action_plan_predecessor_is_frozen_to_current_package_source`, which by design pinned current planner Source to the #527 pair. The installed planner equals the committed base, so activation classifies it `exact-base`; the test now keeps the historical pair exact without tracking Source. This relaxes the #527 "fail on later Source drift" guard for `action_plan.py` and needs Maintainer acceptance.
- **Follow-up:** Runtime activation through `delivery_runtime` at an idle boundary after merge; a read-only comparison showed all 17 installed consumers byte-equal to main `tools/control-plane/`. Independent review of this Source is pending.
