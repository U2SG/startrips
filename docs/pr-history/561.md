# PR #561 - Treat uncomputed PR mergeability as missing evidence in the control plane

- **Source head:** `7072063ecb6b1b83e5372b47f62901870151f4dc`
- **Scope:** `feature_state.reconcile` re-reads a handed-off PR (`ready_for_eval` / `ready_to_merge`) whose GitHub `mergeable` is still null with a 2/4/8 s backoff; a settled `dirty` answer takes the existing conflict demotion to `needs_work`, a still-null answer prints `WAIT_MERGEABILITY`, and a reread that observes `merged` or `closed` is immediately re-dispatched through that lifecycle instead of continuing inside the stale open-PR branch. `action_plan.derive` returns `WAIT_EVIDENCE` for null mergeability. The #527 reviewed hot-predecessor test pins its historical `action_plan.py` pair instead of current planner Source.
- **User-visible change:** None in the product. In the loop, a handed-off PR made dirty by a sibling merge is no longer reported review-clear and left waiting for sign-off while GitHub is still computing mergeability (observed on #557 after #556 merged). A `ready_for_eval` row with null mergeability also skips that round's review-blocker demotion and is re-read next reconcile; lifecycle changes discovered by that reread are handled in the same reconcile round.
- **Review fixes:** The first Source failed only `test_deployed_action_plan_predecessor_is_frozen_to_current_package_source`, which by design pinned current planner Source to the #527 pair. The installed planner equals the committed base, so activation classifies it `exact-base`; the test now keeps the historical pair exact without tracking Source. Independent Hourly Review then found that a null-mergeability reread could observe `merged` or `closed` while `reconcile()` remained in the already-selected open branch. Source `7072063e` moves the reread before lifecycle dispatch and adds regressions for both null-to-merged and null-to-closed transitions.
- **Follow-up:** Runtime activation through `delivery_runtime` at an idle boundary after merge; a read-only comparison showed all 17 installed consumers byte-equal to main `tools/control-plane/` before this change.
- **Validation:** Source CI run `36240913571` passed `core`, `keepsake-render` and every `browser-qa` shard at Source `7072063e`; control-plane run `36240913568` passed Ubuntu and Windows. The pre-final-head `ledger`/`verify` failures were expected because this ledger still named the earlier Source. Local validation remains limited to lightweight static checks.
