# PR #203 - Keep bearer tokens out of request logs

- **Source head:** `a3e2dbae224c88b782842ca16c52dbfb552797dd`
- **Scope:** Extracted the `server/app.ts` request-log middleware into `server/request-log.ts` and made it log the matched Hono route pattern instead of `context.req.path`, in both the success and the `failed` branch, with a `<unmatched>` placeholder for requests no handler served. Added `server/request-log.test.ts`. Added Caddy access-log `filter` redaction for `request>uri` and `request>headers>Referer`, plus an operator note in `deploy/README.md`.
- **User-visible change:** None. Operators see route patterns rather than raw paths in the API log, and `REDACTED` in place of reset/verify/share tokens in the Caddy access log.
- **Review fixes:** Two findings from checking the deployed behaviour rather than the issue text. Caddy keys log field filters by field name, so the issue's recommended `request>uri query {...}` plus `request>uri regexp ...` pair silently drops the `query` filter; `caddy adapt` confirmed it, and the config uses one `regexp` per field instead. Separately, Caddy logs `Referer` in full, so under the configured `Referrer-Policy` every same-origin request from `/reset-password?token=` leaked the token through the header; `request>headers>Referer` is now redacted too.
- **Follow-up:** #200 Phase A should carry its share token as `Authorization: Bearer`, which Caddy redacts by default, rather than a custom `X-Share-Token` header, which is logged in full. The issue's remaining acceptance criteria (the #200 URL redesign and the #198 CFAA invariant) live in issue text and were not editable here. `server/routes/mapstyle.ts` logs an allowlist-validated public tile path and `server/email/email-sender.ts` prints the whole mail body in the non-production no-SMTP dev sink; both were left unchanged.
- **Validation:** Passed locally: `pnpm typecheck`, `pnpm vitest run server/request-log.test.ts` (7), `pnpm vitest run src/` (474), `pnpm vitest run server/ --exclude "server/tests/**"` (130), `pnpm build`, `git diff --check`. The new test was mutation-checked: restoring `context.req.path` fails all 7 cases. The Caddyfile was validated and exercised against a locally built `caddy v2.11.4` matching the pinned image tag, confirming each token URL shape is redacted; CI does not validate the Caddyfile, and the deploy image itself was not run. `pnpm test` in full, `db:migrate`, and the generated-auth-schema check remain authoritative in CI, which provisions PostgreSQL 17.
