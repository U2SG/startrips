# PR #644 - Keep Earth Dive blend frames off React state and forced layout

- **Source head:** `d959fd4eb08e06fb4cdf29f274e27adacb909460`
- **Scope:** During Earth Dive prewarm/blend the particle anchor frame no longer reaches React. `LivingAtlasGlobe` drops the `particleFrame` state and writes `detailHandoffFrameRef` at the four former `setParticleFrame` sites. `DetailedEarthMap` reads that ref through a new `particleFrameSource` prop instead of mirroring a per-frame prop. `syncDetailSpatialReveal` uses a cached layer rect: a `ResizeObserver` refreshes it, and window resize/scroll and Dive stage edges invalidate it. That one read happens before the frame's writes. Dataset attributes and `--earth-dive-reveal-*` properties are written only when their serialized value changed (`formatEarthDiveRevealStyle` / `writeChangedEarthDiveRevealStyle` in `src/scene/earthDiveReveal.ts`). The Dive tick reads computed opacity only when the spatial reveal is not `on`. Dive timing, thresholds, the day/night ramp and the mask are unchanged.
- **User-visible change:** None.
- **Review fixes:** None.
- **Follow-up:** `DetailedEarthMap` calibration and `publishAnchorFrame` still call `host.getBoundingClientRect()` on each calibrated frame. The `handoffSnapshot` state still updates at 0.01 local-progress steps while only map mount reads it.
- **Validation:** Locally: `pnpm install --frozen-lockfile`, `pnpm typecheck`, `git diff --check` and the ledger validators. Authoritative: GitHub CI (vitest, including the new `earthDiveReveal` helper tests and the `LivingAtlasGlobe` source-scan test, the build, and the globe-context and memory browser lanes).
