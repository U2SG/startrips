# PR #647 - Give Atlas controls one family

- **Source head:** `48ce55a56980b1ed6ad204aaa32e2e2d6ec4a76f`
- **Scope:** Control tokens on `:root` in `src/styles/tokens.css` (`--control-*`, `--radius-surface/sheet/tile/field`, `--elev-1/2`; `--control-danger` is `#c28e78`, the most used of the eight old destructive tints, and `--control-primary-ink` is the acid CTA's `#091006`). A new `src/styles/controls.css`, imported right after the tokens, holds the primitives `.st-btn` (primary, quiet, danger, block), `.st-icon-btn`, `.st-chip` (radio dot or check mark), `.st-segmented`, `.st-select`, `.st-check` and `.st-field`, plus `:root { color-scheme: dark }` (also as an `index.html` meta tag) and a zero-specificity `IconActionButton` circle baseline scoped to the Atlas shell and the Composer; Journey Story is portaled to `<body>` and keeps its icon actions. The shell's `.living-atlas button` defaults skip the primitives through `:where(:not(...))`, so every other control keeps its specificity. The Journey Composer, route candidate editor, itinerary import and desktop header nav consume the tokens from their own selectors, and a closing section in `living-atlas.css` gives them one segmented look, radio-dot chips, one 2px focus ring, pointer-down press feedback and a tint for rows and tiles. `.st-select` and `.st-check` replace the three native selects and checkboxes; `.st-field` styles the standalone import dialog's text fields while the Composer keeps its underline inputs. The Composer's 更多 becomes an icon-only `IconActionButton`, the import and GPX file inputs sit transparent over a pill, and the route editor marks one `is-primary` at a time. On the compact layout the route editor spans the safe-area width between header and dock: `place()` reads the published `data-mobile-v2` marker and leaves left and width to CSS. The header nav takes its content width with `nowrap` items (padding 16px to 14px), and the brand text in `starlight-experience.css` now shows from 1301px instead of 1201px. `qa-post-login-controls.mjs` gains 1280 and 1440 desktop checks for nav/brand overlap and single-line nav labels.
- **User-visible change:** Buttons in the Composer, route editor and itinerary import read as one family: secondary dark-glass pills, round icon buttons, one acid primary per surface, cyan selection with radio dots, a shared danger tint and no browser-default buttons, selects, checkboxes or file inputs. Floating panels have rounded glass surfaces. The desktop header nav labels no longer wrap, and the brand text beside the wordmark appears from 1301px wide.
- **Review fixes:** CI caught the GPX file input at 42px: a transparent input sized by percentages filled only the pill's padding box, so it now steps out over the 1px border to cover the full 44px border box.

The atlas-shell viewport list in `qa-post-login-controls.mjs` may conflict with the mobile header PR, and this branch needs a rebase onto the fixed main.
