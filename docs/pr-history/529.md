# PR #529 - Read the replay budget before the carrier binds

- **Source head:** `2b779f475d8405b4b14c487eccc676a04458cc93`
- **Scope:** Move the replay-budget verdict ahead of the carrier binding in `run-loop.sh`, inside the unscoped branch only, so an owner that cannot advance yields the lane instead of re-locking it; plus a regression that drives the real loop across four fresh processes with fake providers.
- **User-visible change:** None directly; it stops one exhausted owner from starving every other eligible owner on the same lane, so work that is ready to proceed is no longer held behind it.
- **Review fixes:** None yet - this Source has had no independent review round.
- **Follow-up:** The fix reaches a running loop only through a maintenance install; until then a workspace must still name the stalled owner in `FEATURE_SKIP` by hand. The execution guard's `unknown-cwd` classification of unrelated local shells, which made preflight fail repeatedly on this machine, is a separate defect and is not addressed here.
- **Validation:** Exact Source CI on `2b779f4` passed control-plane Ubuntu and Windows (both shards), core, keepsake-render and all nine browser-qa lanes; `ledger`/`verify` are the expected pre-ledger failures. The regression was confirmed to bite: with the fix reverted locally the fourth invocation times out at the harness bound instead of yielding. The local full-suite run reported one unrelated error where the guard classified the authoring session's own shells as competing executions; it passes alone and did not reproduce on CI.
