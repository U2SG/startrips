# PR #728 - Assign selected Story photos to a Route Point from one sentence

- **Source head:** `0fdab6eff3fb397c374868f96f75ad4fa83f81e4`
- **Scope:** `POST /api/intents/assign-media` (`update`): the Journey must belong to the session Atlas (404 before any model call); the server loads its Route Point labels and the model sees only the sentence, positional ids `p1…pN` with labels and the fixed `journey` (loose pages) — never asset ids, Route Point ids, coordinates or the selection size; the answer is narrowed to the ids sent, alternatives capped at 3. The router offers `assign-photos` only with a valid active Journey and selection. JourneyStory registers a bridge in select mode that calls its own move and undo; the card shows 「把 N 张移到 · <label>」 with alternatives, then 「已移动 · 撤销」. A `story` surface renders the bar into `<body>` so ⌘K works above the portaled Story.
- **User-visible change:** On desktop, with an intent provider, selected Story photos can be moved to a Route Point by describing where they were taken, with undo.
- **Review fixes:** None requested (Codex review clean).
- **Follow-up:** ⌘K over Story's fullscreen viewer opens the bar with nothing to offer; the mobile dock (PR-C) hosts the bar on phones.
- **Validation:** Local `pnpm typecheck`, `git diff --check`, `node --check`. CI run 39916305011 on the Source head: `core`, `keepsake-render` and all eight browser-qa shards passed, including the new select → ⌘K → confirm → 撤销 scenario in `qa-media-reclassification`.
