# PR #813 - Answer malformed upload ids with 404 instead of a database error

- **Source head:** `2bc4d48897e0bffef01e524d42a6db209512e47d`
- **Scope:** Moves the upload id UUID check from the #811 status route into the shared Atlas-scoped `findUpload` lookup, so `POST /api/uploads/:id/parts/:n`, `POST /api/uploads/:id/complete` and `DELETE /api/uploads/:id` answer a malformed id with `404 UPLOAD_NOT_FOUND` like an unknown or foreign id, instead of a 500 from the Postgres uuid cast. `start` already validates its ids in `parseStartUpload`. No schema change.
- **User-visible change:** None for valid clients; malformed upload ids get a clean not-found answer instead of a server error.
- **Review fixes:** None.
- **Follow-up:** None.
- **Validation:** Local `pnpm typecheck` and `git diff --check`. New integration test in `server/tests/upload-evidence.integration.test.ts` covering the three routes with a malformed id passed in GitHub CI (core), which is authoritative.
