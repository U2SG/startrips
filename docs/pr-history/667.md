# PR #667 - Call the preview upload fetcher as a bare function

- **Source head:** `ecfb726562c634943dcb0e8824784fa6d5b50c1f`
- **Scope:** `uploadAssetPreviewBestEffort` in `src/api/multipartUpload.ts` destructures `fetcher` and calls it as a bare function for the preview PUT. The member call `input.fetcher(url, …)` bound `this` to the options object, and the browser's native `fetch` throws `Illegal invocation` for a non-global `this`, so the PUT never left and the best-effort `catch {}` swallowed it. The shared preview test double in `src/api/multipartUpload.test.ts` now throws the same error for a non-global `this`, so every preview case guards the native call shape.
- **User-visible change:** Newly uploaded photos get their 640 px preview, so Playback and the Story no longer wait on the full original for them. Originals uploaded before this fix are unchanged here (server-side backfill in #668).
- **Review fixes:** None.
- **Follow-up:** #668 backfills the previews of existing originals; #669 names the decode wait in Playback.
- **Validation:** Local: `pnpm install --frozen-lockfile`, `pnpm typecheck`, `git diff --check`, ledger validators. Reproduced on the deployed host before the fix: `POST …/preview` 200, no COS PUT, no `preview/complete`, row left `pending`; same page, bare `fetch` 200 and `{ fetcher: fetch }.fetcher()` throwing `Illegal invocation`. Source CI run 37446282326 passed quick-checks, core, keepsake-render and all eight browser-qa lanes. The `ledger` and `verify` checks failed on the Source only because this file did not exist yet; this ledger-only final follows.
