# PR #598 - Duck the Journey soundtrack under audible foreground video

- **Source head:** `adfa7e48b5276fc67a08cbf68d9ee90c70ac37af`
- **Scope:** Issue #596. `src/journey/soundtrackDucking.ts` holds the policy - when a foreground video counts as audible, the duck factor, and the attack/release ramp, which is time-based rather than tick-based so two surfaces evaluating the same moment agree. `src/journey/soundtrackDuckingController.ts` holds the state machine that drives one soundtrack element's volume by polling live state each frame instead of listening for pause/ended/mute events. Wired into Story (inline and immersive) and Journey Playback / Quick Recap / Full Playback, one controller per surface. `scripts/qa-soundtrack-ducking.mjs` is the browser lane, and `ProductQaPreview` gains a fixture affordance that attaches a soundtrack and can swap its identity to force a real remount.
- **User-visible change:** A Journey soundtrack steps down smoothly while a foreground video is audible and returns to the member's own level when the video stops, is paused, muted or ends. It follows the level the member sets rather than overriding it, including a change made while the duck is already in effect.
- **Review fixes:** Four defects were found and fixed against evidence rather than assumption. The Story wiring copied `storyVideoRef.current` during render, but React attaches those refs in the commit phase, so the copy was null the first time a video appeared and stale across an inline-to-immersive switch - the first video in a Story could simply never duck. Both surfaces passed a hard-coded `getBaselineVolume: () => 1`, which made "the member changed the volume while ducked and got the new level back" unreachable in the product while the policy test for it passed; the controller now owns the baseline, treating any level it did not write as the member's. A replacement soundtrack element, produced by a re-key, sat at the browser default while the controller still believed it was ducked. And when the member changed the level mid-duck, the controller adopted the new baseline but left `current` and `lastWritten` behind, so the ramp restarted from a stale origin every frame and the element never moved - the test for this had the bug written into it as the expected answer and was corrected first.
- **Follow-up:** The immersive hand-off is not asserted. Clicking the current media page did not enter the immersive stage in the lane, so any measurement taken afterwards would describe a surface that was never opened; the lane records that rather than claiming a finding it cannot support. The lane also asserts against the element the controller drives, and records both volumes, because after a soundtrack re-key a blind `querySelector("audio")` can read an orphan. `public/` ships no audio file, so the soundtrack's source never decodes in QA: the lane verifies the volume written to a real element under a real transport and does not claim to measure anything audible.
