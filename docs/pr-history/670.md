# PR #670 - Let a preview backfill pass drain its queue

- **Source head:** `0333c251186a450644e5888f2c59faac5ffcfb54`
- **Scope:** `runPreviewBackfillPass` pages through candidates (eight per page) until none remain or `MEDIA_PREVIEW_BACKFILL_PASS_LIMIT` (default 200) is reached, excluding every asset already attempted in the pass so a `skipped` row cannot be re-selected by the next page. `startPreviewBackfill` schedules the next pass `MEDIA_PREVIEW_BACKFILL_INTERVAL_SECONDS` (default 60) after the previous one finishes, so the interval is a rest between passes rather than a tick aligned to process start. Both values are parsed and bounded in `server/config.ts`; all six `MEDIA_PREVIEW_*` settings (the #260 ceilings and write window, the #668 switch, and these two) are now forwarded through `deploy/compose.yaml`'s API environment and listed in `deploy/env.example` and `.env.example`. The integration test drains eleven rendering originals plus one corrupt and one missing original in one pass, checks the missing one does not loop the pass, and checks that a pass limit of one attempts exactly one asset.
- **User-visible change:** Previews for existing originals are backfilled within about a minute of deployment instead of over an hour, and operators can tune or disable the sweep from `.env.deploy`.
- **Review fixes:** Codex P2 ×2 in 0333c251: the new settings (and the existing preview settings, which were never forwarded either) are added to the compose API environment allowlist and the deploy env example; the sweep rests a full interval after each completed pass instead of reusing a fixed interval tick.
