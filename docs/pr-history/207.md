# PR #207 - Add expiring read-only share grants

- **Source head:** `18d6e4a28f0f64a3651793b72f5de7550dd4bc89`
- **Scope:** Phase A of #200, the authorization foundation. Added `share_grants` and `share_grant_journeys` to `server/db/app-schema.ts` with the drizzle-kit generated `server/db/migrations/0011_lethal_chat.sql` plus its `meta/` snapshot and journal entry. Added `server/authorization/share-access.ts` (`generateShareToken`, `hashShareToken`, `parseBearerToken`, the pure `evaluateShareGrant(grant, now)`, `requireActiveShareGrant`, `ShareAccessError`) and `server/routes/shares.ts` (owner `POST`/`GET /api/shares` and `POST /api/shares/:id/revoke`, guest `GET /api/shared/grant`). Wired both route groups and the `ShareAccessError` branch into `server/app.ts` `onError`. Added `server/authorization/share-access.test.ts`, `server/routes/shares.test.ts` and `server/tests/share-grants.integration.test.ts`.
- **User-visible change:** None yet. No client code changed and no UI exists; the endpoints are the foundation Phases B–E build on.
- **Review fixes:** Revoke is `requireAtlasAccess(request, "update")` rather than `"delete"`, because `"delete"` is owner-only in `permissions.ts` and would let a member create a link they could never withdraw. `requireActiveShareGrant` joins `atlases` and selects `deletion_started_at` instead of filtering it in `WHERE`, so the deleting-atlas rule lives in the pure decision function and is unit-testable. `journeyCount` counts `share_grant_journeys` rows rather than a join against `journeys`, so a soft-deleted Journey cannot silently shrink a grant's recorded scope. Both the create body and the revoke `:id` are UUID-shape checked before any query, so a malformed id returns 400/404 instead of a Postgres `22P02` surfacing as a 500. `revoked_at` is set with `coalesce`, making a repeat revoke idempotent without a read-then-write window.
- **Follow-up:** Phase B (guest Journey DTO and scope-closed navigation), Phase C (share-scoped media read URL with a TTL capped by the remaining grant lifetime), Phases D/E (read-only viewer and owner share UI), Phase F (CFAA matrix and hardening). `/api/shared/*` currently shares the existing per-IP anonymous rate-limit budget; Phase C media reads should re-check that budget against #197 tempo-aware prefetch. Grant membership is deliberately immutable — changing a share set means creating a new link.
