# PR #212 - Remove the legacy playback pacing table

- **Source head:** `76b2be86106d2d4596fb4f4ba4f220a25fb8e6b0`
- **Scope:** Deletes the legacy timing truth now that every mode resolves through `narrativeTiming.ts`. `src/journey/journeyPlayback.ts` loses `PLAYBACK_PACING`, `stepDurationMs()`, `travelDurationMs()`, `stopDurationMs()` and `mediaDurationMs()`; `routePointAngularDistance()` stays, since Quick Recap and the director still measure legs with it. `src/journey/autoEditPlan.ts` loses the `IMAGE_DWELL_MS` / `VIDEO_DWELL_MS` / `CAMERA_MS` / `ARRIVAL_MS` equivalence anchors #208 had kept alive; the planner's greedy budget logic is untouched. `narrativeTiming.ts` gains `UNMEASURED_VIDEO_DURATION_MS = 6000`, which `quickRecapPlayback.ts` now assigns to `QUICK_RECAP_PENDING_VIDEO_DURATION_MS` in place of `PLAYBACK_PACING.videoMs` - a flat number rather than `NARRATIVE_TIMING_PROFILES.full.standard.videoMs`, so a Full Playback tempo retune cannot silently change quick-recap video digest eligibility. Two same-named identifiers that were never consumers were renamed so the cross-feature audit grep stays clean: the local `stepDurationMs` in `playbackPrefetchPlan.ts` is now `stepMs`, and `autoEditPlan.test.ts`'s `FULL_CAMERA_MS` / `FULL_ARRIVAL_MS` fixtures are now `FULL_CAMERA_DURATION` / `FULL_ARRIVAL_DURATION`. Provenance comments in `narrativeTiming.ts`, `journeyKeepsake.ts` and `quickRecapPlayback.ts` are reworded rather than stripped: the identifiers go, the numbers and the reason each profile row holds them stay. PR 6, the last structural step of the shared narrative timing plan (#126, #166, #197).
- **User-visible change:** None. Every deleted symbol had already lost its production callers to #205 and #209-#211; `UNMEASURED_VIDEO_DURATION_MS` carries the same 6000 ms the pacing table did.
- **Review fixes:** None yet.
- **Follow-up:** The planner's flat `travelBase` + `arrivalBase` booking versus playback's distance- and note-aware spend (#210's follow-up) is unchanged and owned by the parallel Quick Recap chapter-booking PR. `narrativeTiming.test.ts`'s quick-recap and keepsake numbers are now literals in the test rather than a second table, so a deliberate retune must be made in two places on purpose; that is the intended trade for keeping coverage of the milliseconds after the anchors were deleted.
