# PR #384 - Switch same-coordinate Route Point context

- **Base:** `3e1ae9398b3b01a10d2bc916e89f17b58633b470`

- **Scope:** Implements ST-081 / issue #377 inside the existing Route Point context surface. Within the current authorized Journey only, distinct Route Point records whose canonical latitude and longitude are exactly equal may share one geographic anchor while keeping independent Route Point IDs, Route order, Stop/passthrough semantics, note/media provenance and selected-record identity. The selected record remains the default context; switching a co-located record updates semantic content through the existing `revealRoutePointContext(...)` path without adding fly/fit, taking camera ownership, changing Playback-current state, inventing Place/Visit entities, using fuzzy coordinate grouping or crossing Journey boundaries. Grouping and previous/next Route context are recomputed from the current Journey DTO after reorder/delete.
- **User-visible change:** A Route Point context with another currently eligible exact-coordinate record in the same active Journey exposes a restrained record switcher. The geographic anchor stays fixed while the selected record's own label, note and representative media become the context. Same labels at different coordinates and near-but-not-exact coordinates remain independent; Journeys without named Stops describe non-Stop records as passthrough Route Points rather than inventing visits.
- **Guest / identity boundary:** Shared read-only Journeys derive grouping only from the scoped shared Journey DTO. The shared `/share` QA path receives the existing production-globe QA wrapper only when `qaRoutePointContext=1`; normal guest behavior, owner capabilities and owner reads are unchanged. The QA wrapper selection is evaluated only inside the `/share` render branch so ordinary Atlas/Earth-Dive startup does not execute the seam.
- **Temporal / semantic-owner boundary:** While Mobile V2 or Globe Focus temporal reveal is active, Route Point context uses the existing Journey and point reveal maps as eligibility authority. Future co-located records are omitted from the switcher, unrevealed previous/next summaries are omitted, and an already-open context is released when its Journey or selected point becomes temporally hidden. Same-coordinate switching is also subordinate to the current semantic `activeJourneyId`; switching is rejected for a non-active Journey, retained context is cleared when Journey ownership changes, and the render path synchronously suppresses stale context during the owner-change commit. Ordinary desktop Atlas behavior remains unchanged when temporal reveal is inactive.
