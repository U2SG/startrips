# PR #254 - Stop a nested focus trap from resurrecting an externally owned inert state

- **Source head:** `9681adb5fc59cba4b64f02c7ca9e75590f800c6c`
- **Scope:** Fixes #250. `useModalFocus` recorded every background element's previous `inert` value and wrote it back on cleanup. On mobile, an expanded Story's trap activates while React already owns `inert` on `.mobile-v2__sheet-layer` (`inert={storyJourneyId !== null}` in `src/journey/LivingAtlasApp.tsx`), so the trap captured `previous = true` and reasserted it from a passive effect cleanup ordered after the very commit that dropped the attribute. `src/journey/useModalFocus.ts` now routes the `.living-atlas` children loop and the `.account-dock` branch through one `claimInertOwnership` helper: an element already inert at activation is not claimed and is never written, and cleanup writes `inert = false` only for what this trap claimed. The helper is exported so the ownership rule is unit-testable with element-like stubs in the default node environment. `scripts/qa-post-login-controls.mjs` gains a normal-motion mobile lane, `mobile-expanded-story-inert-ownership`, that opens the Journey detail sheet, opens and expands the Story through `.journey-story__sheet-handle`, then closes it three ways.
- **User-visible change:** On mobile, closing an expanded Story returns to a Journey detail sheet that actually responds. Before this change the sheet came back visible but permanently non-interactive - the owner's Android recordings show the OS touch indicator landing on the real-map button with no response - and the only escape was dismissing the surface or reloading. The parent sheet is still suppressed while an expanded Story is genuinely open, and no `pointer-events` override was used to paper over an inert tree.
- **Review fixes:** One Codex P2, verified against the code and valid: after Escape closes the real-map surface, `useMobileSurfaceHistory` schedules its `history.go(-1)` in a passive effect, so DOM detachment is not proof the pop has landed, and reopening the Story immediately could let that pending navigation swallow the new Story token. The QA round now waits for `__startripsMobileSurfaceStack` to return to sheet-only depth and asserts that depth, matching what `verifyMobileV2InteractionContract` already does at every other surface boundary.
- **Follow-up:** #255, filed from the regression-family search. It is the mirror direction of the same invariant - a trap releasing a flag it claimed at `false` without checking whether an external owner acquired it mid-trap - which the Composer globe-pick suspension path exhibits on `main` and which this PR leaves exactly as it found it. Closing it needs a decision about who owns the Atlas chrome during a pick, so it was not folded in here. Every other sibling in the family was checked and cleared; see the PR body.
- **Validation:** `./init.sh smoke` locally - `pnpm typecheck` for both projects, `git diff --check`, `node --check` on the changed script, `node scripts/pr-history.mjs validate-all` and `validate-pr`. Behaviour is CI-authoritative and was built guard-first: run 34072518581, at the QA-only head `297db0a`, has `browser-qa / post-login` RED with `afterClose: {inert: true, ariaHidden: null}` and the real-map button timing out unclickable, which is the reported failure measured in a browser; run 34073209732, with the fix at `9681adb`, has that lane green with all three close variants reporting `inert: false` and the real-map button opening on the first click, and `core` green over the five new `claimInertOwnership` cases.
