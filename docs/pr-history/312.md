# PR #312 - Simplify route light grammar

- **Issue relationship:** `Refs #126`, `Refs #246`, `Refs #247` — this is the A1 / Quiet Core visual-hierarchy slice; it does not close the broader Playback, attention-handoff, or render-budget issues.
- **Source head:** `1e2bcd070822cf9d1b1d156cf540043b8e287067`
- **Scope:** Replace the particle Atlas route's perpetual dual strands, independent flow loop, per-point twinkle, and breathing stop rings with one normalized route vocabulary: an end-to-end identity core, restrained palette halo, a single directional leader, and one-shot destination arrival. Existing canonical spherical route samples/projection, route fitting, focus solver, Earth Dive, coastline data, Journey/Playback state, and renderer architecture are unchanged. Temporal/Rewind presentation still consumes the existing journey/point progress maps; per-leg reveal paints that same progress as normalized dash growth rather than opacity-only segment appearance. Route-style QA metadata and probes describe the same Quiet Core vocabulary.
- **User-visible change:** Selected Journeys read more quietly and directionally: camera focus owns attention first, then the route draws once while one light packet describes travel direction; only after that shared travel duration completes does the destination acknowledge arrival once, then the scene settles. In ordinary/resting Atlas state the route remains crisp and readable without perpetual strands/pulses. Reduced-motion users get the same final route/point state immediately with no travelling packet or arrival animation.
- **Review fixes:** Browser QA of the first Quiet Core pass showed that reusing the old destination-fading gradient on the only crisp core made the route too weak exactly at its endpoint, so the Source keeps the soft halo on the effect palette but paints the core in the Journey identity color end-to-end. Deleting infinite rings removed all arrival acknowledgement, so a bounded one-shot destination response was added. Automated review then caught a stale `qa-route-styles.mjs` strand probe; both local/live route-style probes now inspect the normalized leader/solid identity core safely and `data-route-style` reports `quiet-core`. A later CFAA P2 found that the one-shot destination response still started at the same instant as the 980ms route/leader travel and could finish before the leader arrived. The final Source introduces one route timing authority (`--journey-route-travel-duration`), uses it for both draw and leader, and uses that exact duration as the arrival delay; a focused test locks this ordering.
- **Follow-up:** Place → Story/Media spatial handoff and Earth Dive renderer-seam refinement remain separate follow-up slices under the existing design issues. No media carousel/fullscreen rewrite, Home Base motion, visited imprint, WebGPU/TSL migration, local-coastline retune, or second timing/rendering system is included here.
- **Validation:** Exact Source `1e2bcd070822cf9d1b1d156cf540043b8e287067` passed local lightweight validation: `vitest run src/journey/LivingAtlasApp.test.ts src/scene/ParticleEarthScene.test.tsx --maxWorkers=1` passed 126/126 tests; `git diff --check` passed. This proves the visible ordering `focus → route/leader travel → destination response`. Reduced-motion behavior remains covered by the focused CSS test.
