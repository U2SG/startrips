# PR #645 - Write media swipe transforms directly instead of stage variables

- **Source head:** `024e1b5fd390c8ff5efbe7d3a236a86d360442cb`
- **Scope:** `StoryMediaPages` no longer sets `--story-drag-x` (no CSS consumer) or `--story-live-transform` on the stage root during a swipe, so a pointermove no longer restyles every page beneath the stage. The video shell, which was the variable's only consumer, receives the same transform inline at pointerdown, at axis lock and on each pointermove. `clearDragPresentation` clears it for every gesture. The CSS fallback becomes a literal `translate3d(0, 0, 0)`. The CI QA probes and the dev-only `MediaMotionLab` readout now measure the presented page's computed translation or the `data-media-presentation` phase.
- **User-visible change:** None.
- **Review fixes:** None.
- **Follow-up:** `.is-drag-settling` is only removed and never added, so its transition rule is dead. `--story-live-opacity` and `--story-live-z` are root variables that are written once per gesture, not per move.
- **Validation:** Locally: `pnpm install --frozen-lockfile`, `pnpm typecheck`, `git diff --check`, `node --check` on the edited QA scripts, and the pr-history validators. GitHub CI (vitest, build, story-media and media-motion-lab browser lanes) is authoritative.
