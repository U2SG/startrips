# PR #259 - Drive the Earth dive from the zoom authority instead of a mode switch

- **Source head:** `d53cdfdca0edca0d4a10729d0cb3625ac0d5c830`
- **Scope:** Addresses #252, phase A only: the state, progress and ownership contract for the Semantic Earth Dive. `src/scene/semanticZoom.ts` stays the single zoom authority and its published state now carries a `SemanticZoomSnapshot` - the band, the canonical clamped `zoom`, and a `localProgress` derived once from the boundary that opens `local` and the ceiling of the range - so no consumer re-derives a band or restates a threshold. `src/scene/earthDive.ts` is a new pure resolver over that snapshot plus a four-level `DetailReadiness` ladder (`unavailable` / `mounted` / `visual-ready` / `fully-settled`); it advances at most one stage per frame through `particle -> prewarm -> blending -> detail`, blends at `visual-ready` rather than waiting for tiles, releases asymmetrically (leaving needs the band to fall to `macro`), and returns an explicit `owner` that transfers exactly once on the commit edge. It contains no zoom value and no clock, both asserted by a source guard in `earthDive.test.ts`. `src/scene/LivingAtlasGlobe.tsx` resolves that state in one animation-frame loop and derives the stage and the input owner from it alone: the `earthMode` / `transitionTarget` / `targetReady` triple, the 12 s load timeout, the crossfade finish timer and the transition-status element are gone, the section publishes `data-earth-dive` and `data-earth-dive-owner`, and the persistent particle scene stops answering the wheel and the drag while the map owns the camera. `src/scene/detailedEarthModel.ts` gains `getEarthDiveHandoffFrame`, which maps the focus anchor and the same snapshot to a MapLibre centre and a solver seed and returns the identical frame at every mounted stage, plus the pure `solveDetailedEarthHandoffZoom` and `detailedEarthAnchorCorrection`. The handoff is CALIBRATED rather than mapped: the particle Earth publishes what it is actually showing at the focused place - the anchor in viewport CSS pixels and the local scale in viewport CSS pixels per degree of latitude, read from the same shared projection frame its place labels use - and `DetailedEarthMap` solves its own camera to that through MapLibre's public projection alone, taking one measured `(zoom, px/deg)` pair to the zoom whose local scale matches and unprojecting the pixel offset between the projected anchor and the particle's screen point, applied with non-animated `jumpTo` in a two-pass loop that is bounded because the solver is a fixed point once the two agree. Calibration runs before `visual-ready` is reported, so the surface the Dive may reveal is already standing where the particle Earth stands. `DetailedEarthMap` also mounts from that frame instead of a fixed zoom, no longer flies to the same focus a second time, reports its readiness ladder, keeps every gesture handler disabled until ownership transfers, and publishes its own anchor, local latitude scale and zoom in the same units as the particle side. `scripts/qa-earth-dive.mjs` and the `browser-qa / earth-dive` lane grade all of it in a browser at 1440x1024 against a new `?qaState=earth-dive` fixture, which mounts a Journey and focuses one of its Route Points so the anchor being measured is the thing #252 names, and which can also focus the whole Journey - the shape that publishes no focus point and takes its anchor from the route frame - for a second round over that branch.
- **User-visible change:** Zooming the particle Earth in now reveals the detailed map by itself, and zooming out returns, with no button press in either direction and no loading text: the detail surface is prepared invisibly from the regional band, is only revealed once it can actually draw, and keeps the place the user was looking at in the same position and at the same scale when it takes over. If the map cannot load, nothing changes on screen and the particle Earth stays fully usable. The existing `深入真实地图` / `返回粒子地球` control stays as an accessibility command for the same dive, and pressing it while a dive is still preparing now cancels it.
- **Review fixes:** One owner P1, one owner P2 and two Codex P2 findings, each verified against the code before acting. The owner P1 is the substantive one: the first implementation mapped `localProgress` linearly onto a fixed MapLibre band, which is a guess rather than a calibration, and the browser lane could not see it because both samples came from the map, so the ~0 error it printed was a tautology. Measured before rebuilding: the particle Earth draws about 111 to 162 CSS px per degree of latitude across its `local` band at 1440x1024, i.e. MapLibre zoom 6.18 to 6.72, so the old `6.4 -> 9.6` band was up to about 2.6x off at the deep end - a visible scale jump. The screen-space calibration described in Scope replaced it, the linear band is gone, and the lane now compares the two different renderers at both sides of the ownership edge. While rebuilding it I first lowered `DETAILED_EARTH_MIN_ZOOM` and `DETAILED_EARTH_RETURN_ZOOM`, expecting from a hand estimate that the calibration would land near zoom 5; the measurement put it above both, so they were restored to `5.6` and `5.85` with the measured range recorded beside them, and no product constant changed in the end. The owner P2 was a lane defect rather than a product one: the blocked round's drag reused the point resolved at the start of the round while the wheel loop re-resolved it, so a place label had drifted under the cursor, the city layer took the pointerdown for a pick, and a red lane looked like a drag regression; the drag now re-resolves through the same "surface that steers" predicate and grades rotation on both axes with the same `> 0.01` tolerance the equivalent assertion in `qa-login-v3.mjs` uses. Then the two Codex P2 findings. One further defect found while re-reading the result rather than reported: a focused Journey is owned by route fitting and publishes no focus point, so resolving the dive anchor from the focus point alone left the entire route branch with no anchor to hand over and nothing for the detail surface to calibrate against - the P1 defect surviving in the branch the issue cares about most, with the first fixture (`journeyRoutes={[]}`, no route) structurally unable to see it. The anchor is now resolved the way the globe's own wheel handler resolves it, `data-focus-point-lat/lon` keeps its own narrower contract, and the lane grades both focus shapes. (1) Ownership transferred on the frame after the blend began, so one wheel notch crossing both progress cuts handed the gestures to a surface still fading in; the commit edge now has a final `blendPresented` gate, measured by the section from the detail layer's own computed opacity and passed in, which keeps the fix clear of the acceptance rule that no clock may enter the resolver. The same reviewer asked for the reverse direction to be delayed symmetrically and that half was refuted: #252 section 4 forbids "finish the old transition, then obey the user", the layer is `pointer-events: none` while it fades out, and the release writes the particle camera back, so a reversal is obeyed on the frame it happens. (2) A command-driven dive whose style never reached `visual-ready` had no exit, because `commandRequested` also short-circuits the band's own planet/macro exit and pressing the control again only re-set the flag; the control is now one command that cancels at any stage other than `particle`, and the release latch is cleared before the controller's no-change exit so a cancel resolving to the stage the band already wanted cannot latch and block later dives.
- **Follow-up:** A focus change made while the detail surface already owns the view still flies through `applyDetailedEarthFocus`, whose `Math.max(map.getZoom(), DETAILED_EARTH_INITIAL_ZOOM)` sends a calibrated camera from about zoom 6.2-6.7 to 8 - the same "the place must not move" invariant on a path this lane does not exercise. It is left exactly as found, because a deliberate focus flight is a different contract from the handoff, and it belongs with the calibration-polish phase below. Then the later #252 phases, deliberately not bundled here: MapLibre camera calibration polish and the real-device performance phase; the finite-DPR / drawing-buffer / covered-render suspension contract, which stays with #247 / ST-038 and is not duplicated here; removal of the permanent desktop mode chrome, whose fullscreen slice belongs to #253 and which must not come back as a smaller replacement pill; removal of the mobile `真实地图` action and the `mobile-v2__real-map` dialog and its Journey-sheet trigger in `src/journey/LivingAtlasApp.tsx`; and the Geographic Materialization particle progression. `DETAILED_EARTH_INITIAL_ZOOM` remains only as the floor for a genuine later focus flight.
