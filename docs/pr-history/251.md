# PR #251 - Sample and bound Journey route lift so short legs stop rendering as raised sawteeth

- **Source head:** `cd1fb23acc70cce15a3b666b89c1f9d79f1bd734`
- **Scope:** Fixes #242. `buildRouteArcSamples` chose its sample count from angular distance alone, so a leg just over the 1.875 degree segment angle was drawn as two straight segments through one elevated midpoint - a triangular peak - and the `sqrt(angle)` height policy let that peak grow without bound relative to the leg it decorated, about 1.181 chord lengths at 1.90 degrees. `src/scene/geo.ts` now solves the segment count from the lifted curve (an angular term plus the curvature the radial lift introduces, inverted from the `a / (8 n^2)` chord-error bound against `ROUTE_ARC_CHORD_TOLERANCE`), with an even count so the mid-leg peak is always sampled and a four-segment floor for any lifted leg, and it bounds a leg's hump against its own chord through a smooth short-leg ramp. `planRouteArcLegs` makes one plan for the whole route that both `buildRouteArcSamples` and `buildRouteArcLegSamples` read, replacing the separate 2048-vertex leg budget in `src/scene/ParticleEarthScene.tsx` that let the static stroke and the rewind legs disagree. Budget pressure degrades in a fixed order - decorative lift first via `maxRepresentableArcLift`, then subdivision down to one segment per stored leg, and only then the route is not drawn - so a drawn route always passes through every Route Point it stores. `resolveRouteVertexShare` shares the line-vertex pool across visible routes and reserves each route's topology floor plus the floors owed to later routes. The changed dimension is recorded in `docs/cross-feature-assumption-audit.md` as invariant 14, Faithful Path.
- **User-visible change:** Local multi-stop Journeys read as restrained traces that hug geography instead of a chain of steep takeoffs and landings, and a route rotating toward the limb no longer breaks into a row of raised sawteeth. Long-distance legs keep their cinematic arc. Route Point coordinates, chronology and genuine recorded corners are unchanged, and a dense multi-Journey overview no longer lets one route consume the shared line-vertex pool.
- **Review fixes:** Four findings, all reproduced against the code before acting. Codex P1: the shared vertex pool was spent front to back, so with the larger counts one long route could starve the routes after it - fixed by `resolveRouteVertexShare`. Codex P2: one segment per leg could exceed the declared `maxVertices` when a route had more legs than the budget had segments. Codex P2: a leg scaled far below the segments its hump needed kept the full hump as long as it cleared the four-segment floor, drawing the coarse raised polygon this change removes - fixed by `maxRepresentableArcLift`. U2SG P1 blocker: the first fix for the overrun sampled Route Points evenly, which made the stroke shortcut across omitted points and broke the one-to-one leg mapping Playback temporal reveal depends on; the decimation was removed in favour of reserving each route's topology floor, and the test that had blessed the omission was replaced by a pressure fixture asserting complete topology at the floor and no route at all below it.
- **Follow-up:** None. The regression-family search found the five whole-route stroke consumers and the per-leg rewind paths to be the complete set of sampled-path consumers, and all of them read the one evaluator this PR introduces, so no sibling issue was filed. The issue's horizon-clip contribution, marker decluttering, mobile reduced-motion tuning and Home Prelude remain out of scope and unmeasured, as #242 itself marks them as needing live isolation.
