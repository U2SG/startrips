# PR #685 - Split the 3D Journey Book QA lane into four capped suites without redundant turns

- **Source head:** `8c446e3532a0560c599eee64586ea64682cd5a5f`
- **Scope:** `scripts/qa-journey-book-3d.mjs` drops desktop turns that only returned the book to a spread already reached. The cover's automatic turn (check 6) is now the click that opens the first spread. The front-cover drag's release lands on the spread where check 5 starts. The last drag's release is no longer waited out. The 1.2 s picture wait is skipped where no screenshot follows. The lane runs as four parts (`turns`, `drags`, `last-spread`, `phone`), each with its own `pnpm qa:journey-book-3d-<part>` script and its own CI suite and 720 s cap. `turns` runs in story-media, `drags` in route-home-share, and `last-spread` and `phone` in labels-recovery. Each part writes `checks-<part>.json`. The evidence artifact is named per shard (`journey-book-3d-<shard>-<attempt>`). The shard count stays at 8. The suite-contract node tests (`ci-latency`, `ci-ledger-fast-path`) expect 38 suites. Every assertion and threshold is unchanged. The phone part adds a Home-closes-the-book check.
- **User-visible change:** None.
- **Review fixes:** None. Codex found no issues on `24ffe8d0c0` or on the Source `8c446e3532`.
- **Follow-up:** Each turn still costs 40–60 s of SwiftShader frames at 1440x1000, so any new desktop turn added to a part should be weighed against that part's cap.

Every Book part is at or under 29% of its cap. Both runs passed quick-checks, core, keepsake-render and all eight browser-qa lanes; ledger and verify failed only because this ledger was absent.
