- **Scope:** CI/QA reliability only, for issue #383 (feature ST-085). `scripts/qa-home-base-suggestion.mjs` no longer leaves Journey Playback with `page.keyboard.press("Escape")`. The overlay registers its Escape listener only while Playback is playing, paused or completed (`src/journey/JourneyPlaybackOverlay.tsx:1001`), so on a slower runner the key landed during a stop/travel/outro transition and was a no-op — the false red on run `35053486553` against tree `db54cec`. The lane now clicks the product's own `.journey-playback button[aria-label="退出播放"]` control, whose `onClick={requestClose}` runs the same `requestClose -> onClose -> playbackSession.journeyId = null` path, matching `scripts/qa-home-base-context.mjs:352`. Because the overlay idle-hides its chrome with `pointer-events: none`, the script moves the pointer onto the control (the gesture a member makes), waits for `.journey-playback:not(.is-controls-hidden)` and for the control's settled opacity, records a new actionability check, then clicks with plain Playwright actionability at the pre-existing `20_000` ms. Exit is awaited on `.journey-playback` reaching `detached` plus the existing returned-Story branch. One file changed; nothing under `src/` or `server/`.
