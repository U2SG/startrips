# PR #370 - Add the cover-reveal derivative worker protocol

- **Source head:** `2529f556f270de1b5682f55b712f2d961f8e94f2`
- **Scope:** Implements ST-074 / issue #368, Slice 1 of #367, on exact main `1fa6106316b66cc2d56421d5e968749eea555ed7`. Adds `cover_reveal_derivatives` (a job distinct from `media_assets`, pinning the resolved cover plus its #311 verified stored-byte identity, with a `queued|leased|ready|failed|superseded` lifecycle, a lease token hash and expiry, bounded retry metadata, and DB check constraints for the state set, the lease shape and the ready shape) and the FK-free `cover_reveal_writes`, in one drizzle-kit migration `server/db/migrations/0023_gifted_fixer.sql` with its `meta/` snapshot. Adds a pure DOM-free eligibility module, a revocable machine credential read from `server/config.ts`, an atomic claim over `FOR UPDATE SKIP LOCKED` with expired-lease reclaim, short-lived source-read and bounded output-upload capabilities each clamped to the remaining lease, idempotent complete/fail validated against the re-resolved cover and the stored output bytes, and a three-pass reconciler over a `cover-reveals/` namespace kept disjoint from the #260 `previews/` namespace. Ships no RevealFlow renderer, no Journey opening UX, no local AI worker client and no `ink-wash-poster` execution on the server; the diff touches nothing under `src/`.
- **User-visible change:** None. The worker is off unless a deployment sets `COVER_REVEAL_WORKER_TOKEN`, no product surface consumes a derivative yet, and a successful completion leaves the canonical cover pointer, the source `media_assets` row and every `sortOrder` unchanged.
- **Review fixes:** Codex review `5206092916` on `a414c58bda` raised four findings, all verified valid and fixed in `60a0038`, each answered on its thread (`4012567318`, `4012567883`, `4012568628`, `4012569132`). P1 `4012438633`: settling an attempt now clears the output storage columns, so a terminal `failed` row no longer pins the object both sweeps would otherwise skip. P1 `4012438636`: the canonical cover is re-resolved inside the transaction that writes `ready`, under `FOR UPDATE` on the Journey row and its media rows in the repository lock order, so a cover change between validation and publication cannot publish a stale derivative. P2 `4012438640`: enqueue idempotency is enforced by the partial unique index `cover_reveal_derivatives_live_identity_unique` over the pinned identity and generation contract in the live states, with `onConflictDoNothing` and a read of the winner. P2 `4012438644`: each issued capability is clamped to `leaseExpiresAt - now` and an expired claimant is refused outright. The migration was regenerated as a single `0023_gifted_fixer.sql` rather than stacked on the superseded `0023_living_luminals.sql`. Follow-up commit `2529f55` corrects the byte-ceiling regression to capture the output key before the settle clears it, and accepts 429 beside 404 on the guest-prefix probe so the credential assertion does not couple to the share unknown-token budget.
- **Follow-up:** #367 Slice 2 owns the local reference worker client, and ST-073 owns the RevealFlow renderer and the Journey opening UX; neither is started here. No presentation path reads `cover_reveal_derivatives` yet, so a `ready` derivative is currently durable state with no consumer, deliberately. One residual no row lock can exclude is a concurrent INSERT of a brand-new media asset that wins the `sort_order` fallback; it cannot displace an explicit pointer and the invalidation pass supersedes the job on its next run, so the outcome is a retired derivative rather than one attached to the wrong cover.
